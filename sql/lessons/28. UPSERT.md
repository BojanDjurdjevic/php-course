# 28. UPSERT

## Lekcija 28 — UPSERT: INSERT ... ON DUPLICATE KEY UPDATE

Ovo će ti biti baš poznato iz Laravel-a, jer si koristio obrasce poput:

```php
updateOrCreate()
```

ili:

```php
upsert()
```

SQL ideja ispod toga je:

Probaj INSERT. Ako već postoji red koji krši PRIMARY KEY ili UNIQUE constraint, umesto greške uradi UPDATE.

U MySQL-u to može izgledati ovako:

```sql
INSERT INTO room_inventory (
    room_id,
    date,
    available,
    price
)
VALUES (
    15,
    '2026-11-01',
    5,
    120.00
) AS new
ON DUPLICATE KEY UPDATE
    available = new.available,
    price = new.price;
```

Ovaj moderniji alias oblik je preporučljiv; stariji `VALUES(column)` način je deprecated u savremenom MySQL-u. dev.mysql.com

---

## Ali odakle SQL zna šta je „duplicate“?

Iz constraint-a.
Sećaš se:

```php
UNIQUE(room_id, date)
```

Ako već postoji:

```text
room_id = 15
date    = 2026-11-01
```

novi INSERT bi normalno napravio duplicate-key problem.
Ali uz:

ON DUPLICATE KEY UPDATE

MySQL kaže:

```text
red ne postoji
→ INSERT
```

```text
red već postoji po PK/UNIQUE
→ UPDATE postojećeg
```

To je UPSERT:

```text
UPdate
+
inSERT
```

---

## Bez UPSERT-a

Naivni application flow bi bio:

```text
SELECT da li postoji
↓
ako ne postoji → INSERT
ako postoji → UPDATE
```

Na primer:

```sql
SELECT id
FROM room_inventory
WHERE room_id = 15
  AND date = '2026-11-01';
```

pa PHP:

```text
if exists
→ UPDATE
else
→ INSERT
```

Ali odmah vidiš concurrency problem:

```text
Request A SELECT → nema reda
Request B SELECT → nema reda
```

B INSERT

A UPSERT dodatno omogućava da celu nameru izrazimo jednom SQL operacijom.

## Realan inventory primer

Pretpostavimo da supplier u calendar grid-u unosi:

```text
room 15
2026-11-01
available = 4
price = 135
```

Možemo:

```sql
INSERT INTO room_inventory (
    room_id,
    date,
    available,
    price
)
VALUES (
    15,
    '2026-11-01',
    4,
    135.00
) AS new
ON DUPLICATE KEY UPDATE
    available = new.available,
    price = new.price;
```

Ako nema inventory reda:

```text
→ INSERT
```

Ako već postoji isti:

(room_id, date)

onda:

```text
→ UPDATE available i price
```

Ovo je bukvalno odličan match za tvoj inventory calendar.

---

## Možeš update-ovati samo neke kolone

Recimo želiš da postojeći available ostane, ali da promeniš cenu:

```sql
INSERT INTO room_inventory (
    room_id,
    date,
    available,
    price
)
VALUES (
    15,
    '2026-11-01',
    4,
    135.00
) AS new
ON DUPLICATE KEY UPDATE
    price = new.price;
```

Ako red postoji:

```text
price → menja se
available → ostaje star
```

Dakle UPDATE deo ti kontroliše šta se dešava pri konfliktu.

---

## UPSERT zavisi od dobrog schema dizajna

Ovo je vrlo važno.
Ako nemaš:

```php
UNIQUE(room_id, date)
```

onda MySQL nema business rule koji kaže:

ova dva reda predstavljaju isti inventory slot.

Može završiti sa:

```text
15 | 2026-11-01 | 4 | 135
15 | 2026-11-01 | 5 | 140
15 | 2026-11-01 | 2 | 125
```

i onda ni ON DUPLICATE KEY UPDATE nema odgovarajući duplicate key na osnovu kog bi reagovao.
Zato:

```text
dobar UPSERT
↓
počiva na dobrom PRIMARY/UNIQUE constraint-u
```

---

## INSERT IGNORE nije isto

Možeš naići i na:

INSERT IGNORE INTO ...

Ako naiđe na određene greške poput duplicate key-a, MySQL može ignorisati problem umesto da obori statement. Ali to nije isto što i:

ON DUPLICATE KEY UPDATE

jer:

```text
INSERT IGNORE
→ preskoči konfliktni insert
```

```text
ON DUPLICATE KEY UPDATE
→ konflikt? update-uj postojeći red
```

I sa IGNORE treba biti oprezan, jer može utišati više vrsta problema nego što si možda želeo. dev.mysql.com

## Laravel paralela

Ovo:

```php
RoomInventory::updateOrCreate(
    [
        'room_id' => 15,
        'date' => '2026-11-01',
    ],
    [
        'available' => 4,
        'price' => 135,
    ]
);
```

izražava sličan application intent:

```text
nađi logical inventory row
↓
postoji?
→ update
```

ne postoji?

```text
→ create
```

Ali veoma je važno da baza i dalje ima:

```php
UNIQUE(room_id, date)
```

jer application helper sam po sebi nije zamena za database integrity constraint.

## Pitanje 28

Imamo:

```text
room_inventory
--------------
id
room_id
date
available
price
```

```php
UNIQUE(room_id, date)
```

Supplier šalje:

```text
room_id = 7
date = 2026-12-20
available = 3
price = 149.99
```

Želimo:

ako red ne postoji — kreiraj ga; ako već postoji isti (room_id, date) — ažuriraj available i price.

Napiši INSERT ... ON DUPLICATE KEY UPDATE query za to.

---

```sql
INSERT INTO room_inventory (
  room_id, date, available, price
) VALUES (
  7, '2026-12-20', 3, 149.99
) as new
ON DUPLICATE KEY UPDATE
```

available = new.available,
price = new.price;

---

Tačno — 10/10. I sintaksa sa aliasom AS new posle VALUES je validna u aktuelnom MySQL-u; ON DUPLICATE KEY UPDATE reaguje kada bi INSERT prekršio PRIMARY KEY ili UNIQUE indeks. MySQL dokumentacija takođe preporučuje row alias pristup umesto starijeg `VALUES(column)` oblika, koji je deprecated. MySQL
Tvoj query:

```sql
INSERT INTO room_inventory (
    room_id,
    date,
    available,
    price
)
VALUES (
    7,
    '2026-12-20',
    3,
    149.99
) AS new
ON DUPLICATE KEY UPDATE
    available = new.available,
    price = new.price;
```

Mentalno:

```text
(room_id, date) ne postoji
→ INSERT
```

```text
(room_id, date) već postoji
→ UNIQUE konflikt
→ UPDATE available + price
```
