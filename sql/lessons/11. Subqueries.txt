Lekcija 11 — Subqueries

Subquery je jednostavno:

SQL query unutar drugog SQL query-ja.

Najjednostavniji primer:
Daj hotele skuplje od prosečne cene svih hotela.

Prvo bi mogao ručno:
SELECT AVG(base_price)
FROM hotels;

recimo rezultat:
135.50

pa:
SELECT id, name, base_price
FROM hotels
WHERE base_price > 135.50;

Ali ne želimo dva ručna koraka.
Možemo:
SELECT
    id,
    name,
    base_price
FROM hotels
WHERE base_price > (
    SELECT AVG(base_price)
    FROM hotels
);

Unutrašnji query:
SELECT AVG(base_price)
FROM hotels

je subquery.
Mentalno:
inner query
→ izračunaj prosek

outer query
→ pronađi hotele skuplje od tog proseka

Scalar subquery
Prethodni primer vraća jednu vrednost:
135.50

To zovemo scalar subquery.
Zato možemo:
WHERE base_price > (subquery)

jer desno od > očekujemo jednu vrednost.
Subquery sa IN
Recimo:
Daj sve hotele čiji owner pripada određenom skupu user-a.

Na primer users čiji email završava na company.com:
SELECT
    id,
    name
FROM hotels
WHERE owner_id IN (
    SELECT id
    FROM users
    WHERE email LIKE '%@company.com'
);

Inner query može vratiti:
3
7
15
22

pa outer query konceptualno dobija:
WHERE owner_id IN (3, 7, 15, 22)

Subquery nije automatski bolji od JOIN-a
Ovo je važno.
Isti problem često možeš rešiti sa:
JOIN

ili sa:
IN (subquery)

Na primer:
SELECT h.id, h.name
FROM hotels h
INNER JOIN users u
    ON h.owner_id = u.id
WHERE u.email LIKE '%@company.com';

nasuprot:
SELECT id, name
FROM hotels
WHERE owner_id IN (
    SELECT id
    FROM users
    WHERE email LIKE '%@company.com'
);

Oba mogu izraziti istu poslovnu nameru.
Ne postoji pravilo:
subquery = loše
JOIN = dobro

ili obrnuto.
Gledamo:
čitljivost
semantiku problema
query plan
indekse

MySQL optimizer ponekad čak može transformisati način izvršavanja.
Subquery u FROM
Možeš čak koristiti query kao privremeni rezultat:
SELECT
    city,
    average_price
FROM (
    SELECT
        city,
        AVG(base_price) AS average_price
    FROM hotels
    GROUP BY city
) AS city_stats
WHERE average_price > 150;

Inner query prvo pravi:
city | average_price

a outer query onda filtrira taj rezultat.
Takav derived table mora imati alias:
AS city_stats

Ali za sada nam je važnije da prvo savladaš subqueries u WHERE.
Correlated subquery
Postoji još zanimljivija vrsta.
Na primer:
SELECT
    h.id,
    h.name
FROM hotels h
WHERE h.base_price > (
    SELECT AVG(h2.base_price)
    FROM hotels h2
    WHERE h2.city = h.city
);

Ovo znači:
pronađi hotel koji je skuplji od prosečne cene hotela u svom gradu.

Ovde inner query zavisi od trenutnog reda outer query-ja:
h2.city = h.city

To je correlated subquery.
Mentalno:
za trenutni hotel
↓
uzmi njegov city
↓
izračunaj prosek tog grada
↓
uporedi cenu hotela sa tim prosekom

Ovo ćemo još videti uz EXISTS, gde correlated subqueries postaju posebno prirodne.
Kada je subquery zgodan?
Ako problem prirodno zvuči:
„Daj mi X gde je nešto veće od rezultata drugog upita.“

ili:
„Daj X čiji ID pripada skupu koji dobijem drugim query-jem.“

onda subquery često lepo odgovara mentalnom modelu.
Laravel paralela
SQL:
SELECT *
FROM hotels
WHERE base_price > (
    SELECT AVG(base_price)
    FROM hotels
);

Laravel Query Builder može konceptualno:
Hotel::where(
    'base_price',
    '>',
    Hotel::query()->selectRaw('AVG(base_price)')
)->get();

ali upravo zato želim da prvo razumeš SQL, a tek onda wrapper.
Za „2 ujutru“
subquery
→ query unutar query-ja

scalar subquery
→ vraća jednu vrednost

IN (subquery)
→ vraća skup vrednosti

correlated subquery
→ inner query zavisi od trenutnog outer reda

Pitanje 11
Napiši query koji vraća:
id
name
base_price

svih aktivnih hotela čija je base_price veća od prosečne base_price svih aktivnih hotela.
Dakle želim da i outer query i računanje proseka uzimaju u obzir samo:
is_active = TRUE

---

SELECT id, name, base_price
FROM hotels
WHERE base_price > (SELECT AVG(base_price) FROM hotels WHERE is_active = TRUE)
AND is_active = TRUE;

---

Tačno — 10/10.
SELECT id, name, base_price
FROM hotels
WHERE base_price > (
    SELECT AVG(base_price)
    FROM hotels
    WHERE is_active = TRUE
)
AND is_active = TRUE;

Baš dobro što si stavio is_active = TRUE na oba mesta, jer tražimo:
prosek samo aktivnih hotela
+
rezultate samo među aktivnim hotelima

Da si filter stavio samo u subquery, outer query bi mogao vratiti 
i neaktivan hotel ako mu je cena iznad proseka aktivnih.
