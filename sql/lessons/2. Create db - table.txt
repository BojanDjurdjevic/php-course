Lekcija 2 — CREATE DATABASE, CREATE TABLE i tipovi podataka
Sada prelazimo sa mentalnog modela na prvu stvarnu SQL strukturu.
Kreiranje baze:
CREATE DATABASE booking_app;

Izbor baze:
USE booking_app;

A zatim tabela:
CREATE TABLE users (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100) NOT NULL,
    email VARCHAR(255) NOT NULL,
    password_hash VARCHAR(255) NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

Ovo već ima dosta stvari unutra, pa idemo deo po deo.
id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY
To možemo rastaviti:
id
→ ime kolone

BIGINT
→ integer tip

UNSIGNED
→ ne može negativna vrednost

AUTO_INCREMENT
→ MySQL automatski povećava ID

PRIMARY KEY
→ jedinstveni identifikator reda

Dakle:
1
2
3
4
...

MySQL sam generiše.
Za ID-jeve je vrlo čest obrazac:
BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY

Laravel migration ti praktično ovo skriva iza:
$table->id();

VARCHAR
name VARCHAR(100)

znači:
string promenljive dužine, maksimalno 100 karaktera.

Za email:
email VARCHAR(255)

Tipično je sasvim razumno.
VARCHAR(255) ne znači da MySQL uvek rezerviše 255 karaktera kao fixed-length string.
Za fixed-length postoji:
CHAR(10)

što je druga priča.
TEXT
Za duži tekst:
description TEXT

Na primer opis hotela.
Mentalno:
VARCHAR
→ kraći/ograničeni stringovi

TEXT
→ veći tekstualni sadržaj

Ne treba automatski sve stringove praviti kao TEXT.
Integer tipovi
Često ćeš videti:
TINYINT
SMALLINT
MEDIUMINT
INT
BIGINT

Razlika je uglavnom u opsegu vrednosti.
Za obične ID-jeve često:
BIGINT UNSIGNED

Za neke male numeričke vrednosti:
TINYINT

na primer status flag, ali danas za boolean-like podatke treba pažljivo modelovati šta zapravo predstavljaš.
DECIMAL vs FLOAT
Ovo je veoma važno za cene.
Za cenu:
price DECIMAL(10, 2)

znači:
ukupno 10 cifara
2 cifre posle decimalnog separatora

Na primer:
12345678.90

Za novac koristimo:
DECIMAL

a ne:
FLOAT

jer FLOAT radi floating-point aproksimaciju.
Isto što smo već pričali u PHP-u:
money
→ ne želimo binary floating point greške

Za booking cenu:
nightly_price DECIMAL(10, 2)

je mnogo bolji izbor.
Date/time tipovi
Najvažniji:
DATE
DATETIME
TIMESTAMP
TIME

Primer:
check_in DATE
check_out DATE

jer rezervaciji možda treba samo datum.
Za konkretan trenutak:
created_at TIMESTAMP

ili:
created_at DATETIME

Razlike između TIMESTAMP i DATETIME ćemo posebno detaljnije kada dođemo do date/time modelovanja.
NULL i NOT NULL
Ovo:
name VARCHAR(100) NOT NULL

znači:
kolona mora imati vrednost; NULL nije dozvoljen.

Ako napišeš:
phone VARCHAR(30) NULL

onda telefon može biti nepoznat/nepostavljen.
Važno:
NULL
≠
''
≠
0

NULL znači:
nema vrednosti / nepoznato / nije postavljeno

dok:
''

jeste vrednost — samo prazan string.
Ovo će nam kasnije biti veoma bitno kod:
IS NULL
IS NOT NULL

DEFAULT
Možemo definisati default vrednost:
status VARCHAR(20) NOT NULL DEFAULT 'active'

ili:
created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP

Ako pri insert-u ne pošalješ tu kolonu, MySQL koristi default.
BOOLEAN
U MySQL-u:
BOOLEAN

je praktično alias za:
TINYINT(1)

pa možeš imati:
is_active BOOLEAN NOT NULL DEFAULT TRUE

ali ispod haube je numeričko predstavljanje.
Tipično:
0 → false
1 → true

Prvi ozbiljniji primer
CREATE TABLE hotels (
    id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,

    name VARCHAR(150) NOT NULL,

    description TEXT NULL,

    stars TINYINT UNSIGNED NULL,

    base_price DECIMAL(10, 2) NOT NULL,

    is_active BOOLEAN NOT NULL DEFAULT TRUE,

    created_at TIMESTAMP NOT NULL DEFAULT CURRENT_TIMESTAMP
);

Mentalno:
id
→ identitet

name
→ obavezni string

description
→ opcioni veći tekst

stars
→ mali integer

base_price
→ precizan decimal

is_active
→ boolean-like flag

created_at
→ timestamp

Tip podatka je deo poslovnog pravila
Ovo je veoma važno.
Tip ne biraš samo zato što „može da stane“.
Na primer:
price VARCHAR(20)

tehnički može da čuva:
"120.50"

ali je loš model.
Jer onda baza ne zna da je to broj.
Ne može prirodno da radi:
SUM(price)
AVG(price)
ORDER BY price

na način koji očekuješ.
Dakle schema treba da izražava značenje podatka.
Laravel paralela
Laravel migration:
$table->decimal('price', 10, 2);
$table->string('name', 150);
$table->text('description')->nullable();
$table->boolean('is_active')->default(true);

je samo lepši PHP API koji na kraju generiše SQL tipove.
Zato je dobro da znaš šta je ispod.
Mentalna mapa Lekcije 2
BIGINT / INT
→ celi brojevi

VARCHAR
→ kraći string

TEXT
→ duži tekst

DECIMAL
→ precizni decimalni brojevi / novac

DATE
→ datum

DATETIME / TIMESTAMP
→ datum + vreme

BOOLEAN
→ u MySQL-u praktično TINYINT(1)

NULL
→ nema vrednosti

NOT NULL
→ vrednost obavezna

DEFAULT
→ podrazumevana vrednost

Pitanje 2
Za sledeće podatke reci koji bi MySQL tip izabrao i zašto:
hotel id
hotel name
hotel description
nightly price
number of stars
check-in date
is hotel active
optional phone number

Ne moraš pisati CREATE TABLE, samo:
hotel id → ...
hotel name → ...
...

---

hotel id -> bigint, id je uvek integer a big jer uz malo sreće mozemo imati milione korisnika u bazi i obogatiti se 😄

hotel name -> varchar(cak do 55 ili 120) jer je u pitanju manji string, nije opis.

hotel description - text, u zavisnosti od app rules, mozda i longtext.

nightly price -> decimal, ne float jer bi decimal (10, 2) bio precizniji.

number of stars -> smallint, jer ocekujemo brojeve do 5 (7).

check-in date -> date, jer je u pitanju datum.

is hotel active -> boolean, jer nam treba samo true / false -> 
takođe moze se resiti i sa brojevima 0 i 1 pa staviti default 0 i as defined 0 i 1 - viđao sam i takva resenja.

optional phone number -> varchar(55) ne int, jer br tel moze sadrzati i neke znakove poput + pa je string prikladniji.

---

Odlično — 9.6/10. Razmišljaš već kao neko ko tip bira po značenju podatka, a ne samo „šta može da stane“. 😄
Najvažnije korekcije su male:
- hotel id → BIGINT UNSIGNED je dobar izbor za ID. U praksi još AUTO_INCREMENT PRIMARY KEY.
- hotel name → VARCHAR(120) ili VARCHAR(150) sasvim razumno.
- description → TEXT je najčešće dovoljno; LONGTEXT tek ako stvarno očekuješ ogromne sadržaje.
- nightly price → tačno, DECIMAL(10,2), ne FLOAT.
- number of stars → SMALLINT radi, ali je nepotrebno širok. Bolje:TINYINT UNSIGNED
  
  jer očekuješ 1–5 ili eventualno 1–7.
- check_in → DATE, tačno.
- is_active → BOOLEAN je sasvim čitljivo. U MySQL-u je praktično TINYINT(1).
- phone → apsolutno VARCHAR, ne broj. Telefon nije matematička vrednost.
Posebno dobro što si za telefon odmah prepoznao:
+381...

kao dovoljan razlog da ne koristiš integer.
