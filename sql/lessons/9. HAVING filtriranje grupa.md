# 9. HAVING filtriranje grupa

## Lekcija 9 — HAVING: filtriranje grupa

Ovo je jedna od najčešćih SQL interview tema:

---

## Koja je razlika između WHERE i HAVING?

Najkraće:

```text
WHERE
→ filtrira REDOVE pre grupisanja
```

```text
HAVING
→ filtrira GRUPE nakon GROUP BY
```

Recimo da imamo:

```text
city	hotel	price
Novi Sad	A	100
Novi Sad	B	150
Novi Sad	C	200
Belgrade	D	120
Belgrade	E	180
Niš	F	90
```

Query:

```sql
SELECT
    city,
    COUNT(*) AS total_hotels
FROM hotels
GROUP BY city;
```

daje:

```text
Novi Sad  → 3
Belgrade  → 2
Niš       → 1
```

Ali sada hoćemo:

Prikaži samo gradove koji imaju najmanje 2 hotela.

Ne možemo normalno raditi:

```sql
WHERE COUNT(*) >= 2
```

jer WHERE radi pre nego što je `COUNT(*)` izračunat.
Koristimo:

```sql
SELECT
    city,
    COUNT(*) AS total_hotels
FROM hotels
GROUP BY city
HAVING COUNT(*) >= 2;
```

Rezultat:

```text
Novi Sad  → 3
Belgrade  → 2
```

Niš otpada.

---

## WHERE + HAVING zajedno

Ovo je još važnije.
Recimo:

Posmatraj samo aktivne hotele, grupiši ih po gradu,
pa prikaži samo gradove koji imaju najmanje 5 aktivnih hotela.

```sql
SELECT
    city,
    COUNT(*) AS total_hotels,
    AVG(base_price) AS average_price
FROM hotels
WHERE is_active = TRUE
GROUP BY city
HAVING COUNT(*) >= 5;
```

Mentalni flow:

```text
svi hotels redovi
↓
WHERE is_active = TRUE
↓
ostaju samo aktivni REDOVI
↓
GROUP BY city
↓
nastaju GRUPE
↓
COUNT / AVG
↓
HAVING COUNT(*) >= 5
↓
ostaju samo odgovarajuće GRUPE
```

To je ključ cele lekcije.

---

## Još jedan primer

Želimo:

Gradove u kojima je prosečna cena hotela veća od 150.

```sql
SELECT
    city,
    AVG(base_price) AS average_price
FROM hotels
GROUP BY city
HAVING AVG(base_price) > 150;
```

Ovde HAVING ima smisla jer filtriramo rezultat agregacije:

```php
AVG(base_price)
```

```sql
WHERE ili HAVING?
```

Ako imaš:

Samo hotele sa cenom većom od 100

to je:

```sql
WHERE base_price > 100
```

jer filtriraš pojedinačne hotel redove.
Ako imaš:

Samo gradove čija je prosečna cena veća od 100

onda:

```sql
HAVING AVG(base_price) > 100
```

jer filtriraš grupe.
To je savršeno pitanje za intervju:

```text
WHERE
→ before grouping / rows
```

```text
HAVING
→ after grouping / groups
```

---

## Logički redosled query-ja

Ovo vredi početi da pamtiš:

```text
FROM
↓
WHERE
↓
GROUP BY
↓
HAVING
↓
SELECT
↓
ORDER BY
↓
LIMIT
```

SQL se piše:

```sql
SELECT ...
FROM ...
WHERE ...
GROUP BY ...
HAVING ...
ORDER BY ...
LIMIT ...
```

ali konceptualno se obrada ne odvija baš tim redom.
To objašnjava mnogo SQL ponašanja koje bi inače delovalo čudno.

## Pitanje 9

Napiši query koji:

- posmatra samo aktivne hotele
- grupiše ih po city
- za svaki grad vraća:

- city
- broj hotela kao total_hotels
- prosečnu cenu kao average_price
- prikazuje samo gradove koji imaju najmanje 3 aktivna hotela
- i čija je prosečna cena manja od 200
- sortira rezultat od najvećeg ka najmanjem broju hotela.

---

```sql
SELECT city, COUNT(*) AS total_hotels, AVG(base_price) as average_price
FROM hotels
GROUP BY city
HAVING COUNT(*) >= 3
AND AVG(base_price) < 200
ORDER BY total_hotels DESC;
```

PS. Vazno pitanje:

Zasto kazemo HAVING `COUNT(*)`  >= 3

---

## Ako vec imamo alias total_hotels?

Zar ne mozemo HAVING total_hotels > 3 ?

---

Tvoj query je skoro dobar — 9.2/10. Fali samo uslov da posmatramo aktivne hotele:

```sql
WHERE is_active = TRUE
```

Dakle kompletno:

```sql
SELECT
    city,
    COUNT(*) AS total_hotels,
    AVG(base_price) AS average_price
FROM hotels
WHERE is_active = TRUE
GROUP BY city
HAVING COUNT(*) >= 3
   AND AVG(base_price) < 200
ORDER BY total_hotels DESC;
```

I sad tvoje važno pitanje: da, u MySQL-u možeš koristiti alias u HAVING.
Dakle ovo je validno:

```sql
HAVING total_hotels >= 3
   AND average_price < 200
```

pa ceo query može biti:

```sql
SELECT
    city,
    COUNT(*) AS total_hotels,
    AVG(base_price) AS average_price
FROM hotels
WHERE is_active = TRUE
GROUP BY city
HAVING total_hotels >= 3
   AND average_price < 200
ORDER BY total_hotels DESC;
```

To je čak čitljivije.
Važna nijansa je gde alias možeš koristiti.
Recimo:

```sql
SELECT
    COUNT(*) AS total_hotels
FROM hotels
WHERE total_hotels >= 3;
```

❌ ne radi kako želiš.
Zašto? Zato što WHERE logički dolazi pre SELECT, pa alias total_hotels još nije nastao.
Mentalno:

```text
FROM
↓
WHERE          ← alias još ne postoji
↓
GROUP BY
↓
HAVING         ← MySQL dozvoljava SELECT alias
↓
SELECT
↓
ORDER BY       ← alias takođe može
```

Zato:

```sql
ORDER BY total_hotels DESC
```

je sasvim normalno.
I u MySQL-u:

```sql
HAVING total_hotels >= 3
```

je takođe dozvoljeno.
Zašto sam ti ja pisao:

```sql
HAVING COUNT(*) >= 3
```

uglavnom iz dva razloga.
Prvo, dok učimo HAVING, želim da se odmah vidi:

```text
HAVING
→ filtrira rezultat COUNT()
```

a ne da alias sakrije ono što se stvarno agregira.
Drugo, eksplicitna forma:

```sql
HAVING COUNT(*) >= 3
```

je generalno prenosivija između SQL sistema.
MySQL je dosta prijateljski nastrojen prema korišćenju SELECT aliasa u HAVING,
dok SQL dijalekti nisu u svemu identični.

Ali pošto učimo MySQL, slobodno piši:

```sql
HAVING total_hotels >= 3
   AND average_price < 200
```

Ja bih čak u realnom MySQL projektu često izabrao tu verziju zbog čitljivosti.
Samo pazi na tvoje pitanje:

```sql
HAVING total_hotels > 3?
```

Tražili smo najmanje 3, pa mora:

```sql
HAVING total_hotels >= 3
```

jer:

> 3   → 4, 5, 6...

>= 3  → 3, 4, 5, 6...

Za pamćenje:

```sql
WHERE alias ❌
HAVING alias ✅ u MySQL-u
ORDER BY alias ✅
```

A konceptualno:

`COUNT(*)` AS total_hotels

znači da su:

```sql
HAVING COUNT(*) >= 3
```

i, u MySQL-u,

```sql
HAVING total_hotels >= 3
```

u ovom slučaju samo dva načina da izraziš istu nameru.
