# 5. Select - where - order by - limit

## Lekcija 5 — SELECT, WHERE, ORDER BY, LIMIT

Sada prelazimo na najčešću SQL operaciju: čitanje podataka.
Najprostije:

```sql
SELECT *
FROM hotels;
```

* znači: sve kolone.
Ali u realnom kodu je često bolje eksplicitno:

```sql
SELECT id, name, base_price
FROM hotels;
```

Zašto? Manje podataka, jasniji intent, lakše održavanje.
WHERE
Filtrira redove:

```sql
SELECT id, name, base_price
FROM hotels
WHERE is_active = 1;
```

Ili:

```sql
SELECT id, name, base_price
FROM hotels
WHERE base_price > 100;
```

Možeš kombinovati uslove:

```sql
SELECT id, name, base_price
FROM hotels
WHERE is_active = 1
  AND base_price <= 150;
```

Ili:

```sql
WHERE city = 'Novi Sad'
   OR city = 'Belgrade'
```

Bitno:

```text
AND
→ oba uslova moraju biti true
```

```text
OR
→ dovoljan je jedan
```

Ako kombinuješ oba, koristi zagrade kad god logika nije trivijalna:

```sql
WHERE is_active = 1
  AND (city = 'Novi Sad' OR city = 'Belgrade');
```

## ORDER BY

Sortira rezultat:

```sql
SELECT id, name, base_price
FROM hotels
ORDER BY base_price ASC;
```

ASC = rastuće.
80
100
125
200

DESC = opadajuće.

```sql
ORDER BY base_price DESC;
```

Možeš sortirati po više kolona:

```sql
ORDER BY city ASC, base_price DESC;
```

Znači: prvo po gradu, a unutar istog grada skuplji hoteli prvi.
LIMIT
Ograničava broj redova:

```sql
SELECT id, name
FROM hotels
ORDER BY id DESC
LIMIT 10;
```

Vrati najviše 10 redova.
Za pagination ćeš često videti:

```sql
LIMIT 10 OFFSET 20;
```

što znači:

```text
preskoči prvih 20
uzmi sledećih 10
```

To je osnova klasične offset pagination.
Mentalno:

```text
SELECT
→ šta želim
```

```text
FROM
→ odakle
```

```text
WHERE
→ koji redovi
```

```text
ORDER BY
→ kojim redosledom
```

```text
LIMIT
→ koliko njih
```

## Pitanje 5

Napiši query koji vraća samo:

```text
id
name
base_price
```

iz hotels, ali samo za aktivne hotele čija je cena manja ili jednaka 150, sortirane od najjeftinijeg ka najskupljem, i vrati najviše 5 rezultata.

Nije mi jasna logika zasto biamo preskakali 20 pa prikazivali 10...

```sql
SELECT id, name, base_price
FROM hotels
WHERE is_active = TRUE
  AND base_price <= 150
ORDER BY base_price ASC

```

I da, potpuno si u pravu za:

ASC

Možeš ga izostaviti jer je podrazumevani smer za ORDER BY uzlazni:

```sql
ORDER BY base_price;
```


## Pagination — zašto LIMIT 10 OFFSET 20?

Ovde je ključ da ne razmišljaš:

„Zašto bih bezveze preskočio 20 rezultata?“

nego:

„Korisnik je već video prvih 20 rezultata na prethodnim stranicama.“

Recimo da imamo 47 hotela, a želimo da prikazujemo 10 po stranici.
Stranica 1 treba:

hotel 1–10

SQL:

```sql
SELECT id, name
FROM hotels
ORDER BY id
LIMIT 10 OFFSET 0;
```

Odnosno:

```text
preskoči 0
uzmi 10
```

Stranica 2 treba:

hotel 11–20

SQL:

```sql
SELECT id, name
FROM hotels
ORDER BY id
LIMIT 10 OFFSET 10;
```

Znači:

```text
preskoči prvih 10
uzmi sledećih 10
```

Stranica 3:

hotel 21–30

SQL:

```sql
SELECT id, name
FROM hotels
ORDER BY id
LIMIT 10 OFFSET 20;
```

E sada je jasno zašto:

OFFSET 20

Ne preskačemo 20 rezultata zato što nam nisu važni.
Preskačemo ih zato što pripadaju:

```text
page 1 → 1–10
page 2 → 11–20
```

a user trenutno traži:

```text
page 3 → 21–30
```

Formula
Ako imamo:

```php
$page
$perPage
```

onda je:

```php
$offset = ($page - 1) * $perPage;
```

Recimo:

```php
$page = 1;
$perPage = 10;
```

dobijamo:

(1 - 1) × 10 = 0

SQL:

```sql
LIMIT 10 OFFSET 0
```

Page 2:

(2 - 1) × 10 = 10

SQL:

```sql
LIMIT 10 OFFSET 10
```

Page 3:

(3 - 1) × 10 = 20

SQL:

```sql
LIMIT 10 OFFSET 20
```

Page 7 sa po 20 rezultata:

```text
(7 - 1) × 20
= 120
```

znači:

```sql
LIMIT 20 OFFSET 120;
```

Odnosno:

Preskoči 120 rezultata koji pripadaju prethodnih šest stranica i daj mi sledećih 20.

## Kako to izgleda kroz aplikaciju?

Recimo da URL bude:

/hotels.php?page=3

PHP dobije:

```php
$page = $_GET['page'] ?? 1;
```

Naravno, kao što smo učili u HTTP/validation modulu, ne verujemo odmah `$_GET`.
Konceptualno:

```php
$page = valid positive integer ? page : 1;

$perPage = 10;

$offset = ($page - 1) * $perPage;
```

Ako user otvori:

?page=3

PHP izračuna:

```php
$page = 3;

$offset = (3 - 1) * 10;
// 20
```

pa SQL postane konceptualno:

```sql
SELECT id, name, base_price
FROM hotels
ORDER BY id
LIMIT 10 OFFSET 20;
```

MySQL vrati samo redove potrebne za tu stranicu.
PHP ih renderuje.

## Ali kako znamo koliko stranica postoji?

Odlično pitanje koje prirodno dolazi odmah iza ovoga.
Treba nam broj svih rezultata.
Recimo:

```sql
SELECT COUNT(*)
FROM hotels
WHERE is_active = 1;
```

Pretpostavimo rezultat:

47

A:

perPage = 10

Broj stranica:

```php
$totalPages = ceil(47 / 10);
```

dobijamo:

5 stranica

Jer:

```text
page 1 → 10
page 2 → 10
page 3 → 10
page 4 → 10
page 5 → 7
```

Dakle kompletan pagination mentalni model je:

```text
GET ?page=3
↓
validate page
↓
perPage = 10
↓
offset = (page - 1) * perPage
↓
SELECT COUNT(*) → koliko ukupno ima
↓
```

```sql
SELECT ...
LIMIT 10 OFFSET 20
```

```text
↓
render results
↓
```

render:

1 2 [3] 4 5

## Zato Laravel deluje kao magija

Kada radiš:

```php
Hotel::where('is_active', true)
    ->paginate(10);
```

Laravel praktično odradi celu tu infrastrukturu za tebe.
Konceptualno radi nešto nalik:

```sql
SELECT COUNT(*)
FROM hotels
WHERE is_active = 1;
```

da sazna ukupno rezultata,
pa za trenutnu stranicu, recimo page 3:

```sql
SELECT *
FROM hotels
WHERE is_active = 1
LIMIT 10 OFFSET 20;
```

i onda ti napravi objekat koji zna:

```text
currentPage
perPage
total
lastPage
nextPage
previousPage
```

Zato možeš u Blade-u elegantno:

```php
$hotels->links()
```

Ali ispod haube postoji upravo ova matematika.

## Jedna veoma važna stvar — ORDER BY

Kod pagination-a gotovo uvek želiš deterministički ORDER BY.
Nemoj:

```sql
SELECT *
FROM hotels
LIMIT 10 OFFSET 20;
```

bez jasnog reda i onda očekivati stabilne stranice.
Bolje:

```sql
SELECT *
FROM hotels
ORDER BY id ASC
LIMIT 10 OFFSET 20;
```

ili:

```sql
ORDER BY created_at DESC, id DESC
```

## Zašto?

Jer pagination zapravo kaže:

„Daj mi elemente broj 21–30 u ovom redosledu.“

Bez definisanog redosleda koncept „21. rezultat“ nije dovoljno stabilan.

## Konkretan BookYourHotel primer

Recimo search vrati 86 hotela.
Želiš:

12 po stranici

User klikne:

?page=4

PHP:

```php
$page = 4;
$perPage = 12;

$offset = ($page - 1) * $perPage;

// 3 * 12
// 36
```

Query:

```sql
SELECT id, name, base_price
FROM hotels
WHERE is_active = 1
ORDER BY base_price ASC, id ASC
LIMIT 12 OFFSET 36;
```

To znači:

```text
rezultati 1–12   → page 1
13–24            → page 2
25–36            → page 3
37–48            → PAGE 4
```

Zato preskačemo 36, pa uzimamo sledećih 12.
