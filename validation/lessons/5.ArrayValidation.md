# 5.ArrayValidation

Odlično. Idemo na Lekciju 5 — Validation array-a i nested inputa.
Ovo je veoma bitno jer čim forma ima checkbox grupe, više adresa, room IDs, tagove ili kompleksniji JSON, više ne validiraš samo jednu scalar vrednost nego strukturu + svaki element unutar nje.
Pretpostavimo HTML:

```html
<input type="checkbox" name="features[]" value="wifi">
<input type="checkbox" name="features[]" value="spa">
<input type="checkbox" name="features[]" value="parking">
```

Ako user čekira wifi i spa, PHP dobija:

```php
$_POST['features'] = [
    'wifi',
    'spa',
];
```

Prvo pitanje nije:

„Da li je wifi dozvoljen?“

nego:

„Da li je features uopšte array?“

Znači:

```php
$features = $_POST['features'] ?? [];

if (!is_array($features)) {
    $errors['features'] = 'Features must be an array.';
}
```

---

## Zašto?

Jer client može ručno poslati:

features=banana

i tada dobiješ:

```php
$_POST['features'] === 'banana';
```

Ako odmah uradiš:

```php
foreach ($features as $feature) {
```

imaćeš problem.
Mentalni model je:

```text
STRUCTURE VALIDATION
↓
ELEMENT VALIDATION
```

Dakle prvo:

```php
is_array($features)
```

pa tek onda:

```php
foreach ($features as $feature) {
    // validiraj svaki element
}
```

Recimo da dozvoljavamo samo:

```php
$allowedFeatures = [
    'wifi',
    'spa',
    'parking',
];
```

Možemo:

```php
$features = $_POST['features'] ?? [];

if (!is_array($features)) {
    $errors['features'] = 'Features must be an array.';
} else {
    foreach ($features as $feature) {
        if (
            !is_string($feature) ||
            !in_array($feature, $allowedFeatures, true)
        ) {
            $errors['features'] = 'Invalid feature selected.';
            break;
        }
    }
}
```

Obrati pažnju na:

```php
in_array(
    $feature,
    $allowedFeatures,
    true
)
```

Ovo true uključuje strict comparison.
Dakle:

```php
in_array('1', [1], true); // false
```

dok bez strict:

```php
in_array('1', [1]); // može biti true
```

Za validation uglavnom želimo:

strict comparison

## Nested input

Recimo forma:

```html
<input name="address[city]">
<input name="address[zip]">
```

PHP napravi:

```php
$_POST['address'] = [
    'city' => 'Novi Sad',
    'zip' => '21000',
];
```

Opet prvo struktura:

```php
$address = $_POST['address'] ?? null;

if (!is_array($address)) {
    $errors['address'] = 'Address must be an object-like structure.';
}
```

Tek onda pojedinačna polja:

```php
$city = $address['city'] ?? null;
$zip = $address['zip'] ?? null;
```

pa:

```php
if (!is_string($city) || trim($city) === '') {
    $errors['city'] = 'City is required.';
}
```

i:

```php
if (
    !is_string($zip) ||
    !preg_match('/^\d{5}$/', $zip)
) {
    $errors['zip'] = 'Invalid ZIP code.';
}
```

Dakle:

```text
address
↓
is_array?
↓
city / zip postoje?
↓
tip svakog polja
↓
normalization
↓
format/business validation
```

## Array of objects / nested rows

Sada nešto realnije.
Recimo JSON:

```json
{
  "rooms": [
    {
      "room_id": 5,
      "guests": 2
    },
    {
      "room_id": 8,
      "guests": 3
    }
  ]
}
```

Ovo je vrlo slično nečemu što možeš imati u booking sistemu.
Prvo:

```php
$rooms = $data['rooms'] ?? null;

if (!is_array($rooms)) {
    $errors['rooms'] = 'Rooms must be an array.';
}
```

Onda svaki element:

```php
foreach ($rooms as $index => $room) {
    if (!is_array($room)) {
        $errors["rooms.$index"] = 'Invalid room structure.';
        continue;
    }

    $roomId = $room['room_id'] ?? null;
    $guests = $room['guests'] ?? null;

    if (!is_int($roomId)) {
        $errors["rooms.$index.room_id"] = 'Room ID must be integer.';
    }

    if (
        !is_int($guests) ||
        $guests < 1 ||
        $guests > 10
    ) {
        $errors["rooms.$index.guests"] =
            'Guests must be between 1 and 10.';
    }
}
```

Ovo je već veoma blizu Laravel error bag konceptu:

```text
rooms.0.room_id
rooms.0.guests
rooms.1.guests
```

## Da li je to validno?

Zavisi od poslovnog pravila.
Ako je rooms optional:

```php
[]
```

možda je OK

Ako booking mora imati makar jednu sobu:

```php
if ($rooms === []) {
    $errors['rooms'] = 'At least one room is required.';
}
```

ili:

```php
if (count($rooms) < 1) {
```

Dakle:

```php
is_array()
```

proverava samo tip/strukturu.
Ne proverava business rule:

minimum 1 element
maximum 5 elemenata
unique values
...

Duplikati
Recimo:

```php
$features = [
    'wifi',
    'wifi',
    'spa',
];
```

Svi elementi pojedinačno jesu validni.
Ali možda business rule kaže da duplikati nisu dozvoljeni.
Možeš:

```php
if (count($features) !== count(array_unique($features))) {
    $errors['features'] = 'Duplicate features are not allowed.';
}
```

I opet vidiš razliku:

```text
ELEMENT VALIDATION
≠
ARRAY-LEVEL BUSINESS VALIDATION
```

## Još jedan važan primer: ID lista

Recimo HTML šalje:

```text
room_ids[]=5
room_ids[]=8
room_ids[]=11
```

Pošto je HTML forma, vrednosti dolaze kao stringovi:

```php
[
    '5',
    '8',
    '11',
]
```

Tu ne bi radio:

```php
is_int($roomId)
```

jer će pasti.
Možeš:

```php
foreach ($roomIds as $roomId) {
    if (
        !is_string($roomId) ||
        !ctype_digit($roomId)
    ) {
        // invalid
    }

    $roomId = (int) $roomId;
}
```

Ili:

```php
$validatedRoomId = filter_var(
    $roomId,
    FILTER_VALIDATE_INT,
    [
        'options' => [
            'min_range' => 1,
        ]
    ]
);
```

Kod JSON-a bi možda tražio pravi integer:

```php
is_int($roomId)
```

Opet ista priča:

```text
HTML form
→ string representation
```

```text
JSON
→ tip je deo payload-a
```

## Laravel paralela

Laravel ovde daje vrlo elegantne rule-ove:

```php
$request->validate([
    'features' => ['required', 'array'],
    'features.*' => ['string', 'in:wifi,spa,parking'],
]);
```

ili:

```php
$request->validate([
    'rooms' => ['required', 'array', 'min:1'],
    'rooms.*.room_id' => ['required', 'integer'],
    'rooms.*.guests' => ['required', 'integer', 'between:1,10'],
]);
```

Tačka * znači:

validiraj svaki element kolekcije.

Mi sada praktično ručno pravimo isti mentalni model.

## Kako bi ti redom validirao ovaj input?

Ne treba ceo kod ako nećeš — zanima me prvenstveno redosled provera i šta bi uradio sa svakim elementom.

---

rvo bih proverio da li je niz:

```php
$roomIds = $_POST['room_ids'] ?? [];

if(!is_array($roomIds)) { // invalid}
```

Pa da li ima minimum 1 element?

```php
if(count($roomIds) < 1) // invalid
```

Onda svaki po na osob da li je validan, pozitivan broj (koji inace iz forme dolazi kao string):

```php
foreach($roomIds as $id) {
   if(!is_string($id) || !ctype_digit($id) // error;

  Onda cast:
  $id = (int) $id;
}
```

---

Redosled ti je dobar:

1. uzmi input
2. proveri da je array
3. proveri minimum 1 element
4. proveri svaki element
5. cast tek posle uspešne validacije

Jedina bitna dopuna je ovo: `ctype_digit()` prihvata i:

'0'

jer je to string sastavljen od cifara.
A zahtev kaže:

pozitivan integer

što znači > 0.
Dakle posle cast-a treba još:

```php
$id = (int) $id;

if ($id < 1) {
    // invalid
}
```

Ili možeš sve spojiti preko FILTER_VALIDATE_INT:

```php
$validatedId = filter_var(
    $id,
    FILTER_VALIDATE_INT,
    [
        'options' => [
            'min_range' => 1,
        ]
    ]
);

if ($validatedId === false) {
    // invalid
}
```

Ali tvoj `ctype_digit()` + cast + range pristup je sasvim legitiman.
Još jedna dobra praksa: nemoj samo kastovati lokalnu `$id` promenljivu ako ti kasnije treba normalizovan niz. Umesto:

```php
foreach ($roomIds as $id) {
    $id = (int) $id;
}
```

napravi:

```php
$validatedRoomIds = [];

foreach ($roomIds as $id) {
    if (!is_string($id) || !ctype_digit($id)) {
        // error
        continue;
    }

    $id = (int) $id;

    if ($id < 1) {
        // error
        continue;
    }

    $validatedRoomIds[] = $id;
}
```

Na kraju dobiješ čist array:

```php
[5, 8]
```

umesto originalnog:

```php
['5', '8', 'banana']
```

To je važna ideja: validacija + normalizacija često treba da proizvedu novi, trusted-ish podatak za dalju business logiku.
