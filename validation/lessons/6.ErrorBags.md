# 6.ErrorBags

## Error bags i više validation grešaka

Pretpostavimo formu:

```html
<input name="name">
<input name="email">
<input name="age">
```

Početnički pristup često izgleda ovako:

```php
if (...) {
    exit('Invalid name');
}

if (...) {
    exit('Invalid email');
}

if (...) {
    exit('Invalid age');
}
```

Problem je UX:

```text
submit
→ popravi name
→ submit
→ popravi email
→ submit
→ popravi age
```

Mnogo je bolje:

```text
submit
→ vidi sve greške odjednom
```

Zato pravimo error bag:

```php
$errors = [];
```

i onda svako polje upisuje svoju grešku:

```php
$errors['name'] = 'Name is required.';
$errors['email'] = 'Email is invalid.';
$errors['age'] = 'Age must be between 18 and 100.';
```

Na kraju:

```php
if ($errors !== []) {
    // validation failed
}
```

```text
Osnovni primer
$errors = [];
```

```php
$name = $_POST['name'] ?? null;
$email = $_POST['email'] ?? null;
$age = $_POST['age'] ?? null;
```

```text
Name
if (!is_string($name)) {
    $errors['name'] = 'Name must be a string.';
} else {
    $name = trim($name);
```

```php
    if ($name === '') {
        $errors['name'] = 'Name is required.';
    } elseif (mb_strlen($name) > 100) {
        $errors['name'] = 'Name may not exceed 100 characters.';
    }
}
```

Obrati pažnju na elseif.
Ako je name prazan, nema smisla da korisniku još kažeš:

Name may not exceed 100 characters.

Za jedno polje često želiš jednu najrelevantniju grešku.
Email

```php
if (!is_string($email)) {
    $errors['email'] = 'Email must be a string.';
} else {
    $email = trim($email);

    if ($email === '') {
        $errors['email'] = 'Email is required.';
    } elseif (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
        $errors['email'] = 'Email must be valid.';
    }
}
```

Age
Kod HTML forme:

```php
if (!is_string($age)) {
    $errors['age'] = 'Age is required.';
} else {
    $age = trim($age);

    if ($age === '') {
        $errors['age'] = 'Age is required.';
    } else {
        $validatedAge = filter_var(
            $age,
            FILTER_VALIDATE_INT,
            [
                'options' => [
                    'min_range' => 18,
                    'max_range' => 100,
                ],
            ]
        );

        if ($validatedAge === false) {
            $errors['age'] = 'Age must be an integer between 18 and 100.';
        } else {
            $age = $validatedAge;
        }
    }
}
```

Na kraju:

```php
if ($errors !== []) {
    // ne idi u DB
}
```

Ako nema grešaka:

```php
// $name
// $email
// $age

// sada su validirani / normalizovani
```

## Error bag po polju

Najčešći oblik:

```php
$errors = [
    'name' => 'Name is required.',
    'email' => 'Email is invalid.',
];
```

Prednost je što view može lako:

```php
<?= htmlspecialchars($errors['name'] ?? '') ?>
```

ispod konkretnog inputa.
To je mnogo bolje nego jedan generički:

```php
$errors[] = 'Something is wrong.';
```

jer ne znaš kojoj kontroli pripada.

---

A šta ako jedno polje ima više grešaka?

Postoje dva pristupa.
Jedna greška po polju

```php
$errors['password'] = 'Password must contain at least 8 characters.';
```

Ovo je jednostavno i vrlo često dovoljno.
Više grešaka po polju

```php
$errors['password'][] = 'Password must contain at least 8 characters.';
$errors['password'][] = 'Password must contain a number.';
$errors['password'][] = 'Password must contain a symbol.';
```

Onda dobiješ:

```php
[
    'password' => [
        'Password must contain at least 8 characters.',
        'Password must contain a number.',
        'Password must contain a symbol.',
    ]
]
```

Ovo može biti korisno za kompleksna pravila.
Ali za obične forme često je bolji UX da korisniku pokažeš prvu relevantnu grešku po polju.

## Laravel paralela

Kada Laravel validacija padne, framework praktično pravi error bag za tebe.
Na primer:

```php
$request->validate([
    'name' => ['required', 'string', 'max:100'],
    'email' => ['required', 'email'],
    'age' => ['required', 'integer', 'between:18,100'],
]);
```

U Blade-u:

```text
@error('email')
    {{ $message }}
@enderror
```

iza toga konceptualno postoji upravo:

errors['email']

što sada ručno pravimo.

## Važna odluka: fail-fast ili collect-all

Postoje dva nivoa.

---

## Na nivou cele forme

Ne želimo:

```text
if invalid name → exit
```

nego:

```text
validiraj name
validiraj email
validiraj age
→ skupi sve
```

To je collect-all.
Ali unutar jednog polja često koristimo fail-fast.
Na primer:

```php
if (!is_string($email)) {
    $errors['email'] = 'Email must be a string.';
} elseif (trim($email) === '') {
    $errors['email'] = 'Email is required.';
} elseif (!filter_var($email, FILTER_VALIDATE_EMAIL)) {
    $errors['email'] = 'Email is invalid.';
}
```

Nema smisla da posle:

email = []

proveravamo `trim()`, pa email format itd.
Znači:

```text
FORMA
→ collect all field errors
```

```text
JEDNO POLJE
→ često fail-fast kroz svoja pravila
```

To je dobar mentalni model.

## Old input + errors

Ovo se lepo spaja sa prethodnim PRG zadatkom.
Ako imamo:

```php
if ($errors !== []) {
    $_SESSION['errors'] = $errors;

    $_SESSION['old'] = [
        'name' => is_string($name) ? $name : '',
        'email' => is_string($email) ? $email : '',
        'age' => is_string($_POST['age'] ?? null)
            ? $_POST['age']
            : '',
    ];

    header('Location: create.php', true, 303);
    exit;
}
```

Na GET-u:

```php
$errors = $_SESSION['errors'] ?? [];
$old = $_SESSION['old'] ?? [];
```

i prikaz:

```html
<input
    name="email"
    value="<?= htmlspecialchars(
        $old['email'] ?? '',
        ENT_QUOTES,
        'UTF-8'
    ) ?>"
```

>

pa:

```php
<?php if (isset($errors['email'])): ?>
```

```html
    <p>
        <?= htmlspecialchars(
            $errors['email'],
            ENT_QUOTES,
            'UTF-8'
        ) ?>
    </p>
<?php endif; ?>
```

To je već potpuno realan form validation flow.

## Jedna važna dizajnerska stvar

Ne bih radio:

```php
$errors['name'] = 'Invalid.';
$errors['name'] = 'Too long.';
```

jer drugi upis pregazi prvi.
Ako želiš jednu grešku po polju, koristi if/elseif.
Ako želiš više:

```php
$errors['name'][] = '...';
```

Namerno odluči koji model koristiš.

---

## Pitanje za tebe

Imamo tri polja:

```text
name
email
age
```

i user pošalje:

```text
name = ""
email = "banana"
age = "150"
```

Objasni mi kako bi error bag izgledao nakon validacije ako želimo jednu grešku po polju,
i zašto ne bismo radili exit čim pronađemo grešku u name.

---

Dakle error bag bi bio assoc niz koji bi otprilike imao:

```php
[
 'name' => 'Name is required',
'email' => ...
'age' => ...
]
```

A exit ne radimo iz prostog razloga zbog UI da ne vraćamo korisnika 100 puta, nego on lepo popuni,
mi pokupimo sve greške i vratimo mu tačno grešku za svako polje ako ima grešaka. Onda on zna šta treba popraviti...
