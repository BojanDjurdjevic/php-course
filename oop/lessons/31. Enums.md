# 31. Enums

## Lekcija 31 — Enums u PHP-u

Enum = enumeration.

Koristimo ga kada neka vrednost može pripadati konačnom, unapred poznatom skupu opcija.

Tipičan booking primer:

```text
pending
confirmed
cancelled
completed
```

Bez enum-a možda imamo:

```php
$status = 'confirmed';
```

Problem je što možemo slučajno napisati:

```php
$status = 'confrimed';
```

PHP kaže:

String je string. Meni je ovo sasvim legalno.

Enum uvodi pravi tip.

```php
enum BookingStatus
{
    case Pending;
    case Confirmed;
    case Cancelled;
    case Completed;
}
```

Sada:

```php
$status = BookingStatus::Confirmed;
```

više nemamo proizvoljan string.
Mentalno:

```text
string
→ praktično beskonačno mogućih vrednosti
```

```text
BookingStatus
→ samo 4 dozvoljene vrednosti
```

To je najveća vrednost enum-a.

---

## Enum case je objekat

Ovo je bitno.

```php
$status = BookingStatus::Confirmed;
```

`$status` nije string "Confirmed".
To je enum objekat/case tipa:

BookingStatus

Zato možeš:

```php
var_dump($status instanceof BookingStatus);
// true
```

I poređenje radi elegantno:

```php
if ($status === BookingStatus::Confirmed) {
    // ...
}
```

Ovde je === potpuno prirodan izbor.

---

## Backed enums

Ovo će ti za Laravel biti još važnije.
Možemo enum povezati sa stvarnom scalar vrednošću:

```text
enum BookingStatus: string
{
    case Pending = 'pending';
    case Confirmed = 'confirmed';
    case Cancelled = 'cancelled';
    case Completed = 'completed';
}
```

Ovo se zove backed enum.
Može biti backed sa:

```text
string
ili
int
```

Na primer:

```text
enum UserRole: int
{
    case Admin = 1;
    case Supplier = 2;
    case Customer = 3;
}
```

Ali za statuse je string često čitljiviji.
->value
Kod backed enum-a:

```php
$status = BookingStatus::Confirmed;

echo $status->value;
```

dobijaš:

confirmed

Dakle:

```text
BookingStatus::Confirmed
→ enum case
```

```text
BookingStatus::Confirmed->value
→ 'confirmed'
```

Ovo je veoma bitna razlika.
`from()` i `tryFrom()`
Ako iz baze ili HTTP input-a dobiješ:

```php
$status = 'confirmed';
```

možeš ga pretvoriti u enum:

```php
$status = BookingStatus::from('confirmed');
```

dobiješ:

`BookingStatus::Confirmed`

Ali ako uradiš:

```php
BookingStatus::from('banana');
```

dobićeš grešku:

ValueError

Ako ne želiš exception:

```php
$status = BookingStatus::tryFrom('banana');
```

dobiješ:

null

Mentalno:

```text
from()
→ mora postojati
→ inače exception
```

```text
tryFrom()
→ pokušaj
→ ako ne postoji, null
```

Ovo je dobro interview pitanje.

```php
cases()
```

Možeš dobiti sve moguće enum vrednosti:

```php
$statuses = BookingStatus::cases();
```

To daje array enum case-ova.
Na primer:

```php
foreach (BookingStatus::cases() as $status) {
    echo $status->value;
}
```

Možeš time lako praviti `<select>`:

```html
<select>
    <?php foreach (BookingStatus::cases() as $status): ?>
        <option value="<?= $status->value ?>">
            <?= $status->name ?>
        </option>
    <?php endforeach; ?>
</select>
```

name vs value
Kod:

`BookingStatus::Confirmed`

imaš:

`BookingStatus::Confirmed`->name

rezultat:

Confirmed

i:

`BookingStatus::Confirmed`->value

rezultat:

confirmed

Dakle:

```text
name
→ PHP naziv case-a
```

```text
value
→ backed vrednost
```

## Enum može imati metode

Ovo je deo zbog kog enum nije samo lepša konstanta.
Na primer:

```text
enum BookingStatus: string
{
    case Pending = 'pending';
    case Confirmed = 'confirmed';
    case Cancelled = 'cancelled';
    case Completed = 'completed';
```

```php
    public function label(): string
    {
        return match ($this) {
            self::Pending => 'Pending',
            self::Confirmed => 'Confirmed',
            self::Cancelled => 'Cancelled',
            self::Completed => 'Completed',
        };
    }
}
```

Pa:

```php
echo BookingStatus::Confirmed->label();
```

Dakle enum može da nosi ponašanje vezano za svoj zatvoren skup vrednosti.
Još korisnije:

```php
public function canBeCancelled(): bool
{
    return match ($this) {
        self::Pending,
        self::Confirmed => true,

        self::Cancelled,
        self::Completed => false,
    };
}
```

Pa:

```php
if ($booking->status->canBeCancelled()) {
    // ...
}
```

To već izgleda kao ozbiljan domain model.

## Enum vs constants

Pre enum-a često bismo imali:

```php
class Booking
{
    public const STATUS_PENDING = 'pending';
    public const STATUS_CONFIRMED = 'confirmed';
    public const STATUS_CANCELLED = 'cancelled';
}
```

To je bolje od magic strings, ali i dalje:

```php
function changeStatus(string $status)
```

prima bilo koji string.
Sa enum-om:

```php
function changeStatus(BookingStatus $status)
```

PHP sada garantuje:

Moraš mi dati validan BookingStatus.

To je mnogo jači contract.
Dakle:

```text
constants
→ centralizuju vrednosti
```

```text
enum
→ centralizuje vrednosti + pravi type + može imati behavior
```

Zato je enum obično bolji kada imamo pravi zatvoren skup dozvoljenih stanja.

## Laravel veza — Eloquent cast

Ovo ti je verovatno najpoznatija upotreba.
Model:

```php
use App\Enums\BookingStatus;

class Booking extends Model
{
    protected function casts(): array
    {
        return [
            'status' => BookingStatus::class,
        ];
    }
}
```

U bazi imaš:

confirmed

ali Laravel ti može dati:

```php
$booking->status
```

kao:

`BookingStatus::Confirmed`

Onda možeš:

```php
if ($booking->status === BookingStatus::Confirmed) {
    // ...
}
```

i:

```php
$booking->status = BookingStatus::Cancelled;

$booking->save();
```

Eloquent odradi konverziju između enum-a i DB vrednosti.
To je mnogo čistije od:

```php
if ($booking->status === 'confirmed') {
```

na 30 mesta.

## Enum + validation u Laravelu

Možeš čak validirati enum:

```php
use Illuminate\Validation\Rule;

'status' => [
    'required',
    Rule::enum(BookingStatus::class),
],
```

Dakle request layer može garantovati da je input validan enum case.

## Kada enum nije dobar izbor?

Ako se vrednosti često dodaju iz baze od strane admina.
Recimo:

```text
hotel categories
amenities
cities
countries
product categories
```

Ako admin treba da može da doda novu kategoriju
bez deploy-a, enum je pogrešan alat.

Enum je compile/code-level zatvoren skup.
Dakle:

```text
STATUS
→ često enum
```

```text
DINAMIČKI DB PODACI
→ tabela/model
```

## Enum može implementirati interface

Može čak i:

```php
interface HasLabel
{
    public function label(): string;
}
```

pa:

```text
enum BookingStatus: string implements HasLabel
{
    case Pending = 'pending';
    case Confirmed = 'confirmed';
```

```php
    public function label(): string
    {
        return match ($this) {
            self::Pending => 'Pending',
            self::Confirmed => 'Confirmed',
        };
    }
}
```

Dakle enum je prilično ozbiljan OOP element, ne samo fancy constant.

---

## Jedna važna stvar: enum ne može da extends klasu

Enum nije regularna inheritance baza.
Ne može:

```php
enum BookingStatus extends Something
```

Ali može:

implements SomeInterface

i može koristiti trait, uz odgovarajuća ograničenja.

## Mini provera za enum

Ako imamo:

```text
enum BookingStatus: string
{
    case Pending = 'pending';
    case Confirmed = 'confirmed';
}
```

koja je razlika između:

`BookingStatus::Confirmed`

`BookingStatus::Confirmed`->name

i:

`BookingStatus::Confirmed`->value

?
Posle ovog odgovora vraćamo se tačno gde smo stali: OOP Interview pitanje #2.

---

name -> naziv case-a,
u ovom slučaju Confirmed.

value -> backend vrednost case-a
u ovom slučaju: confirmed.

---

Tačno — 10/10.
Još kompletno:

`BookingStatus::Confirmed`

je sam enum case objekat tipa BookingStatus.
`BookingStatus::Confirmed`->name

```php
// 'Confirmed'
```

je naziv case-a.
`BookingStatus::Confirmed`->value

```php
// 'confirmed'
```

je njegova backed vrednost.
Dakle:

```text
case object → BookingStatus::Confirmed
name        → Confirmed
value       → confirmed
```
