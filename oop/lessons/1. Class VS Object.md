## Lekcija 1: Class vs Object — šta objekat zapravo predstavlja?

Najvažnija mentalna razlika:

```text
class
→ definicija / blueprint / tip
```

```text
object
→ konkretna instanca te klase
→ ima svoje stanje u runtime-u
```

Na primer:

```php
class User
{
    public int $id;
    public string $name;
}
```

Ovo još nije korisnik.
Ovo je samo definicija:

Svaki objekat tipa User može imati id i name.

Tek kada uradimo:

```php
$user = new User();
```

nastaje objekat.
Možemo napraviti više objekata iste klase:

```php
$user1 = new User();
$user1->id = 1;
$user1->name = 'Ana';

$user2 = new User();
$user2->id = 2;
$user2->name = 'Marko';
```

Imamo:

```text
User class
   │
   ├── object #1
   │   id = 1
   │   name = Ana
   │
   └── object #2
       id = 2
       name = Marko
```

Iako oba objekta koriste istu definiciju klase, imaju sopstveno stanje.

---

## Objekat = State + Behavior

Ovo je korisniji OOP mentalni model od „class je šablon“.
Objekat obično objedinjuje:

```text
STATE
→ šta objekat trenutno zna / sadrži
```

```text
BEHAVIOR
→ šta objekat može da radi
```

Recimo:

```php
class Booking
{
    public string $status = 'pending';

    public function confirm(): void
    {
        $this->status = 'confirmed';
    }
}
```

Ovde:

```text
status
→ state
```

```text
confirm()
→ behavior
```

Kad napravimo:

```php
$booking = new Booking();
```

imamo:

```text
Booking object
├── state:
│   status = pending
│
└── behavior:
    confirm()
```

pa:

```php
$booking->confirm();
```

menja stanje baš tog objekta:

```text
pending
↓
confirmed
```

```php
$this
```

Ovo je jedna od centralnih OOP stvari.
U:

```php
public function confirm(): void
{
    $this->status = 'confirmed';
}
```

`$this` znači:

trenutni objekat nad kojim je metoda pozvana.

Ako imamo:

```php
$booking1 = new Booking();
$booking2 = new Booking();

$booking1->confirm();
```

onda:

```text
$booking1->status
→ confirmed
```

```text
$booking2->status
→ pending
```

Iako oba koriste istu metodu `confirm()`,
`$this` se odnosi na objekat koji je metodu pozvao.
Mentalno:

```php
$booking1->confirm();
```

otprilike znači:

"Pozovi `confirm()` nad booking1 objektom."

pa unutar metode:

```php
$this
```

znači:

```php
$booking1
```

## Zašto uopšte OOP?

Proceduralno bismo možda imali:

```php
$bookingStatus = 'pending';

function confirmBooking(&$status)
{
    $status = 'confirmed';
}
```

OOP kaže:

Ako status pripada booking-u, a `confirm()` menja booking,
zašto ih ne bismo držali zajedno?

Dakle:

```php
class Booking
{
    public string $status = 'pending';

    public function confirm(): void
    {
        $this->status = 'confirmed';
    }
}
```

Time povezujemo podatke i operacije koje njima pripadaju.
Ali važno: OOP nije samo:

„stavi sve funkcije u klase“.

Dobar OOP pokušava da modeluje odgovornosti i granice.
Kasnije ćemo zato razlikovati:

```text
Booking
→ predstavlja booking
```

```text
BookingRepository
→ zna kako da booking učita/snima
```

```text
BookingService
→ vodi booking use-case
```

```text
BookingController
→ prima HTTP zahtev
```

To je već mnogo bliže onome što radiš u Laravelu.

## Objekti imaju identitet

Ovo je malo dublja stvar i vrlo je bitna u PHP-u.

```php
$user1 = new User();
$user1->name = 'Ana';

$user2 = $user1;
```

Sada ovo:

```php
$user2->name = 'Marija';
```

šta misliš da će biti:

```php
echo $user1->name;
```

Rezultat:

Marija

---

## Zašto?

Zato što kod PHP objekata:

```php
$user2 = $user1;
```

ne pravi automatski novu potpuno nezavisnu kopiju objekta.
Obe promenljive se odnose na isti objekat.
Mentalno:

```text
$user1 ──────┐
             ↓
          User object
          name = Marija
             ↑
$user2 ──────┘
```

Ovo je potpuno drugačije od običnih scalar vrednosti:

```php
$a = 5;
$b = $a;

$b = 10;

echo $a; // 5
```

Kod objekata obe promenljive mogu pokazivati na isti object identity.

---

## Ako želimo pravi drugi objekat

Možemo:

```php
$user2 = clone $user1;
```

Tada dobijamo drugu instancu:

```text
$user1 → User object A
$user2 → User object B
```

pa promena jednog ne menja automatski drugi.
clone ćemo kasnije detaljnije kada dođemo do magic metoda poput:

```php
__clone()
```

Za sada je dovoljno da zapamtiš:

```text
assignment object-a
→ još jedna promenljiva ka istom objektu
```

```text
clone
→ nova instanca
```

## Class vs object vs variable

Još jedna važna razlika:

```php
$user = new User();
```

Ovde imamo tri različite stvari:

```text
User
→ klasa
```

```text
new User()
→ kreiranje objekta
```

```text
$user
→ PHP promenljiva koja drži pristup/reference-like handle ka objektu
```

Nemoj mentalno izjednačiti:

```php
$user = objekat
```

sa:

promenljiva i objekat su ista stvar

Praktično pričamo „`$user` je User objekat“,
ali tehnički promenljiva je način na koji pristupamo toj instanci.

---

## Veza sa Laravelom

Kad napišeš:

```php
$user = User::find(5);
```

ako je user pronađen, Eloquent ti daje:

```text
User class
↓
konkretna User model instanca
↓
$user
```

I zato:

```php
$user->name
$user->email
$user->save()
```

ima smisla.
Tu već koristiš OOP svakodnevno:

```text
properties / attributes
methods
object state
object behavior
```

Samo Laravel dosta stvari sakrije iza ORM-a.

## Mini interview pitanje 1

---

## Šta će ovaj kod ispisati i zašto?

```php
class Booking
{
    public string $status = 'pending';

    public function confirm(): void
    {
        $this->status = 'confirmed';
    }
}

$a = new Booking();
$b = $a;

$b->confirm();

echo $a->status;
```

Ne zanima me samo rezultat — objasni mi šta se desilo između `$a` i `$b`.

---

## Ispisaće 'confirmed'

Zato sto nije isto kao kod varijabli,
nego b takodje nosi isti objekat kao `$a` i samim tim utiče na objekat

Tačno — 9.8/10.

Suština je:

```php
$a = new Booking();
$b = $a;
```

ne pravi drugi nezavisan Booking objekat.

Obe promenljive pristupaju istoj instanci, pa:

```php
$b->confirm();
```

menja stanje tog jednog objekta:

Booking object

```text
status = confirmed
↑             ↑
$a            $b
```

Zato:

```php
echo $a->status;
```

ispisuje:

confirmed
Mala terminološka nijansa: često kažemo da obe „pokazuju na isti objekat“.
To je bolji mentalni model nego da kažemo da `$b` „kopira ceo objekat“.

Ako bismo uradili:

```php
$b = clone $a;
```

onda bismo dobili dve različite instance.
