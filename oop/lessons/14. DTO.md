# 14. DTO

## Lekcija 14 — DTO

DTO = Data Transfer Object.

Najkraće:

DTO je objekat čija je glavna svrha da prenese strukturirane
podatke između slojeva aplikacije.

Recimo da iz request-a dobijemo:

```php
[
    'user_id' => 5,
    'room_id' => 12,
    'check_in' => '2026-11-10',
    'check_out' => '2026-11-13',
]
```

Možemo svuda da prosleđujemo array:

```php
$service->createBooking($data);
```

ali onda servis mora da zna:

```php
$data['user_id']
$data['room_id']
$data['check_in']
$data['check_out']
```

i lako napraviš typo:

```php
$data['checkin']
```

PHP ti tu ne pomaže mnogo.
Umesto toga:

```php
final class CreateBookingData
{
    public function __construct(
        public readonly int $userId,
        public readonly int $roomId,
        public readonly DateTimeImmutable $checkIn,
        public readonly DateTimeImmutable $checkOut,
    ) {}
}
```

pa:

```php
$data = new CreateBookingData(
    userId: 5,
    roomId: 12,
    checkIn: new DateTimeImmutable('2026-11-10'),
    checkOut: new DateTimeImmutable('2026-11-13'),
);
```

i onda:

```php
$service->createBooking($data);
```

Servis dobija strukturisan, tipizovan objekat.

## Zašto je DTO bolji od običnog array-a?

Jer:

```text
array
→ struktura nije eksplicitno garantovana
→ ključevi mogu biti pogrešni
→ tipovi nisu jasno definisani
→ IDE slabije pomaže
```

```text
DTO
→ poznata struktura
→ typed properties
→ autocomplete
→ lakši refactor
→ jasniji contract između slojeva
```

Na primer:

```php
public function createBooking(
    CreateBookingData $data
): Booking {
    // ...
}
```

odmah govori mnogo više nego:

```php
public function createBooking(array $data): Booking
```

Jer kod array ne znaš:

Koji array? Šta mora da sadrži?

Kod DTO-a znaš.
readonly
Za DTO često ima smisla:

```php
public readonly int $userId
```

jer DTO uglavnom predstavlja paket podataka koji se prenosi i ne treba usput proizvoljno menjati.
Dakle:

```php
$data->userId = 10; // ❌
```

nakon inicijalizacije nije dozvoljeno.
Još čistije u modernom PHP-u možeš:

```php
final readonly class CreateBookingData
{
    public function __construct(
        public int $userId,
        public int $roomId,
        public DateTimeImmutable $checkIn,
        public DateTimeImmutable $checkOut,
    ) {}
}
```

Sada su sve instance properties readonly.

## DTO nije isto što i Model

Ovo je bitno.

```text
DTO
→ prenosi podatke
```

```text
Model / Entity
→ predstavlja business objekat i često ima identitet/ponašanje
```

Na primer:

CreateBookingData

predstavlja:

Podatke potrebne da pokušamo da napravimo booking.

Dok:

Booking

može predstavljati već postojeći booking:

```text
id
user
room
status
total
createdAt
```

i imati behavior:

```php
$booking->cancel();
$booking->confirm();
```

DTO obično ne treba da postane mesto gde trpamo business logiku.

## Laravel paralela

Kod Laravel-a ti FormRequest često odradi:

```text
HTTP input
→ validation
```

A zatim možeš napraviti DTO:

```php
$data = new CreateBookingData(
    userId: auth()->id(),
    roomId: $request->integer('room_id'),
    checkIn: new DateTimeImmutable($request->input('check_in')),
    checkOut: new DateTimeImmutable($request->input('check_out')),
);
```

pa Service više ne mora da zna ništa o HTTP request-u.
To je važna granica:

```text
Controller
→ zna HTTP
```

```text
DTO
→ prenosi podatke
```

```text
Service
→ zna use-case
```

## Šta konkretno dobijamo sa DTO-om u pogledu strukture, tipova i coupling-a sa HTTP request-om?

---

Sa DTO dobijamo strukturisane, gotove podatke, typed properties, autocomplete, lakŝi refactor...
Kod array, tipovi nisu jasno definisani, kljucevi mogu biti pogresni, struktura nije garantovana.

Tako da u prvom primeru, vec imamo sprwman objekat za kreiranje booking-a.

---

Tačno — 10/10.
Posebno dobro ovo:

„već imamo spreman objekat za kreiranje booking-a“

Samo jedna fina nijansa: DTO sam po sebi ne znači automatski da su podaci validirani.
Najčistiji tok je:

```text
HTTP Request
→ validation
→ mapping u DTO
→ Service
```

Tada servis zaista dobija već očišćen i tipizovan input, bez zavisnosti od `$_POST`,
Laravel Request objekta ili konkretnih HTTP detalja.
