# 28. Self VS Static

## Lekcija 28 — self vs static i Late Static Binding

Ovo je malo naprednija PHP OOP tema i vrlo dobra interview stvar.

Već znamo:

self::

ali postoji i:

static::

I nisu uvek isto.
Pogledaj:

```php
class User
{
    public static function type(): string
    {
        return 'user';
    }

    public static function describe(): string
    {
        return self::type();
    }
}

class Admin extends User
{
    public static function type(): string
    {
        return 'admin';
    }
}
```

Ako uradimo:

```php
echo Admin::describe();
```

šta će se desiti?
`describe()` je nasleđen od User.
Unutar njega imamo:

```php
self::type();
```

self znači:

klasa u kojoj je ova metoda definisana

A `describe()` je definisan u:

User

Zato rezultat bude:

user

Čak iako smo pozvali:

```php
Admin::describe()
```

A sada static::

Promenimo samo:

```php
public static function describe(): string
{
    return static::type();
}
```

I ponovo:

```php
echo Admin::describe();
```

Sada dobijamo:

admin

---

## Zašto?

static:: uzima u obzir klasu preko koje je poziv napravljen.
To se zove:

Late Static Binding
Mentalno:

self::

```text
→ veži se za klasu gde je kod DEFINISAN
```

static::

```text
→ uzmi u obzir klasu preko koje je poziv IZVRŠEN
```

Dakle:

```php
Admin::describe();
```

sa:

```php
static::type();
```

kaže otprilike:

Poziv je došao kroz Admin, pa pogledaj `Admin::type()`.

---

## Zašto ovo postoji?

Zbog inheritance-a.
Recimo:

```php
class Model
{
    public static function create(): static
    {
        return new static();
    }
}
```

pa:

```php
class User extends Model {}
class Booking extends Model {}
```

Sada:

```php
$user = User::create();
$booking = Booking::create();
```

new `static()` omogućava:

```text
User::create()
→ novi User
```

```text
Booking::create()
→ novi Booking
```

Da smo napisali:

```php
return new self();
```

vezali bismo se za klasu gde je metoda definisana.
static kao return type
Moderni PHP omogućava:

```php
public static function create(): static
```

što znači:

vraćam instancu konkretne klase kroz koju je poziv izvršen.

To je veoma zgodno za fluent API-je, factories i inheritance hijerarhije.
I verovatno ti već zvuči poznato iz framework sveta.
parent::

Sad možemo lepo razlikovati sva tri:

self::

```text
→ trenutna klasa u kojoj je kod definisan
```

parent::

```text
→ direktni parent
```

static::

```text
→ late-static-bound klasa, tj. konkretna klasa poziva
```

Primer:

```php
class User
{
    public static function role(): string
    {
        return 'user';
    }
}

class Admin extends User
{
    public static function role(): string
    {
        return parent::role() . '-admin';
    }
}
```

Ovde parent:: eksplicitno kaže:

pozovi parent implementaciju.

Nemoj mešati `$this` i static::

```php
$this
```

radi sa konkretnom instancom:

```php
$user->name
```

Dok:

static::

i dalje pripada static/class kontekstu, samo podržava polymorphic inheritance ponašanje.
Mentalno:

```text
$this
→ koji OBJEKAT?
```

self::

```text
→ u kojoj KLASI je kod definisan?
```

static::

```text
→ kroz koju KLASU je poziv došao?
```

## Šta će ovo ispisati i zašto?

```php
class User
{
    public static function role(): string
    {
        return 'user';
    }

    public static function first(): string
    {
        return self::role();
    }

    public static function second(): string
    {
        return static::role();
    }
}

class Admin extends User
{
    public static function role(): string
    {
        return 'admin';
    }
}

echo Admin::first();
echo Admin::second();
```

Objasni mi posebno zašto self:: i static:: ovde daju različit rezultat.

---

`first()` će dati 'user'
zato što self:: određuje da se poziv
izvrsi samo unutar klase kojoj pripada.

`second()` daje 'admin' jer
static:: kaže PHP-u da obrati pažnju,
kroz koju klasu je pozvana metoda,
tj kroz koju klasu je poziv izvršen.

---

Tačno — 10/10.
Samo bih self:: formulisao još preciznije:

self::

```text
→ vezuje se za klasu u kojoj je metoda DEFINISANA
```

static::

```text
→ uzima u obzir klasu kroz koju je poziv IZVRŠEN
```

Zato:

```php
Admin::first();
```

ulazi u metodu definisanu u User, a:

```php
self::role();
```

ostaje vezan za User → user.
Dok:

```php
static::role();
```

koristi Late Static Binding i vidi da je poziv došao kroz Admin → admin.
