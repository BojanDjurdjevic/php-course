# 5. Static VS Instance

## Lekcija 5 — static vs instance članovi

Ovo je jedan od najvažnijih OOP koncepata jer se često koristi pogrešno.

Do sada smo imali instance properties:

```php
class Booking
{
    public string $status = 'pending';
}
```

Svaki objekat ima svoje stanje:

```php
$a = new Booking();
$b = new Booking();

$a->status = 'confirmed';

echo $b->status; // pending
```

Dakle:

```text
instance property
→ pripada konkretnom objektu
```

Ali možemo imati i static:

```php
class Booking
{
    public static int $count = 0;
}
```

Tome ne pristupamo preko konkretnog objekta:

Booking::`$count`;

nego preko klase.
Mentalno:

```text
instance member
→ pripada objektu
```

```text
static member
→ pripada klasi
```

Na primer:

```php
class Booking
{
    public static int $count = 0;

    public function __construct()
    {
        self::$count++;
    }
}
```

Pa:

```php
new Booking();
new Booking();
new Booking();

echo Booking::$count; // 3
```

Ovde sva tri objekta dele isti static property.
self::

Unutar klase:

self::`$count`

znači:

static član ove klase.

Slično:

```php
self::someMethod();
```

za static metodu.
Dok:

```php
$this->status
```

znači:

član konkretne instance.

Dakle:

```text
$this
→ object context
```

self::

```text
→ class/static context
```

---

## Static method

Možemo imati:

```php
class PriceCalculator
{
    public static function addTax(float $price): float
    {
        return $price * 1.2;
    }
}
```

Poziv:

```php
$total = PriceCalculator::addTax(100);
```

Ne pravimo:

```php
new PriceCalculator();
```

jer metoda ne koristi nikakvo stanje objekta.
Ali ovde dolazi važna arhitektonska nijansa:

Samo zato što metoda može biti static, ne znači da treba sve pretvarati u static.

Ako klasa ima dependencies:

```php
class BookingService
{
    public function __construct(
        private BookingRepository $repository,
    ) {}
}
```

onda instance pristup ima mnogo više smisla nego:

```php
BookingService::create();
```

jer objekat može nositi svoje dependencies i lepo raditi sa dependency injection-om.

---

## Kada static ima smisla?

Dobar kandidat:

```php
final class MathHelper
{
    public static function percentage(
        float $amount,
        float $percent
    ): float {
        return $amount * $percent / 100;
    }
}
```

Jer:

```text
nema object state
nema dependency
čista operacija
```

Ali čak i tu se često može koristiti obična funkcija.
Static češće ima smisla za:

```text
factory metode
utility metode
shared class state
named constructors
```

Na primer:

```php
class BookingStatus
{
    public static function confirmed(): string
    {
        return 'confirmed';
    }
}
```

Iako ćemo kasnije videti da je za ovakav slučaj enum često bolji alat.

## Laravel veza

Ti već stalno vidiš:

```php
User::find(5);
Booking::query();
Cache::get('key');
DB::transaction(...);
```

Ali ovde postoji važna stvar: u Laravelu stvari poput:

DB::

Cache::

Auth::

često izgledaju kao običan static poziv,
ali Laravel Facades ispod haube nisu isto što i
jednostavna statička klasa sa čistim static metodama.

To ćemo kasnije povezati sa Service Container-om.
Za sada:

```text
pravi static
→ pripada klasi
```

```text
Laravel Facade syntax
→ izgleda static
→ ali iza toga često stoji objekat iz containera
```

To je veoma bitna razlika.

## Mini interview pitanje 5

Koja je razlika između:

```php
$this->status
```

i:

self::`$count`

i zašto bi BookingService sa BookingRepository
dependency-jem uglavnom bio bolji kao običan
objekat preko dependency injection-a nego kao potpuno static servis?

---

```text
$this->status je instance property dok je
self::$count static member klase
```

Klase jako lepo nose i rade sa DI tako da je to često bolje rešenje od static

---

Tačno — 9.8/10.
Suština:

```text
$this->status
→ property konkretne instance
→ svaki objekat može imati svoju vrednost
```

```text
self::$count
→ static property klase
→ deli se na nivou klase
```

A za BookingService si pogodio najvažniju stvar:

običan objekat lepo nosi dependency-je kroz constructor:

```php
class BookingService
{
    public function __construct(
        private BookingRepository $repository
    ) {}
}
```

To znači:

```text
lakši DI
lakše testiranje
lakše menjanje implementacije
jasnije dependencies
```

Dok static servis često sakrije zavisnosti i oteža testiranje.
