# 10. Traits

## Lekcija 10 — Traits

Trait rešava drugačiji problem od inheritance-a i interface-a.

Najkraće:

```text
interface
→ contract
```

```text
inheritance
→ IS-A odnos
```

```text
trait
→ reuse konkretne implementacije
```

Recimo više potpuno različitih klasa treba da ima logovanje:

```php
class BookingService
{
    public function log(string $message): void
    {
        echo $message;
    }
}

class UserService
{
    public function log(string $message): void
    {
        echo $message;
    }
}
```

Ne želimo copy/paste.
Ali ovo nema smisla:

```php
class UserService extends BookingService
```

jer:

UserService IS-A BookingService ❌

Tu trait može biti koristan:

```php
trait LogsActivity
{
    public function log(string $message): void
    {
        echo $message;
    }
}
```

pa:

```php
class BookingService
{
    use LogsActivity;
}

class UserService
{
    use LogsActivity;
}
```

Sada obe klase dobijaju:

```php
$this->log('Something happened');
```

bez inheritance odnosa.

---

## Šta trait zapravo radi?

Mentalno možeš da ga zamišljaš kao:

Ubaci ove methods/properties u klasu koja kaže use TraitName.

Dakle:

```php
trait HasTimestamps
{
    public function touch(): void
    {
        // ...
    }
}

class Booking
{
    use HasTimestamps;
}
```

konceptualno znači da Booking sada ima ponašanje definisano u trait-u.
Ali trait nije objekat.
Ne možeš:

```php
new LogsActivity(); // ❌
```

I trait nije parent class niti interface.

---

## Trait može imati properties

Na primer:

```php
trait HasUuid
{
    private string $uuid;

    public function uuid(): string
    {
        return $this->uuid;
    }
}
```

Klasa koja koristi trait dobija i property i method.
Ipak, tu treba biti oprezan: što trait ima više state-a i hidden dependencies, to može biti teži za razumevanje.

---

## Više trait-ova

Klasa može:

```php
class Booking
{
    use HasUuid;
    use LogsActivity;
    use HasTimestamps;
}
```

Dakle PHP nema multiple class inheritance:

extends samo jednu klasu

ali možeš koristiti više trait-ova.
Nemoj ipak mentalno reći:

Traits su multiple inheritance.

Slični su po code reuse efektu, ali nisu isto što i prava inheritance hijerarhija.

---

## Method conflict

Recimo:

```php
trait A
{
    public function log(): void
    {
        echo 'A';
    }
}

trait B
{
    public function log(): void
    {
        echo 'B';
    }
}
```

Ako:

```php
class Service
{
    use A, B;
}
```

PHP ne zna koji `log()` želiš.
Možemo eksplicitno rešiti:

```php
class Service
{
    use A, B {
        A::log insteadof B;
    }
}
```

Možemo čak napraviti alias:

```php
class Service
{
    use A, B {
        A::log insteadof B;
        B::log as logFromB;
    }
}
```

Sad imamo:

```php
$service->log();      // A
$service->logFromB(); // B
```

Ovo nećemo često koristiti, ali vredi znati da postoji.

## Kada trait ima smisla?

Najbolje kada više nepovezanih klasa dele malo, jasno, reusable ponašanje.
Na primer:

```text
HasUuid
LogsActivity
SoftDeletes
HasFactory
Notifiable
```

---

## I poslednja tri ti sigurno zvuče poznato iz Laravel-a. 🙂

Na primer:

```php
class User extends Authenticatable
{
    use Notifiable;
}
```

ili Eloquent model:

use HasFactory, SoftDeletes;

To su baš PHP trait-ovi.
Laravel ih vrlo intenzivno koristi.

---

## Kada trait može biti smell?

Ako napraviš:

```php
trait DoesEverything
{
    // 900 linija
    // DB queries
    // HTTP
    // email
    // validation
    // business logic
}
```

onda trait samo skriva lošu arhitekturu.
Trait treba da bude:

```text
fokusiran
jasne odgovornosti
relativno mali
```

I često je composition još bolji izbor kada ponašanje zavisi od pravih dependency-ja.
To ćemo sledeće detaljno raditi.

---

## Interface vs Trait

Ovo jako dobro zapamti:

```text
interface
→ kaže ŠTA moraš imati
```

```text
trait
→ daje ti KAKO je nešto implementirano
```

Na primer:

```php
interface Loggable
{
    public function log(string $message): void;
}
```

samo zahteva metodu.
Dok:

```php
trait LogsActivity
{
    public function log(string $message): void
    {
        echo $message;
    }
}
```

daje konkretnu implementaciju.
Možeš čak koristiti oba:

```php
class BookingService implements Loggable
{
    use LogsActivity;
}
```

Trait ti obezbedi implementaciju koju interface zahteva.

## Mini interview pitanje 10

Koja je razlika između:

```text
interface
trait
inheritance
```

i zašto bi trait imao više smisla ako BookingService i UserService dele `log()` ponašanje, nego da napišemo:

```php
class UserService extends BookingService
```

samo da bismo ponovo koristili isti kod?

---

interface - kao neki contract koji klasa treba da ispuni. Metoda koju treba da implementira, na koji god nacin. Klasa moze implementirati vise interfaces.

trait - reuse konkretne metode. Suprotno od interface, bas govori kako metoda mora biti implementirana.

inheritance - nasledjivanje. Child klasa nasledjuje sve od parent. Klasa moze naslediti samo jednu klasu, ne vise njih.

Booking i User Servisi nisu IS-A i besmisleno je da jedna drugu nasledi, te je za deljene metode upravo Trait najbolje rešenje

---

Tačno — 9.7/10.
Jedina sitna korekcija: trait ne kaže baš da metoda „mora biti implementirana tako“. Preciznije:

```text
interface
→ zahteva da određeno ponašanje postoji
```

```text
trait
→ daje gotovu implementaciju za reuse
```

Klasa može čak da pregazi trait metodu svojom sopstvenom implementacijom ako to želi.
Ostalo ti je potpuno pogođeno, posebno ovo:

```text
BookingService nije UserService
UserService nije BookingService
```

pa bi inheritance samo zbog deljenog `log()` koda bio pogrešan odnos.
