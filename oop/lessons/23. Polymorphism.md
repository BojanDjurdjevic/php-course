# 23. Polymorphism

## Lekcija 23 — Polymorphism

Mi smo polymorphism zapravo već koristili nekoliko puta, samo ga još nismo imenovali.

Najkraće:

Polymorphism znači da isti contract možemo
koristiti sa različitim konkretnim objektima, a svaki izvršava svoje ponašanje.

Imamo:

```php
interface PaymentGateway
{
    public function charge(int $amount): void;
}
```

Implementacija 1:

```php
final class StripeGateway implements PaymentGateway
{
    public function charge(int $amount): void
    {
        echo "Charging {$amount} through Stripe";
    }
}
```

Implementacija 2:

```php
final class PayPalGateway implements PaymentGateway
{
    public function charge(int $amount): void
    {
        echo "Charging {$amount} through PayPal";
    }
}
```

A Service:

```php
final class BookingService
{
    public function __construct(
        private PaymentGateway $payment
    ) {}

    public function pay(int $amount): void
    {
        $this->payment->charge($amount);
    }
}
```

Service poziva u oba slučaja potpuno isto:

```php
$this->payment->charge($amount);
```

Ali stvarno ponašanje zavisi od objekta koji smo mu dali.
Sa:

```php
$service = new BookingService(
    new StripeGateway()
);
```

pozvaće se:

```php
StripeGateway::charge()
```

A sa:

```php
$service = new BookingService(
    new PayPalGateway()
);
```

pozvaće se:

```php
PayPalGateway::charge()
```

BookingService ne mora da radi:

```php
if ($gateway === 'stripe') {
    // ...
}

if ($gateway === 'paypal') {
    // ...
}
```

To je velika vrednost polymorphism-a.

---

## Jedan tip, više oblika

Otud i naziv:

```text
poly
→ mnogo
```

```text
morph
→ oblika
```

Za Service oba objekta su:

PaymentGateway

ali konkretno mogu biti:

```text
StripeGateway
PayPalGateway
AdyenGateway
FakePaymentGateway
```

Dakle:

```text
jedan contract
↓
više konkretnih ponašanja
```

## Polymorphism nije samo interface

Može se pojaviti i kroz inheritance.
Na primer:

```php
abstract class Notification
{
    abstract public function send(): void;
}
```

pa:

```php
class EmailNotification extends Notification
{
    public function send(): void
    {
        echo 'Email';
    }
}

class SmsNotification extends Notification
{
    public function send(): void
    {
        echo 'SMS';
    }
}
```

Možemo:

```php
function notify(Notification $notification): void
{
    $notification->send();
}
```

i pozvati:

```php
notify(new EmailNotification());
notify(new SmsNotification());
```

Ista funkcija:

```php
notify(...)
```

isti poziv:

```php
$notification->send();
```

ali različita konkretna implementacija.
To je polymorphism.

---

## Zašto je važan?

Jer nam omogućava da ovo:

```php
if ($type === 'email') {
    ...
} elseif ($type === 'sms') {
    ...
} elseif ($type === 'slack') {
    ...
}
```

često zamenimo objektima koji sami znaju svoje ponašanje.
Time se lepo povezuje sa:

```text
Interface
→ contract
```

```text
Polymorphism
→ različite implementacije tog contract-a
```

```text
DI
→ ubacujemo željenu implementaciju
```

```text
OCP
→ dodajemo novu implementaciju bez menjanja consumer-a
```

```text
LSP
→ svaka implementacija mora stvarno biti validna zamena
```

Sad vidiš da SOLID, DI i interfaces nisu odvojene lekcije — svi rade zajedno.

## Mini interview pitanje 23

Imamo:

```php
interface NotificationChannel
{
    public function send(string $message): void;
}
```

i klase:

```text
EmailChannel
SmsChannel
SlackChannel
```

koje ga implementiraju.
Zašto je mogućnost da napišemo:

```php
function notify(
    NotificationChannel $channel,
    string $message
): void {
    $channel->send($message);
}
```

primer polymorphism-a?

---

## Šta ta funkcija zna, a šta ne mora da zna o konkretnom objektu koji dobije?

---

Funkcija samo zna kakav joj objekat treba,
ali ona ne mora da zna kako ce da uradi ono sto se od njega ocekuje.

Polymorphisam je zato sto vise klasa mogu
implementirati ovaj jedan interfejs i samim tim,
svaka od tih klasa je dobar kandidat za ovu funkciju

---

Tačno — 10/10.
Odlično si ga objasnio. Funkcija zna samo contract:

NotificationChannel

i zna da bezbedno može da pozove:

```php
$channel->send($message);
```

Ne mora da zna da li je unutra:

```text
EmailChannel
SmsChannel
SlackChannel
```

niti kako svaki od njih šalje poruku.
To je polymorphism:

```text
isti contract
+ isti poziv metode
+ različito konkretno ponašanje
```

I vrlo lepo si ga povezao sa LSP-om: svaka od tih implementacija
treba da bude validan kandidat gde god se očekuje NotificationChannel.
