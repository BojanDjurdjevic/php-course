# 2. Properties, methods, construct

## Lekcija 2 — Properties, methods i constructor

Sada prelazimo sa:

šta je objekat?

na:

kako objekat dobija svoje početno stanje?

Recimo ovo:

```php
class User
{
    public int $id;
    public string $name;
    public string $email;
}
```

pa:

```php
$user = new User();

$user->id = 5;
$user->name = 'Bojan';
$user->email = 'bojan@test.com';
```

radi, ali ima problem: možemo napraviti
User objekat koji još nije validno inicijalizovan.

Na primer:

```php
$user = new User();

echo $user->name;
```

name još nema vrednost.
Zato postoji constructor.

```php
class User
{
    public function __construct(
        public int $id,
        public string $name,
        public string $email,
    ) {
    }
}
```

Sada:

```php
$user = new User(
    5,
    'Bojan',
    'bojan@test.com'
);
```

Constructor se izvršava u trenutku new.
Mentalno:

```text
new User(...)
↓
alokacija nove instance
↓
__construct(...)
↓
postavi početno stanje
↓
dobijamo spreman User objekat
```

U PHP-u ova sintaksa:

```php
public function __construct(
    public int $id,
    public string $name,
)
```

zove se constructor property promotion.
To je skraćeno od:

```php
class User
{
    public int $id;
    public string $name;

    public function __construct(
        int $id,
        string $name,
    ) {
        $this->id = $id;
        $this->name = $name;
    }
}
```

Oba pristupa predstavljaju istu osnovnu ideju.

---

## Zašto je constructor važan?

Zato što može da garantuje:

ovaj objekat ne može ni da nastane bez podataka koji su mu potrebni.

Na primer:

```php
class Booking
{
    public function __construct(
        public int $userId,
        public int $roomId,
        public DateTimeImmutable $checkIn,
        public DateTimeImmutable $checkOut,
    ) {
    }
}
```

Sada ne možemo:

```php
$booking = new Booking();
```

jer constructor zahteva podatke.
To je dobro ako objekat bez njih nema smisla.

## Method koristi stanje objekta

Recimo:

```php
class Booking
{
    public function __construct(
        public DateTimeImmutable $checkIn,
        public DateTimeImmutable $checkOut,
    ) {
    }

    public function numberOfNights(): int
    {
        return $this->checkIn
            ->diff($this->checkOut)
            ->days;
    }
}
```

Pa:

```php
$booking = new Booking(
    new DateTimeImmutable('2026-11-10'),
    new DateTimeImmutable('2026-11-13'),
);

echo $booking->numberOfNights(); // 3
```

Ovde metoda ne traži:

```php
numberOfNights($checkIn, $checkOut)
```

jer objekat već zna svoje stanje.
Zato metoda koristi:

```php
$this->checkIn
$this->checkOut
```

Mentalno:

```text
Booking object
├── checkIn
├── checkOut
└── numberOfNights()
      ↓
   koristi stanje ovog booking-a
```

I tu OOP počinje da dobija smisao: ne prosleđujemo stalno
istih pet podataka između funkcija ako oni već pripadaju tom objektu.

---

## Constructor nije obična metoda koju mi pozivamo kasnije

Ovo:

```php
new User(...)
```

automatski izaziva:

```php
__construct(...)
```

Ne radimo tipično:

```php
$user->__construct(...);
```

naknadno.
Constructor služi za inicijalizaciju nove instance.

---

## Veza sa Laravelom

Ovo već koristiš kod dependency injection-a:

```php
class BookingService
{
    public function __construct(
        private BookingRepository $bookings,
        private InventoryRepository $inventory,
    ) {
    }
}
```

Tu constructor ne prima business podatke booking-a,
nego zavisnosti koje su objektu potrebne da radi svoj posao.

Mentalno:

```text
Booking entity constructor
→ početno stanje objekta
```

```text
BookingService constructor
→ dependency injection
```

Ista PHP mogućnost, različita arhitektonska svrha.

## Mini interview pitanje 2

Koja je razlika između ova dva pristupa:

```php
$user = new User();
$user->name = 'Bojan';
$user->email = 'bojan@test.com';
```

i:

```php
$user = new User(
    name: 'Bojan',
    email: 'bojan@test.com'
);
```

gde User ima odgovarajući `__construct()`?

Zašto constructor može biti bolji način da
garantujemo da objekat od trenutka nastanka ima validno početno stanje?

---

U drugom primeru User ima odgovarajuci konstruktor.

To je bolji nacin da garantujemo da ce objekat vec biti inicijalizovan
jer prilikom new on zahteva neophodne podatke kako bi se izbeglo da
se napravi neinicijalizovan objekat pa onda `$user->name` na primer nece raditi.

---

Tačno — 10/10.
Upravo je to glavna vrednost konstruktora:

```text
new User(...)
→ ne dozvoljava da objekat nastane bez potrebnog početnog stanja
```

Dok prvi pristup:

```php
$user = new User();
$user->name = 'Bojan';
$user->email = 'bojan@test.com';
```

ostavlja period u kom objekat postoji, ali još nije kompletno inicijalizovan.
Kod typed property-ja to može dovesti
i do greške ako pokušaš da čitaš property pre nego što je dobio vrednost.

Drugi pristup:

```php
$user = new User(
    name: 'Bojan',
    email: 'bojan@test.com'
);
```

forsira pravilo:

Ako objekat postoji, onda već ima minimum podataka koji su mu potrebni.
