# 12.Mime validation - finfo

## Lekcija 12 — MIME validation sa finfo

Sada dolazimo do jednog od najvažnijih delova upload security-ja.
Pretpostavimo:

```php
$file = $_FILES['photo'];
```

Imamo:

```php
$file['name']
$file['type']
$file['tmp_name']
```

Od ova tri, za određivanje stvarnog tipa fajla ne želimo da verujemo:

```php
$file['name']
$file['type']
```

jer dolaze sa client strane.
Umesto toga:

```php
$finfo = new finfo(FILEINFO_MIME_TYPE);

$mime = $finfo->file($file['tmp_name']);
```

Na primer možemo dobiti:

```text
image/jpeg
image/png
image/webp
application/pdf
```

Ako finfo->`file()` ne uspe, može vratiti:

false

zato:

```php
$mime = $finfo->file($file['tmp_name']);

if ($mime === false) {
    $errors['photo'] = 'Could not detect file type.';
}
```

---

## Allowlist, ne blocklist

Lošiji pristup:

```php
if ($mime !== 'application/x-php') {
    // allow
}
```

To je blocklist mentalni model:

zabrani ono čega sam se setio.

Mnogo bolji:

```php
$allowedMimes = [
    'image/jpeg',
    'image/png',
    'image/webp',
];

if (!in_array($mime, $allowedMimes, true)) {
    $errors['photo'] = 'Unsupported image type.';
}
```

To je allowlist:

dozvoli samo ono što eksplicitno očekujem.

I opet:

```php
in_array(..., true)
```

strict comparison.

---

## MIME određuje ekstenziju

Ako smo već utvrdili:

```php
$mime === 'image/jpeg'
```

mnogo je bolje da server odluči ekstenziju:

```php
$extensions = [
    'image/jpeg' => 'jpg',
    'image/png' => 'png',
    'image/webp' => 'webp',
];

$extension = $extensions[$mime];
```

nego:

```php
$extension = pathinfo(
    $file['name'],
    PATHINFO_EXTENSION
);
```

Jer originalni filename može biti:

```text
hotel.exe.jpg
photo.php
whatever.fakeextension
```

A storage filename želimo da bude potpuno pod našom kontrolom:

```php
$filename =
    bin2hex(random_bytes(16))
```

```text
    . '.'
    . $extension;
```

## MIME nije isto što i potpuna image validation

Ovo je važna nijansa.
Ako:

```php
$finfo->file($tmp) === 'image/jpeg'
```

to je mnogo bolje od client-provided MIME-a.
Ali za aplikaciju koja zaista očekuje sliku, možemo ići korak dalje i pokušati da je zaista interpretiramo kao image.
Na primer:

```php
$imageInfo = getimagesize($file['tmp_name']);
```

Ako nije validna slika:

```php
$imageInfo === false
```

Za validnu sliku možeš dobiti podatke kao:

```php
[
    0 => 1920,
    1 => 1080,
    2 => IMAGETYPE_JPEG,
    'mime' => 'image/jpeg',
]
```

Dakle:

```php
$width = $imageInfo[0];
$height = $imageInfo[1];
```

To nam omogućava i dimensional validation:

```php
if ($width > 6000 || $height > 6000) {
    $errors['photo'] = 'Image dimensions are too large.';
}
```

---

## Zašto proveravati dimensions?

Zamisli fajl:

4 MB JPEG

ali rezolucija:

12000 × 10000

Disk size je relativno mali zbog kompresije.
Ali kada ga GD ili druga image biblioteka dekodira u memoriju, može zauzeti ogroman RAM.
Zato za image pipeline često proveravamo oba:

```text
file size
+
pixel dimensions
```

Redosled za sliku sada izgleda ovako
`$_FILES` entry postoji?

```text
↓
UPLOAD_ERR_OK?
↓
file size?
↓
finfo MIME?
↓
MIME allowlist?
↓
getimagesize() uspeva?
↓
dimensions?
↓
business rules?
↓
generate filename
↓
destination directory
↓
move / process image
```

Još jedna bitna nijansa
`getimagesize()` nije generalna MIME validation funkcija za sve fajlove.
Odlična je kada je business contract:

očekujem sliku.

Za PDF, ZIP, CSV itd. nema smisla.
Tu ostajemo na drugim odgovarajućim validatorima.

## Pitanje

Pretpostavimo da user uploaduje fajl nazvan:

holiday.jpg

a:

```php
$file['type'] === 'image/jpeg'
```

ali:

```php
$finfo->file($file['tmp_name'])
```

vrati:

application/pdf

---

## Šta radiš?

I drugo: zašto bi kod image upload-a, čak i nakon validnog image/jpeg MIME-a, ipak mogao da koristiš:

```php
getimagesize()
```

pre nego što sliku pošalješ u GD ili Intervention Image?

---

Drugi deo si objasnio odlično: upravo zato `getimagesize()` ima smisla pre GD/Intervention obrade. Disk veličina i decoded image memory nisu ista stvar.
Samo jedna važna korekcija za prvi scenario.
Ako:

```php
$finfo->file($file['tmp_name'])
```

vrati:

application/pdf

a business contract kaže da prihvatamo samo:

```text
image/jpeg
image/png
image/webp
```

onda bih fajl odmah odbio.
Dakle:

```php
$allowed = [
    'image/jpeg',
    'image/png',
    'image/webp',
];

if (!in_array($mime, $allowed, true)) {
    $errors['photo'] = 'Unsupported image type.';
}
```

Ne moramo ni stići do:

```php
getimagesize(...)
```

jer već znamo da MIME ne odgovara contract-u.
`getimagesize()` dolazi kao dodatna provera nakon što MIME već prođe allowlist.
Mentalno:

```text
finfo MIME
↓
nije dozvoljen?
→ reject
```

dozvoljen?

```text
↓
getimagesize()
↓
nije prava / čitljiva slika?
→ reject
```

jeste?

```text
↓
proveri width / height
```

A ovo što si rekao za:

```text
$imageInfo[0] // width
$imageInfo[1] // height
```

je tačno.
