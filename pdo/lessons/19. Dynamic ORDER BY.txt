Lekcija 19 — Dinamički ORDER BY: zašto placeholder nije rešenje
Ovo se direktno nadovezuje na prethodnu lekciju.
Recimo korisnik na stranici hotela može da bira:
sort = price
sort = name
sort = newest

Možda bismo pokušali:
$stmt = $pdo->prepare(
    'SELECT *
     FROM hotels
     ORDER BY :column'
);

$stmt->execute([
    'column' => $sort,
]);

Ali imamo problem koji već znaš:
Placeholder predstavlja vrednost, a naziv kolone je deo SQL strukture.

Dakle:
:city
:min_price
:status
:id

mogu biti vrednosti.
Ali:
table name
column name
ASC / DESC
SQL keyword

nisu obične values.
Pa kako onda bezbedno pravimo dinamički ORDER BY?
Koristimo whitelist.
Na primer korisnik pošalje:
$sort = $_GET['sort'] ?? 'name';

Mi definišemo šta aplikacija uopšte dozvoljava:
$allowedSorts = [
    'name'   => 'name',
    'price'  => 'base_price',
    'newest' => 'created_at',
];

Pa:
$sortColumn = $allowedSorts[$sort] ?? 'name';

Sada je $sortColumn siguran zato što ne dolazi direktno od korisnika.
Dolazi samo iz naše kontrolisane liste:
name
base_price
created_at

i možemo:
$sql = "
    SELECT *
    FROM hotels
    ORDER BY $sortColumn
";

Na prvi pogled može izgledati čudno:
„Ali sada opet interpoliramo promenljivu u SQL!“

Da — ali ključna razlika je poreklo te promenljive.
Loše:
ORDER BY {$_GET['sort']}

User praktično kontroliše SQL strukturu.
Dobro:
$allowedSorts = [
    'price' => 'base_price',
    'name' => 'name',
];

$sortColumn = $allowedSorts[$_GET['sort'] ?? ''] ?? 'name';

User bira samo ključ naše liste.
Mi odlučujemo koji SQL fragment taj ključ predstavlja.
Mentalno:
USER:
"price"
   ↓
WHITELIST:
price → base_price
name  → name
   ↓
APPLICATION:
ORDER BY base_price

Ne radimo:
user input
↓
direktno u SQL strukturu

Isti princip važi za ASC / DESC.
Ne radiš:
$direction = $_GET['direction'];

$sql = "ORDER BY base_price $direction";

nego:
$direction = strtoupper(
    $_GET['direction'] ?? 'ASC'
);

$direction = in_array(
    $direction,
    ['ASC', 'DESC'],
    true
)
    ? $direction
    : 'ASC';

pa tek:
$sql = "
    SELECT *
    FROM hotels
    ORDER BY base_price $direction
";

Još bolje možeš mapirati kompletan izbor:
$sortOptions = [
    'price_low'  => 'base_price ASC',
    'price_high' => 'base_price DESC',
    'newest'     => 'created_at DESC',
    'name'       => 'name ASC',
];

pa:
$orderBy = $sortOptions[$sort] ?? 'name ASC';

Ovo je vrlo čist pristup jer korisnik nikada ne šalje pravi SQL fragment.
On šalje:
price_low

a aplikacija ga prevodi u:
base_price ASC

Bitna mentalna podela
Dynamic VALUE
→ placeholder
→ prepare + execute

Dynamic SQL STRUCTURE
→ whitelist / mapping
→ nikada slepo user input

To je jedna od najvažnijih praktičnih sigurnosnih lekcija PDO-a.
Mini interview pitanje 20
Zašto ovo nije pravi pristup:
$stmt = $pdo->prepare(
    'SELECT * FROM hotels ORDER BY :sort'
);

$stmt->execute([
    'sort' => $_GET['sort'],
]);

i kako bi bezbedno dozvolio korisniku da bira između sortiranja po:
name
price
created_at

?

---

Nije dobar pristup iz dva razloga:

1. Placeholders se vezuju samo za vrednosti a ne za strukturu sql-a
2. Nikako ne lepimo u upit korisnički unos.

Kako bezbedno?

Napraviti allowedList i onda kada korisnik pošalje šta želi,&#x20;

ukoliko se to poklapa sa allowedList stavljamo u upit a ako ne

stavimo default vrednost tipa name.

---

Tačno — 10/10.
Posebno mi se sviđa što si naveo oba razloga, jer su odvojeni problemi:
ORDER BY :sort
→ placeholder nije namenjen SQL identifier-u

ORDER BY {user input}
→ SQL injection rizik

Pravi mentalni model je:
dinamička vrednost
→ placeholder

dinamička SQL struktura
→ whitelist / mapping

Na primer:
$allowedSorts = [
    'name'       => 'name',
    'price'      => 'base_price',
    'created_at' => 'created_at',
];

$sort = $_GET['sort'] ?? 'name';

$column = $allowedSorts[$sort] ?? 'name';

$sql = "SELECT * FROM hotels ORDER BY $column";

Ovde korisnik nikada ne određuje SQL direktno — samo bira jednu od opcija koje smo mi unapred dozvolili.
