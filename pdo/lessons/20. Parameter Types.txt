Lekcija 20 — PDO parameter types
Do sada smo često radili:
$stmt->execute([
    'id' => $id,
]);

Ali PDO poznaje i eksplicitne tipove parametara:
PDO::PARAM_INT
PDO::PARAM_STR
PDO::PARAM_BOOL
PDO::PARAM_NULL

Na primer:
$stmt = $pdo->prepare(
    'SELECT *
     FROM users
     WHERE id = :id'
);

$stmt->bindValue(
    ':id',
    $id,
    PDO::PARAM_INT
);

$stmt->execute();

Ovde eksplicitno kažemo PDO-u:
:id
→ integer

Umesto da PDO/driver sam zaključuje ili tretira vrednost na podrazumevani način.
Zašto je ovo korisno?
Recimo:
$id = '15';

iz $_GET će po prirodi stvari često biti string:
"15"

iako semantički predstavlja integer.
Možemo prvo validirati/castovati:
$id = (int) $id;

a zatim:
$stmt->bindValue(':id', $id, PDO::PARAM_INT);

Time imamo jasnu nameru kroz ceo tok:
HTTP input
→ "15"

validation/cast
→ 15

PDO binding
→ PARAM_INT

MySQL
→ integer value

Posebno važno: LIMIT i OFFSET
Recimo:
$stmt = $pdo->prepare(
    'SELECT *
     FROM hotels
     ORDER BY id
     LIMIT :limit
     OFFSET :offset'
);

Ovde želimo brojeve.
Praktičan pristup je:
$stmt->bindValue(
    ':limit',
    $limit,
    PDO::PARAM_INT
);

$stmt->bindValue(
    ':offset',
    $offset,
    PDO::PARAM_INT
);

$stmt->execute();

Za pagination:
$page = 3;
$perPage = 20;

$offset = ($page - 1) * $perPage;

pa:
LIMIT 20
OFFSET 40

U ovakvim slučajevima eksplicitni PARAM_INT je posebno koristan, jer SQL sintaksa tu očekuje numeričke vrednosti.
PARAM_BOOL
Na primer:
$stmt = $pdo->prepare(
    'UPDATE hotels
     SET is_active = :active
     WHERE id = :id'
);

$stmt->bindValue(
    ':active',
    true,
    PDO::PARAM_BOOL
);

$stmt->bindValue(
    ':id',
    $id,
    PDO::PARAM_INT
);

$stmt->execute();

Naravno, u MySQL-u će boolean na kraju tipično završiti kroz njegov numerički boolean model, ali PHP/PDO kod jasno kaže šta vrednost semantički predstavlja.
PARAM_NULL
Ako baš želimo SQL NULL:
$stmt->bindValue(
    ':deleted_at',
    null,
    PDO::PARAM_NULL
);

Važno je razlikovati:
NULL

od stringa:
"NULL"

Isto kao što smo učili u SQL modulu.
execute([...]) ili bindValue()?
Za većinu običnih vrednosti:
$stmt->execute([
    'email' => $email,
    'name' => $name,
]);

je sasvim lep i praktičan kod.
Ali kad želiš eksplicitnu kontrolu tipa, bindValue() je odličan:
$stmt->bindValue(':id', $id, PDO::PARAM_INT);

Zato ne treba razmišljati:
bindValue()
→ uvek bolje

execute([...])
→ lošije

nego:
execute([...])
→ jednostavno i praktično

bindValue()
→ kada mi treba eksplicitna kontrola parametra/tipa

Mini interview pitanje 21
Zašto bi za:
LIMIT :limit OFFSET :offset

radije uradio:
$stmt->bindValue(':limit', $limit, PDO::PARAM_INT);
$stmt->bindValue(':offset', $offset, PDO::PARAM_INT);

nego da potpuno ignorišeš tip tih vrednosti?
I kako se ovo razlikuje od validacije $limit i $offset pre nego što uopšte dođu do PDO-a?

---

Ovde SQL očekuje isključivo brojeve int, tako da mi PDO-u 
eksplicitno navedemo da želimo da se pošalju 
brojevi čak iako je prosleđen string što je najčešće iz GET-a.

Ovo se ipak razlikuje od php validacije, jer ovo samo ne cast-uje vrednost nego 
PDO-u naglašava da želimo da se tretira kao integer, pa je idealno da prvo vrednosti 
budu validirane i normalizovane + PDO::PARAM_INT

Da — 9.6/10. Suština ti je potpuno dobra, samo jedna mala korekcija u formulaciji.
Kada napišemo:
$stmt->bindValue(':limit', $limit, PDO::PARAM_INT);

ne kažemo samo PDO-u „ovo semantički smatram integerom“ — PDO će vrednost bindovati kao integer tip, što može uključivati konverziju u integer za slanje driver-u.
Ali to i dalje nije validation.
Ako korisnik pošalje nešto besmisleno:
?limit=abc

ne želimo da se oslonimo na to da će se nekako pretvoriti u 0.
Ispravan tok je:
HTTP input
→ validation
→ normalization/cast
→ PDO binding
→ database

Na primer:
$limit = filter_input(
    INPUT_GET,
    'limit',
    FILTER_VALIDATE_INT
);

if ($limit === false || $limit < 1 || $limit > 100) {
    $limit = 20;
}

$stmt->bindValue(':limit', $limit, PDO::PARAM_INT);

Dakle:
validation
→ Da li prihvatam ovu vrednost?

normalization
→ U kom obliku je želim u PHP-u?

PDO::PARAM_INT
→ Kako je šaljem DB driver-u?

To su tri različite odgovornosti.
