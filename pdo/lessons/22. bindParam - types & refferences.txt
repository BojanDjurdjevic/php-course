Lekcija 22 — bindParam() tipovi i reference

Pošto smo već rekli da bindParam() 
vezuje promenljivu po referenci, 
postoji još jedna važna posledica.

Recimo:
$id = '15';

$stmt->bindParam(
    ':id',
    $id,
    PDO::PARAM_INT
);

PDO ne uzima samo trenutnu vrednost $id, 
već prati promenljivu do execute().

Zato:
$id = 15;
$stmt->execute();

$id = 20;
$stmt->execute();

isti statement možemo izvršiti više puta sa različitim vrednostima.
To je posebno zgodno za batch operacije:
$stmt = $pdo->prepare(
    'INSERT INTO tags (name) VALUES (:name)'
);

$stmt->bindParam(':name', $name, PDO::PARAM_STR);

foreach ($tags as $tag) {
    $name = $tag;
    $stmt->execute();
}

Ovde se :name ne binduje ponovo svaki put. 
Bindovana je promenljiva $name, a mi menjamo njen sadržaj.

Ali baš zato bindParam() ne možeš tretirati isto kao bindValue().

Ovo:
$stmt->bindValue(':id', 15, PDO::PARAM_INT);

je prirodno.
Ali bindParam() očekuje promenljivu koju može vezati po referenci:
$id = 15;

$stmt->bindParam(':id', $id, PDO::PARAM_INT);

Mentalna razlika ostaje:
bindValue()
→ snapshot vrednosti sada

bindParam()
→ referenca na promenljivu
→ vrednost se čita pri execute()

Mini interview pitanje 23
Zašto je bindParam() posebno zgodan u ovakvoj petlji:
$stmt = $pdo->prepare(
    'INSERT INTO tags (name) VALUES (:name)'
);

$stmt->bindParam(':name', $name);

foreach ($tags as $tag) {
    $name = $tag;
    $stmt->execute();
}

i šta bi konceptualno bilo drugačije kada bismo pre petlje jednom uradili:
$stmt->bindValue(':name', $name);

---

Zgodniji je bindParam iz razloga što on vezuje vrednost po reverenci 
i nije snapshot vrednosti u jenom momentu. 
Dakle promenjiva se menja do execute, što nije slučaj sa bindValue()

---

Tačno — 10/10.
Najbolja mentalna slika je upravo:
bindValue()
→ snapshot vrednosti u trenutku bindovanja

bindParam()
→ referenca na promenljivu
→ uzima njenu trenutnu vrednost pri execute()

Zato je u petlji bindParam() zgodan kada namerno menjaš istu promenljivu između izvršenja.
