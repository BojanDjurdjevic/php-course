Lekcija 26 — PDO::quote() i zašto nije zamena za prepared statements

PDO ima metodu:

$pdo->quote($value);

Na primer:
$email = "bojan@example.com";

$quoted = $pdo->quote($email);

može dati nešto poput:
'bojan@example.com'

Odnosno PDO napravi string odgovarajuće quoted/escaped forme za konkretan driver.
Teoretski bi neko mogao da uradi:
$email = $pdo->quote($_POST['email']);

$sql = "
    SELECT *
    FROM users
    WHERE email = $email
";

$stmt = $pdo->query($sql);

To je bolje od potpuno slepog:
WHERE email = '$email'

ali to i dalje nije pristup koji želimo da koristimo umesto prepared statements.
Zašto?
Zato što se ponovo vraćamo na mentalni model:
quote()
→ pokušavaš bezbedno da konstruišeš jedan SQL string

prepared statement
→ SQL struktura i podatak ostaju odvojeni

Prepared statement:
$stmt = $pdo->prepare(
    'SELECT * FROM users WHERE email = :email'
);

$stmt->execute([
    'email' => $email,
]);

je mnogo jasniji:
SQL
→ WHERE email = :email

VALUE
→ $email

Kod quote() ti i dalje ručno sastavljaš SQL:
SQL fragment
+
quoted value
+
SQL fragment

što otvara mnogo više prostora za greške.
Posebno: quote() nije za identifiers
Kao što placeholder nije za:
table name
column name
ASC / DESC

ni quote() ne rešava taj problem.
Ako korisnik bira:
ORDER BY price

rešenje je i dalje:
whitelist

a ne:
$pdo->quote($_GET['sort']);

Jer SQL string value:
'base_price'

nije isto što i SQL identifier:
base_price

Mentalna mapa
PDO::quote()
→ escape/quote jedne vrednosti za driver
→ postoji, ali retko nam treba u normalnom CRUD kodu

prepare() + placeholders
→ standardni način za dinamičke vrednosti
→ jasnije
→ manje prostora za greške
→ preferirani pristup

Dakle ako na intervjuu pitaju:
„Možemo li protiv SQL injection-a samo koristiti PDO::quote()?“

dobar odgovor je:
PDO ima quote(), ali za user-controlled vrednosti standardni i poželjniji pristup 
su prepared statements sa parametrima. quote() nije zamena za parameter binding niti rešava dinamičke SQL identifikatore.

Mini interview pitanje 27
Koja je konceptualna razlika između:
$pdo->quote($email)

i:
$stmt = $pdo->prepare(
    'SELECT * FROM users WHERE email = :email'
);

$stmt->execute([
    'email' => $email,
]);

i zašto bi u normalnoj aplikaciji gotovo uvek preferirao drugi pristup?

---

Zato sto je daleko bezbedniji pristup.

quote() nije zamena za parameter binding niti rešava dinamičke SQL identifikatore.

---

Da, suština je tačna — 9.3/10. Samo jedna važna korekcija: 
ne bih rekao da je prepared statement „daleko bezbedniji“ 
u smislu da je quote() automatski nebezbedan. Ako se quote() koristi potpuno pravilno za vrednost, 
može bezbedno escape-ovati tu vrednost. 
Problem je što ručno sklapanje SQL stringa daje mnogo više prostora da programer napravi grešku.

Zato je mnogo bolji mentalni model:
quote()
→ ručno praviš bezbedan SQL literal
→ i dalje sam sklapaš SQL string

prepare + parameters
→ SQL struktura ostaje odvojena od podataka
→ manje prostora za grešku
→ standardni pristup

I kao što si rekao, ni jedno ni drugo ne rešava dinamičke identifiers poput naziva kolone — tu koristimo whitelist.
