Lekcija 10 — rowCount() i zašto je tu lako pogrešiti

Pošto si rekao da si rowCount() već koristio, ovo je baš bitna lekcija.

Kod:
$stmt = $pdo->prepare(
    'UPDATE room_inventory
     SET available = available - 1
     WHERE room_id = :room_id
       AND available > 0'
);

$stmt->execute([
    'room_id' => $roomId,
]);

$count = $stmt->rowCount();

ovde rowCount() ima vrlo korisno značenje:
koliko je redova pogođeno DML operacijom?

Na primer:
1
→ jedan inventory red je pogođen

0
→ nijedan red nije pogođen

To je upravo ono što smo koristili u concurrency priči:
UPDATE room_inventory
SET available = available - 1
WHERE room_id = 5
  AND available > 0;

pa:
if ($stmt->rowCount() === 1) {
    // uspeh
}

Kod UPDATE / DELETE je rowCount() vrlo prirodan alat.
Ali kod:
SELECT ...

ne treba se oslanjati na:
$stmt->rowCount();

kao na univerzalan način da dobiješ broj vraćenih redova.
Za SELECT je ponašanje driver-dependent i nije prenosivo/reliable na isti način.
Ako stvarno želiš broj redova, pitaj bazu:
SELECT COUNT(*)
FROM bookings
WHERE status = 'confirmed';

pa:
$count = $stmt->fetchColumn();

Mentalno:
UPDATE / DELETE
→ rowCount() ima smisla za affected rows

SELECT
→ za broj rezultata koristi COUNT(*)

I još jedna bitna nijansa kod UPDATE.
Recimo:
UPDATE users
SET name = 'Bojan'
WHERE id = 5;

Ako je name već bio 'Bojan', zavisno od driver/server podešavanja možeš dobiti drugačiju semantiku oko "matched" vs "actually changed" rows.
Zato je važno da rowCount() ne zamišljaš samo kao:
"koliko redova WHERE pronađe"

nego kao PDO/driver rezultat o pogođenim redovima za konkretan statement.
Mini interview pitanje 10
Zašto je ovo dobar slučaj za rowCount():
$stmt->execute();

if ($stmt->rowCount() === 1) {
    // decrement inventory uspeo
}

nakon:
UPDATE room_inventory
SET available = available - 1
WHERE id = :id
  AND available > 0;

a zašto ne bi trebalo da radiš:
$stmt = $pdo->query('SELECT * FROM users');
$count = $stmt->rowCount();

ako želiš pouzdano da saznaš koliko user-a postoji?

---

Za SELECT je ponašanje driver-dependent i nije prenosivo/reliable na isti način. 
Zato je tvoj drugi primer pogresan i tu je nbolje pitati bazu sa COUNT(*).

Tačno — 9.5/10. Drugi deo si objasnio potpuno precizno.
Za prvi deo samo dodaj ovu ideju:
UPDATE ... WHERE available > 0
→ rowCount() nam kaže da li je update zaista pogodio red

1
→ decrement je uspeo

0
→ uslov nije prošao / red nije pogođen

Zato je rowCount() baš koristan za atomic conditional update scenarije.
