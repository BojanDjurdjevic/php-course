Lekcija 14 — errorInfo() i errorCode()

Pošto koristimo:

PDO::ERRMODE_EXCEPTION

najčešće ćemo DB grešku dobiti kroz exception.
Ali PDO i PDOStatement imaju i metode za čitanje informacija o grešci:
$pdo->errorCode();
$pdo->errorInfo();

i:
$stmt->errorCode();
$stmt->errorInfo();

Mentalno:
errorCode()
→ kratak SQLSTATE kod

errorInfo()
→ više detalja o poslednjoj grešci

errorInfo() tipično vraća array sa informacijama tipa:
[
    '23000',
    1062,
    'Duplicate entry ...'
]

Otprilike:
[0]
→ SQLSTATE

[1]
→ driver-specific error code

[2]
→ driver-specific error message

Na primer duplicate UNIQUE vrednost može dati nešto iz kategorije:
SQLSTATE 23000
→ integrity constraint violation

To lepo povezuje PDO sa MySQL modulom koji smo upravo završili.
Recimo:
try {
    $stmt = $pdo->prepare(
        'INSERT INTO users (email) VALUES (:email)'
    );

    $stmt->execute([
        'email' => $email,
    ]);
} catch (PDOException $e) {
    // UNIQUE(email) može ovde izazvati exception
}

Ovde aplikacija može da razlikuje:
validation
→ pre INSERT-a proveri format

DB UNIQUE
→ poslednja linija zaštite

PDOException
→ PHP-u javlja da DB operacija nije uspela

Samo jedna vrlo važna praksa: ne treba korisniku direktno prikazivati sirovu DB poruku poput:
Duplicate entry ...
SQLSTATE...
table users...

To je korisno za log/debug, ali korisnik treba da dobije nešto poput:
Email adresa je već zauzeta.

Dakle:
DB detalj
→ log/debug

user-facing poruka
→ kontrolisana i razumljiva

Mini interview pitanje 14
Koja je razlika između:
errorCode()

i:
errorInfo()

i zašto nije dobra ideja da korisniku direktno prikažemo ceo 
DB error message koji dobijemo iz PDO-a?

---

errorCode() je kratak SQL State kod, dok je errorInfo() 
više informacija o poslednjoj grešci gde pdo vraća informacije u vidu niza.

Korisniku iz bezbednosnih razloga nikada ne odajemo koja je greška u bazi, 
jer na osnovu nje može i da otkrije više informacija o bazi, ako je napadač. 

Zato greška ide u log a korisniku custom message.

---

Tačno — 10/10.
Posebno dobro ovo:
DB detalj
→ log/debug

korisnik
→ custom, kontrolisana poruka

Jer sirova DB greška može otkriti stvari poput naziva tabela, 
constraint-a, strukture upita ili driver detalja. 
To nije nešto što želimo da izlažemo spolja.

errorCode() je kraći SQLSTATE signal, dok errorInfo() daje širi kontekst, 
tipično niz sa SQLSTATE kodom, driver-specific kodom i porukom.
