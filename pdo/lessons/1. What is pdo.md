# 1. What is pdo

## Modul 7 — PDO

---

## Lekcija 1: Šta je zapravo PDO?

PDO znači:

PHP Data Objects

Najvažnija rečenica za početak:

PDO je PHP interfejs za komunikaciju sa bazama podataka.

On nije baza, nije MySQL i nije SQL.
Mentalno:

```text
PHP aplikacija
     ↓
    PDO
     ↓
PDO MySQL driver
     ↓
 MySQL server
     ↓
   database
```

Recimo imaš PHP:

```php
$pdo = new PDO(
    'mysql:host=localhost;dbname=booking;charset=utf8mb4',
    'root',
    ''
);
```

Ovde ne „otvaraš bazu“ u smislu fajla.
Kažeš PDO-u otprilike:

```text
Želim konekciju
↓
koristi MySQL driver
↓
server je localhost
↓
baza je booking
↓
charset utf8mb4
↓
evo credentials
```

PDO zatim preko odgovarajućeg driver-a komunicira sa MySQL serverom.

---

## Zašto postoji PDO?

PHP bi teoretski mogao imati potpuno drugačiji API za svaku bazu:

```php
mysql_connect_somehow()
postgres_connect_somehow()
sqlite_connect_somehow()
```

...

PDO daje zajednički PHP interfejs:

```php
$pdo->prepare();
$stmt->execute();
$stmt->fetch();
```

i podržava različite DB sisteme preko driver-a:

```text
PDO
├── pdo_mysql
├── pdo_pgsql
├── pdo_sqlite
└── ...
```

Zato možeš razmišljati ovako:

```text
PDO
= zajednički PHP API
```

```text
Driver
= prevodilac/adapter između PDO-a i konkretnog DBMS-a
```

Ali jedna važna stvar:

PDO ne čini SQL potpuno database-independent.

Ako napišeš MySQL-specifičan SQL:

INSERT ... ON DUPLICATE KEY UPDATE

i sutra promeniš driver na PostgreSQL, taj SQL neće magično proraditi.
Dakle PDO apstrahuje način komunikacije, ne sve razlike između SQL dijalekata.

---

## Tri glavna objekta koja ćemo stalno sretati

Ovo želim da ti ostane kao glavna mapa modula:

```text
PDO
↓
PDOStatement
↓
rezultat / podaci
```

```text
1. PDO
$pdo = new PDO(...);
```

Predstavlja tvoju konekciju/session prema DB serveru.
Preko njega radiš stvari poput:

```php
$pdo->prepare(...);
$pdo->query(...);
$pdo->beginTransaction();
$pdo->commit();
$pdo->rollBack();
```

Mentalno:

```php
$pdo
```

= vrata prema bazi

---

## 2. PDOStatement

Kada napišeš:

```php
$stmt = $pdo->prepare(
    'SELECT * FROM users WHERE email = :email'
);
```

`$stmt` više nije PDO konekcija.
To je:

PDOStatement

odnosno objekat koji predstavlja SQL statement koji pripremamo/izvršavamo i iz kojeg čitamo rezultat.
Mentalno:

```text
$pdo
→ konekcija
```

```text
$stmt
→ konkretan SQL posao preko te konekcije
```

Zato posle radiš:

```php
$stmt->execute(...);
$stmt->fetch();
$stmt->fetchAll();
$stmt->rowCount();
```

na `$stmt`, a ne na `$pdo`.

---

## 3. Rezultat

Recimo:

```php
$stmt = $pdo->prepare(
    'SELECT id, name FROM users WHERE id = :id'
);

$stmt->execute([
    'id' => 5,
]);

$user = $stmt->fetch();
```

Tok je:

```text
PHP pravi statement
        ↓
PDO šalje zahtev driver-u
        ↓
driver komunicira sa MySQL
        ↓
MySQL izvrši SQL
        ↓
vrati result set
        ↓
PDOStatement drži/pristupa rezultatu
        ↓
fetch()
        ↓
PHP vrednost
```

To je suština cele priče.

---

## Gde se uklapa SQL koji smo upravo učili?

Ovo je možda najvažnija veza između prethodnog i ovog modula.
U MySQL modulu radili smo:

```sql
SELECT *
FROM bookings
WHERE hotel_id = 15
  AND status = 'confirmed';
```

To je odgovornost baze.
PDO ne odlučuje:

- koji indeks će MySQL koristiti,
- kako radi JOIN,
- šta radi GROUP BY,
- kako radi FOR UPDATE,
- kako optimizer izvršava query.
PDO samo omogućava PHP-u da kaže:

„MySQL, izvrši ovaj SQL i vrati mi rezultat.“

Dakle:

```text
PHP business logic
        ↓
       PDO
        ↓
       SQL
        ↓
MySQL optimizer / engine
        ↓
      result
```

Zato nam je SQL modul morao doći pre PDO-a.

---

## PDO vs MySQL

Ovo je često interview pitanje u prikrivenom obliku.
Nemoj reći:

„PDO je za MySQL.“

Preciznije:

PDO je database-access abstraction layer u PHP-u koji preko driver-a omogućava komunikaciju sa različitim DBMS-ovima, među njima i MySQL-om.

Za MySQL imamo:

```text
PDO
+
pdo_mysql driver
+
MySQL server
```

---

## A šta je onda mysqli?

PHP ima i drugi API:

MySQLi

mysqli je:

MySQL Improved

i namenjen je konkretno MySQL-u.
PDO je širi:

```text
PDO
→ MySQL
→ PostgreSQL
→ SQLite
→ drugi podržani driver-i
```

Dok:

```text
mysqli
→ MySQL
```

Oba podržavaju prepared statements.
Dakle razlog za PDO nije:

„PDO je bezbedan, mysqli nije.“

To bi bilo pogrešno.
Oba mogu biti bezbedna kada se pravilno koriste.
PDO je nama zgodan zbog API-ja koji već poznaješ i zato što je vrlo čest u PHP aplikacijama.

## Poveži ovo sa Laravelom

Ovo će ti biti posebno korisno.
Kad u Laravelu radiš:

```php
DB::select(...);
```

ili:

```php
User::where('email', $email)->first();
```

ispod svih tih slojeva na kraju mora postojati nešto što razgovara sa DB driver-om.
Vrlo uprošćeno:

```text
Eloquent
↓
Query Builder
↓
Laravel Database Connection
↓
PDO
↓
pdo_mysql
↓
MySQL
```

Zato ti Laravel deluje kao:

```php
User::find(5);
```

ali nekoliko slojeva ispod završimo kod iste fundamentalne ideje:

PHP mora nekako poslati SQL MySQL-u.

PDO je jedan od ključnih slojeva koji to omogućava.

## Mini interview pitanje 1

Krećemo odmah po našem pravilu — jedno pitanje:

Kada napišemo new `PDO(...)`,
šta zapravo predstavlja objekat koji dobijemo u `$pdo`,
i koja je razlika između tog PDO objekta i PDOStatement objekta koji dobijemo iz `$pdo->prepare`()?

---

`$pdo` bi ovde istvari bio pdo objekat - konekcija/session na bazu ili da kazemo most, vrata ka bazi,
dok je pdoStatement vec konkretan sql posao preko te konekcije, konkretno upit koji baza treba da izvrsi.

---

Tačno — 10/10.
Najkraće i najpreciznije:

```text
$pdo
→ PDO objekat
→ aktivna DB konekcija/session
→ “vrata” prema bazi
```

dok je:

```text
$stmt
→ PDOStatement objekat
→ konkretan SQL statement koji pripremamo/izvršavamo
→ preko njega posle čitamo rezultat
```

Dakle:

```php
$pdo = new PDO(...);

$stmt = $pdo->prepare(
    'SELECT * FROM users WHERE id = :id'
);
```

mentalno je:

```text
PDO konekcija
    ↓
PDOStatement
    ↓
execute()
    ↓
MySQL izvrši SQL
    ↓
fetch()/fetchAll()
```

Samo jedna sitna preciznost: PDOStatement nije još nužno „upit koji je baza izvršila“. Posle `prepare()` imamo pripremljen statement; tek nakon:

```php
$stmt->execute();
```

dolazi do izvršenja.
To će nam biti baš sledeća važna razlika:

```php
prepare()
```

```text
≠
execute()
```
