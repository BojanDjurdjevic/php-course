# 5. PREPARE VS EXECUTE

## Lekcija 5 — `prepare()` vs `execute()`

Ovo je jedna od najvažnijih stvari u celom PDO modulu.
Imamo:

```php
$stmt = $pdo->prepare(
    'SELECT * FROM users WHERE email = :email'
);
```

---

## Šta je ovde urađeno?

Napravili smo:

PDOStatement

koji predstavlja SQL šablon:

```sql
SELECT *
FROM users
WHERE email = :email
```

Ali još nemamo konkretnu vrednost za:

:email

i još nismo rekli:

izvrši ovaj statement sa ovim podatkom.

Tek onda radimo:

```php
$stmt->execute([
    'email' => $email,
]);
```

Mentalno:

```text
prepare()
→ pripremi SQL strukturu
```

```text
execute()
→ izvrši statement sa konkretnim vrednostima
```

To je veoma važna podela.
Na primer:

```php
$stmt = $pdo->prepare(
    'SELECT * FROM users WHERE id = :id'
);
```

možemo isti statement koristiti više puta:

```php
$stmt->execute(['id' => 5]);
$user5 = $stmt->fetch();

$stmt->execute(['id' => 10]);
$user10 = $stmt->fetch();
```

SQL struktura je ista:

```sql
WHERE id = :id
```

samo menjamo podatak.
I sada dolazimo do bezbednosti.
Loš pristup:

```php
$sql = "
    SELECT *
    FROM users
    WHERE email = '$email'
";
```

Ovde smo spojili:

```text
SQL sintaksu
+
user-controlled podatak
```

u jedan string.
Kod prepared statement-a:

```php
$stmt = $pdo->prepare(
    'SELECT * FROM users WHERE email = :email'
);

$stmt->execute([
    'email' => $email,
]);
```

mentalno držimo odvojeno:

```text
SQL struktura
→ SELECT ... WHERE email = :email
```

```text
podatak
→ vrednost $email
```

To je suština prepared statements-a.

---

## Mini interview pitanje 5

Koja je razlika između:

```php
$pdo->prepare(...)
```

i:

```php
$stmt->execute(...)
```

i zašto je korisno što SQL struktura i korisničke vrednosti nisu spojene u jedan običan string?

---

`$pdo->prepare`(...) jeste priprema upita sa da kazemo placeholderom podatka, na primer =:email...

`$stmt->execute`(...) vezuje podatak za taj 'placeholcder' i izvrsava upit.

Ovo je korisno, jer kada bi sve bilo spojeno u jedan string, ne bi bilo bezbedno jer su podaci koji nam dolaze user controlled.

---

Tačno — 9.8/10.
Suština ti je dobra:

```text
prepare()
→ pravi/priprema SQL statement sa placeholder-ima
```

```text
execute()
→ prosleđuje konkretne vrednosti i izvršava statement
```

Samo mala preciznost: `execute([...])` možemo praktično posmatrati kao prosleđivanje/bindovanje vrednosti za to izvršenje, ali kasnije ćemo razlikovati to od eksplicitnih metoda:

```php
bindValue()
bindParam()
```

Najvažniji deo odgovora ti je ovaj:

SQL struktura i user-controlled podatak ne smeju biti slepljeni u jedan string.

Mentalno:

```text
SQL
WHERE email = :email
        ↑
placeholder
```

```text
DATA
bojan@example.com
```

Baza dobija jasnu razliku između:

šta je SQL instrukcija

i:

šta je samo vrednost

To je centralna ideja zaštite od SQL injection-a.
