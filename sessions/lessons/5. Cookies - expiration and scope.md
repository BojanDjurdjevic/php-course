# 5. Cookies - expiration and scope

## Lekcija 5 — Cookies: `setcookie()`, expiration i scope

Sad prelazimo na cookie-je kao zaseban koncept, ne samo session cookie.
Najprostiji primer:

```php
setcookie('theme', 'dark');
```

Browser zatim može dobiti:

Set-Cookie: theme=dark

Na sledećem request-u:

```php
$_COOKIE['theme'] ?? null;
```

može dati:

dark

Važno: `setcookie()` ne menja magično trenutni `$_COOKIE`.
Ako uradiš:

```php
setcookie('theme', 'dark');

var_dump($_COOKIE['theme'] ?? null);
```

u istom request-u možda još nećeš videti novu vrednost.

---

## Zašto?

Jer:

```text
setcookie()
→ šalje Set-Cookie header browseru
```

```text
browser
→ čuva cookie
```

```text
sledeći request
→ browser ga šalje nazad
```

```text
PHP
→ tada puni $_COOKIE
```

Dakle cookie round-trip je:

SERVER RESPONSE

```text
Set-Cookie
↓
BROWSER STORAGE
↓
```

---

## NEXT REQUEST

Cookie: ...

```text
↓
$_COOKIE
```

Expiration
Ako uradiš:

```php
setcookie(
    'theme',
    'dark',
    time() + 3600
);
```

cookie važi približno još jedan sat.
Ako nemaš expiration ili koristiš session-cookie ponašanje, browser ga tipično tretira kao privremen cookie vezan za browser session.
Za duže trajanje:

```php
setcookie(
    'language',
    'sr',
    time() + 60 * 60 * 24 * 30
);
```

otprilike 30 dana.

## Brisanje cookie-ja

Cookie ne brišemo tako što napišemo:

```php
unset($_COOKIE['theme']);
```

To samo menja PHP array u trenutnom request-u.
Browser i dalje ima cookie.
Da ga stvarno ukloniš iz browsera, tipično pošalješ isti cookie sa expiration-om u prošlosti:

```php
setcookie(
    'theme',
    '',
    time() - 3600
);
```

Vrlo važna stvar:

Cookie moraš brisati sa istim relevantnim scope parametrima sa kojima je napravljen.

Na primer path.
Ako je napravljen kao:

```php
setcookie(
    'theme',
    'dark',
    [
        'expires' => time() + 3600,
        'path' => '/',
    ]
);
```

onda ga brišeš sa:

```php
setcookie(
    'theme',
    '',
    [
        'expires' => time() - 3600,
        'path' => '/',
    ]
);
```

---

## Moderniji `setcookie()` syntax

Umesto stare pozicione forme:

```php
setcookie(
    $name,
    $value,
    $expires,
    $path,
    $domain,
    $secure,
    $httponly
);
```

mnogo je čitljivije koristiti options array:

```php
setcookie(
    'theme',
    'dark',
    [
        'expires' => time() + 3600,
        'path' => '/',
        'secure' => true,
        'httponly' => true,
        'samesite' => 'Lax',
    ]
);
```

To ćemo koristiti dalje.
path
Cookie scope može zavisiti od path-a.
Ako:

```php
setcookie(
    'theme',
    'dark',
    [
        'path' => '/',
    ]
);
```

cookie je dostupan praktično kroz ceo sajt.
Ako:

```php
'path' => '/admin'
```

browser će ga slati request-ovima za /admin..., ali ne nužno za ostatak sajta.
Za većinu application-wide preference/session cookie-ja:

```php
'path' => '/'
```

je čest izbor.
domain
Možeš definisati i domain scope.
Na primer cookie za:

example.com

ili potencijalno više subdomena, u zavisnosti od konfiguracije.
Ali za sada želim da ovo zapamtiš:

```text
path
→ gde unutar sajta cookie važi
```

```text
domain
→ za koje host/domain request-ove cookie važi
```

## Cookies su client-side data

Ovo je ogromna razlika u odnosu na session.
Ako čuvaš:

```php
setcookie(
    'role',
    'admin',
    ...
);
```

korisnik može potencijalno menjati tu vrednost u svom browseru.
Zato:

```text
cookie data
→ user-controlled / untrusted input
```

Ne smeš raditi:

```php
if ($_COOKIE['role'] === 'admin') {
    // admin access
}
```

To bi bilo potpuno nesigurno.
Cookie je dobar za stvari poput:

```text
theme
language
non-sensitive preferences
remember-me token uz bezbedan dizajn
session ID
```

ali authorization odluke ne zasnivamo na običnom client cookie podatku.

---

## Session cookie vs običan application cookie

Na primer:

```text
PHPSESSID=abc123
→ session cookie
→ identifikuje server-side session
```

```text
theme=dark
→ application cookie
→ sama vrednost preference-a je u browseru
```

To je fundamentalna razlika.

## Šta nije u redu sa ovim kodom?

```php
setcookie(
    'role',
    'admin',
    [
        'expires' => time() + 86400,
        'path' => '/',
    ]
);

if (
    ($_COOKIE['role'] ?? null) === 'admin'
) {
    echo 'Welcome, admin!';
}
```

Objasni mi dve stvari:

1. zašto `$_COOKIE['role']` možda neće odmah biti 'admin' u istom request-u nakon `setcookie()`,
2. zašto je još ozbiljnije to što authorization uopšte zasnivamo na običnom cookie-ju.
