# 11. Logout Flow — Part 1

## Module 10 — Authentication bez frameworka

### Lekcija 11/15 — Logout flow

Logout izgleda jednostavno:

```php
unset($_SESSION['user_id']);
```

ali iza njega zapravo postoji nekoliko različitih odluka:

```text
ukloni authenticated identity
da li uništiti celu session?
šta sa session cookie-jem?
šta sa session ID-em?
šta sa remember-me tokenom?
šta sa current-user cache-om?
```

Najvažniji mentalni model:

```text
Logout
→ invalidiraj authenticated state
```

Ne znači nužno:

```text
uništi apsolutno sve što postoji u session-u
```

---

## 1. Šta logout zapravo znači?

Ako imamo:

```php
$_SESSION['user_id'] = 17;
```

onda session predstavlja authenticated korisnika.

Logout treba da napravi stanje:

```text
pre:
user_id = 17

posle:
nema authenticated identity
```

Dakle osnovna operacija je:

```php
unset($_SESSION['user_id']);
```

ili preko wrapper-a:

```php
$this->session->forget('user_id');
```

Posle toga:

```php
$auth->check();
```

treba da vrati:

```text
false
```

---

## 2. Logout ne briše User-a

Ovo zvuči očigledno, ali vredi precizno razdvojiti.

Logout:

```text
uklanja authentication state
```

Ne radi:

```text
DELETE FROM users
```

Ne menja:

```text
email
password
role
account status
```

User i dalje postoji.

Samo više nema aktivnu authenticated session u tom browser-u.

---

## 3. Minimalni logout

Najjednostavnija implementacija:

```php
public function logout(): void
{
    $this->session->forget('user_id');
}
```

Mentalno:

```text
authenticated session
↓
remove user_id
↓
guest session
```

Ovo već može biti potpuno validan logout ako želiš da session nastavi da postoji za druge podatke.

---

## 4. Zašto session može da ostane i posle logout-a?

Session možda ne sadrži samo auth podatke.

Može sadržati:

```text
flash messages
shopping cart
CSRF token
locale
temporary form data
```

Na primer:

```php
$_SESSION = [
    'user_id' => 17,
    'cart' => [...],
    'csrf_token' => '...',
];
```

Logout može da ukloni samo:

```text
user_id
```

a ostatak session state-a da ostane.

Dakle:

```text
logout
≠ automatski session_destroy()
```

---

## 5. Partial logout vs full session destruction

Možemo razmišljati o dve strategije.

### Partial logout

```text
ukloni samo auth-related podatke
```

Na primer:

```php
unset($_SESSION['user_id']);
```

Session nastavlja da postoji.

### Full session destruction

```text
uništi celu session
```

Na primer:

```php
session_destroy();
```

To uklanja server-side session state.

Oba pristupa imaju legitimne use case-ove.

---

## 6. `session_destroy()` ne znači automatski “sve je nestalo iz PHP promenljive”

Važna PHP nijansa.

```php
session_destroy();
```

uništava session podatke povezane sa trenutnim session ID-em u storage-u.

Ali ne mora automatski da isprazni trenutni:

```php
$_SESSION
```

array u memoriji tog request-a.

Ako želiš da ga eksplicitno očistiš:

```php
$_SESSION = [];
```

pa onda:

```php
session_destroy();
```

Mentalno:

```text
$_SESSION = []
→ očisti current request state

session_destroy()
→ ukloni persisted session data
```

To nisu potpuno ista operacija.

---

## 7. Šta sa session cookie-jem?

Čak i ako uništiš server-side session, browser može i dalje imati cookie:

```text
PHPSESSID=abc123
```

Taj ID više možda ne vodi do validne session, ali cookie fizički i dalje može postojati kod browser-a.

Ako želiš potpuno čišćenje, možeš obrisati i session cookie.

Konceptualno:

```text
server-side session
→ destroy

browser session cookie
→ expire/delete
```

To daje potpuniji logout lifecycle.

---

## 8. Brisanje session cookie-ja

Tipično prvo uzmeš session cookie parametre:

```php
$params = session_get_cookie_params();
```

pa cookie pošalješ sa isteklim vremenom:

```php
setcookie(
    session_name(),
    '',
    time() - 42000,
    $params['path'],
    $params['domain'],
    $params['secure'],
    $params['httponly']
);
```

Ideja:

```text
isti cookie name
isti path/domain
expiry u prošlosti
↓
browser ga uklanja
```

Detalji mogu zavisiti od konfiguracije, ali mentalni model je važniji od samog boilerplate-a.

---

## 9. Da li uvek treba uništiti celu session?

Ne nužno.

Ako imaš:

```text
cart
locale
flash
CSRF
```

možda želiš da korisnik nakon logout-a i dalje zadrži deo session state-a.

Primer:

```text
logged-in user
↓
logout
↓
cart ostaje
↓
guest i dalje može da nastavi shopping
```

Tada je:

```php
unset($_SESSION['user_id']);
```

često bolji izbor od:

```php
session_destroy();
```

---

## 10. Logout je application policy

Ne postoji jedno pravilo:

```text
uvek session_destroy()
```

ili:

```text
nikad session_destroy()
```

Treba da znaš šta tvoja session sadrži.

Ako session služi samo za:

```text
auth state
```

full destruction može biti sasvim prirodan.

Ako sadrži i druge korisne guest podatke:

```text
auth-only cleanup
```

može biti bolji dizajn.

Ključno pitanje:

> Šta tačno treba da prestane da važi kada se user izloguje?

# 11. Logout Flow — Part 2

## Module 10 — Authentication bez frameworka

### Lekcija 11/15 — Logout flow

---

## 11. Session ID posle logout-a

Pretpostavimo imamo:

```text
session ABC
→ authenticated user #17
```

Posle logout-a možemo ostaviti isti session ID:

```text
session ABC
→ guest
```

ili ga možemo promeniti.

Sa security aspekta često ima smisla uraditi rotation:

```php
session_regenerate_id(true);
```

nakon uklanjanja authenticated identity.

Mentalno:

```text
authenticated session ABC
↓
logout
↓
guest session XYZ
```

Tako se jasno prekida kontinuitet privilegovane session identity.

---

## 12. Zašto rotirati ID i na logout-u?

Na login-u rotiramo zbog:

```text
guest
→ authenticated
```

Na logout-u možemo rotirati zbog suprotnog prelaza:

```text
authenticated
→ guest
```

Time stari authenticated session identifier prestaje da bude koristan kao aktivni session ID.

Ovo je posebno zdravo ako session ostaje živa zbog:

```text
flash
cart
locale
```

Dakle:

```text
remove auth identity
+
regenerate session ID
```

je dobar logout pattern.

---

## 13. Redosled logout koraka

Ako ne uništavamo celu session:

```text
1. ukloni auth-related data
2. očisti current-user cache
3. regenerate session ID
4. nastavi kao guest
```

Na primer:

```php
public function logout(): void
{
    $this->session->forget('user_id');

    $this->currentUser = null;
    $this->userResolved = true;

    $this->session->regenerate();
}
```

Sada su:

```text
session state
AuthService cache
session identifier
```

usklađeni.

---

## 14. Current-user cache mora biti očišćen

Iz prethodne lekcije imamo:

```php
private ?User $currentUser = null;
private bool $userResolved = false;
```

Ako je user već učitan:

```php
$auth->user();
```

pa onda uradimo:

```php
$auth->logout();
```

ne sme ostati:

```text
currentUser = User #17
```

jer bi isti request mogao kasnije pogrešno vratiti starog user-a.

Zato:

```php
$this->currentUser = null;
$this->userResolved = true;
```

mora pratiti logout.

---

## 15. Zašto `userResolved = true` posle logout-a?

Ako uradimo:

```php
$this->currentUser = null;
$this->userResolved = false;
```

sledeći:

```php
$auth->user();
```

bi ponovo pokušao resolution.

Ali upravo smo eksplicitno logout-ovali user-a.

Bolje:

```text
userResolved = true
currentUser = null
```

što znači:

> Znamo stanje za ovaj request — nema current user-a.

---

## 16. Auth-related session keys mogu biti više od jednog

Danas imamo:

```php
$_SESSION['user_id'];
```

Ali kasnije možemo imati:

```text
authenticated_at
last_activity
two_factor_passed
auth_context
```

Logout treba da očisti sve što pripada authenticated state-u.

Na primer:

```php
$this->session->forget('user_id');
$this->session->forget('authenticated_at');
$this->session->forget('last_activity');
```

Zato je korisno znati koje session keys auth sloj poseduje.

---

## 17. Nemoj ostaviti authorization podatke posle logout-a

Ako si nekada čuvao:

```php
$_SESSION['role'] = 'admin';
```

ili:

```php
$_SESSION['permissions'] = [...];
```

logout mora i to ukloniti.

Inače možeš završiti sa:

```text
user_id nema
ali role = admin
```

što je potpuno nekonzistentan auth state.

Još bolji dizajn je da takve podatke ni ne čuvaš bez potrebe, nego ih resolve-uješ kroz current User-a.

---

## 18. Logout i CSRF

Logout je state-changing akcija.

Zato u ozbiljnoj aplikaciji ne želiš nužno:

```text
GET /logout
```

koji automatski menja server state.

Bolji obrazac je često:

```text
POST /logout
```

sa CSRF zaštitom.

Zašto?

Jer:

```text
GET
→ trebalo bi da bude safe/idempotent retrieval semantics

logout
→ menja authenticated state
```

CSRF detaljno radimo u Security modulu, ali ovde je bitno razumeti HTTP semantiku.

---

## 19. Zašto `GET /logout` može biti problem?

Ako je logout GET endpoint:

```html
<img src="https://example.com/logout">
```

ili neki link može naterati browser da pošalje request bez namerne korisničke akcije.

Najgori rezultat možda nije krađa podataka, ali attacker može korisnika stalno izlogovati.

To je oblik neželjene state-changing akcije.

Zato je:

```text
POST /logout
+
CSRF token
```

zdraviji obrazac.

---

## 20. Logout route treba da bude protected

Ruta:

```text
POST /logout
```

ima smisla samo za authenticated user-a.

Dakle:

```text
POST /logout
↓
AuthMiddleware
↓
LogoutController
↓
AuthService::logout()
```

Guest nema authenticated state koji treba ukloniti.

Nije katastrofa ako logout bude idempotent i za guest-a, ali route contract je prirodno:

```text
auth middleware
```

## 21. Logout Controller

Controller treba da bude veoma tanak:

```php
final class LogoutController
{
    public function __construct(
        private AuthService $auth
    ) {}

    public function __invoke(): void
    {
        $this->auth->logout();

        header('Location: /login');
        exit;
    }
}
```

Ili sa Response objektom:

```php
public function __invoke(): Response
{
    $this->auth->logout();

    return Response::redirect('/login');
}
```

Controller:

```text
prima HTTP request
poziva logout use case
vraća response
```

Ne treba sam da manipuliše session detaljima.

---

## 22. AuthService treba da poseduje logout lifecycle

Lošije:

```php
unset($_SESSION['user_id']);
session_regenerate_id(true);
```

direktno u Controller-u.

Bolje:

```php
$this->auth->logout();
```

Zašto?

Jer AuthService već zna:

```text
koji session keys čine auth state
kako se current-user cache čisti
da li se session ID rotira
šta kasnije treba uraditi sa remember-me tokenom
```

Logout treba da bude centralizovan kao i login.

---

## 23. Remember-me menja logout pravila

Kasnije ćemo imati persistent login token.

Tada:

```text
logout
```

ne sme samo da ukloni:

```text
session user_id
```

jer bi browser mogao preko remember-me cookie-ja odmah ponovo da se autentifikuje.

Logout tada mora da invalidira i:

```text
remember-me token
+
remember-me cookie
```

Dakle kompletan logout može postati:

```text
remove session auth
invalidate persistent token
delete persistent cookie
rotate session ID
```

To detaljno radimo u sledećoj lekciji.

---

## 24. Logout jednog uređaja vs svih uređaja

Jedan user može imati:

```text
Laptop → session A
Phone  → session B
Tablet → session C
```

Klasičan logout sa laptopa obično znači:

```text
invalidate session A
```

Ali ne nužno:

```text
invalidate B i C
```

To je:

```text
logout current session/device
```

Poseban use case je:

```text
logout all devices
```

koji zahteva dodatnu session/token infrastrukturu.

Minimalni PHP session sistem to ne rešava automatski.

---

## 25. Promena password-a i postojeće sessions

Ovo je važna security odluka.

Ako user promeni password:

```text
da li stare sessions ostaju validne?
```

Možeš imati politiku:

```text
password changed
→ invalidate all other sessions
```

posebno kod security-sensitive sistema.

Ali za to moraš imati način da pratiš/invalidiraš sessions ili auth version.

To je iznad našeg minimalnog auth sistema, ali concept je važan.

---

## 26. Session version / auth version koncept

Jedan napredniji pattern je da User ima nešto poput:

```text
auth_version = 5
```

Session zapamti:

```text
auth_version = 5
```

Ako želiš globalno da invalidiraš sve stare sessions:

```text
user.auth_version
5 → 6
```

Sledeći request vidi:

```text
session version 5
database version 6
↓
session više nije validna
```

To može biti koristan pattern za:

```text
logout all devices
password compromise
security reset
```

Ne implementiramo ga sada, ali mentalno pokazuje da session invalidation može biti šira od jednog browser-a.

---

## 27. Kompletan logout mentalni flow

Za naš osnovni sistem:

```text
POST /logout
↓
AuthMiddleware
↓
LogoutController
↓
AuthService::logout()
↓
remove user_id
↓
clear current-user cache
↓
regenerate session ID
↓
guest
↓
redirect /login
```

Ako koristimo full destruction:

```text
POST /logout
↓
clear $_SESSION
↓
destroy server-side session
↓
delete session cookie
↓
guest
```

Ako kasnije uključimo remember-me:

```text
logout
↓
session auth invalidation
+
persistent token invalidation
+
remember cookie deletion
```

## Najvažnije za zapamtiti

Logout znači:

```text
invalidiraj authenticated state
```

Ne znači nužno:

```text
uništi sve session podatke
```

Minimalno:

```php
$this->session->forget('user_id');
```

Ali moraš očistiti i per-request cache:

```php
$this->currentUser = null;
$this->userResolved = true;
```

Dve strategije:

```text
partial logout
→ ukloni auth-related session state

full logout/session destruction
→ očisti celu session
→ session_destroy()
→ po potrebi obriši session cookie
```

`session_destroy()` i:

```php
$_SESSION = [];
```

nisu ista operacija:

```text
$_SESSION = []
→ current in-memory state

session_destroy()
→ persisted server-side session
```

Dobar partial logout pattern:

```text
remove auth identity
↓
clear AuthService cache
↓
regenerate session ID
↓
nastavi kao guest
```

Logout route je najbolje tretirati kao:

```text
POST /logout
```

jer logout menja state.

Tipičan flow:

```text
POST /logout
↓
AuthMiddleware
↓
LogoutController
↓
AuthService
↓
guest
```

I najvažnija buduća nijansa:

```text
session logout
≠ nužno kompletan logout
```

ako postoji:

```text
remember-me token
```

Tada moraju biti invalidirani i:

```text
persistent token
persistent cookie
```
