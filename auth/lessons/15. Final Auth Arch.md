## 3. `User`

`User` predstavlja persisted identity/account state.

Na primer:

```php
final class User
{
    public function __construct(
        private int $id,
        private string $email,
        private string $passwordHash,
        private ?DateTimeImmutable $emailVerifiedAt,
        private AccountStatus $status
    ) {}

    public function id(): int
    {
        return $this->id;
    }

    public function email(): string
    {
        return $this->email;
    }

    public function passwordHash(): string
    {
        return $this->passwordHash;
    }

    public function isEmailVerified(): bool
    {
        return $this->emailVerifiedAt !== null;
    }

    public function isActive(): bool
    {
        return $this->status === AccountStatus::Active;
    }
}
```

`User` ne treba da zna:

```text
$_POST
session_start()
SQL query
redirect
```

On predstavlja account/domain state.

## 4. `UserRepository`

Repository je persistence boundary.

Contract:

```php
interface UserRepository
{
    public function findById(int $id): ?User;

    public function findByEmail(
        string $email
    ): ?User;

    public function create(
        string $email,
        string $passwordHash
    ): User;

    public function updatePasswordHash(
        int $userId,
        string $passwordHash
    ): void;

    public function markEmailVerified(
        int $userId
    ): void;
}
```

Repository zna:

```text
SQL
PDO
tables
mapping rows → objects
```

Ne zna:

```text
login policy
session state
redirect
```

## 5. `Session`

Session wrapper izoluje:

```php
$_SESSION
session_regenerate_id()
```

od ostatka application code-a.

Na primer:

```php
final class Session
{
    public function get(
        string $key,
        mixed $default = null
    ): mixed {
        return $_SESSION[$key] ?? $default;
    }

    public function put(
        string $key,
        mixed $value
    ): void {
        $_SESSION[$key] = $value;
    }

    public function forget(string $key): void
    {
        unset($_SESSION[$key]);
    }

    public function regenerate(): void
    {
        session_regenerate_id(true);
    }
}
```

Mentalno:

```text
AuthService
↓
Session abstraction
↓
PHP session implementation
```

## 9. Login + Remember Me

```text

↓

↓

↓

↓

↓

```

Dakle:

```text

→ normalna session

→ persistent fallback authentication
```

To su povezani, ali odvojeni slojevi.

## 21. Dependency Injection wiring

Na composition root-u možemo povezati objekte:

```php
$pdo = new PDO(...);

$session = new Session();

$userRepository = new PdoUserRepository(
    $pdo
);

$rememberTokenRepository =
    new PdoRememberTokenRepository($pdo);

$resetTokenRepository =
    new PdoPasswordResetTokenRepository($pdo);

$verificationTokenRepository =
    new PdoVerificationTokenRepository($pdo);

$auth = new AuthService(
    $userRepository,
    $session
);

$rememberMe = new RememberMeService(
    $rememberTokenRepository,
    $userRepository,
    $auth
);

$registration = new RegistrationService(
    $userRepository
);

$passwordReset = new PasswordResetService(
    $userRepository,
    $resetTokenRepository,
    $pdo
);

$emailVerification =
    new EmailVerificationService(
        $userRepository,
        $verificationTokenRepository
    );
```

To je DI iz OOP modula u stvarnoj auth arhitekturi.

Klase dobijaju dependencies spolja.

Ne kreiraju ih same.

Na primer:


```text

```

```text

table structure
```

```text
DIP
+

```

na praktičnom primeru.

## 23. Transaction boundaries pripadaju use case-u

Primer Password Reset:

```text
update password
+
invalidate reset token
```

treba da budu atomic.

Zato:

```text
PasswordResetService
→ transaction boundary
```

Ne:

```text
UserRepository sam započne transaction
```

pa drugi repository nema isti lifecycle context.

Isti princip smo već koristili u BookingService-u:

```text
Service
→ orkestrira use case
→ odlučuje gde počinje/ završava transaction
```

Repository samo učestvuje koristeći isti PDO connection.
