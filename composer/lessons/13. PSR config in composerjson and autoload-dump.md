# 13. PSR config in composerjson and autoload-dump

## Lekcija 13/15 — PSR-4 konfiguracija u composer.json + composer dump-autoload

Do sada smo razumeli mentalni model:

```text
App\Services\BookingService
↓
src/Services/BookingService.php
```

Sada gledamo gde se to pravilo stvarno definiše i šta Composer radi kada kažeš:

```bash
composer dump-autoload
```

Najkraće:

autoload sekcija u composer.json definiše pravila učitavanja klasa,
a composer dump-autoload regeneriše Composer-ove autoload fajlove na osnovu tih pravila.

---

## 1. Osnovna PSR-4 konfiguracija

Naš MiniStay projekat:

```json
{
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    }
}
```

To znači:

```text
App\
→ src/
```

Pa:

```text
App\Services\BookingService
→ src/Services/BookingService.php
```

```text
App\Http\Request
→ src/Http/Request.php
```

```text
App\Enums\BookingStatus
→ src/Enums/BookingStatus.php
```

To već znaš.
Ali važna stvar je:

Composer mora da generiše svoju autoload konfiguraciju na osnovu ovog composer.json.

---

## 2. Šta se dešava nakon izmene composer.json?

Recimo projekat prvo ima samo:

```json
{
    "require": {
        "php": "^8.3"
    }
}
```

Onda ti ručno dodaš:

```json
"autoload": {
    "psr-4": {
        "App\\": "src/"
    }
}
```

---

## Samo čuvanje composer.json nije dovoljno da već generisani

Composer autoloader automatski zna za novu konfiguraciju.

Treba regenerisati autoload metadata:

```bash
composer dump-autoload
```

ili skraćeno:

composer dumpautoload

Najčešće ćeš viđati prvu varijantu.

---

## 3. Šta dump-autoload zapravo radi?

Ne instalira nove packages.
Ne radi dependency update.
Ne menja ti package verzije.
On praktično radi:

```text
pročitaj autoload konfiguraciju
↓
pročitaj autoload pravila dependencies
↓
regeneriši Composer autoload metadata
↓
osveži vendor/autoload.php infrastrukturu
```

Dakle:

```bash
composer dump-autoload
```

nije isto što i:

```bash
composer install
```

niti:

```bash
composer update
```

Mentalno:

```text
install
→ dependencies
```

```text
update
→ dependency resolution
```

```text
dump-autoload
→ autoload metadata
```

---

## 4. Kada ti stvarno treba dump-autoload?

Najjasniji slučaj:

Promenio si autoload konfiguraciju u composer.json.

Na primer:

Pre:

```json
"autoload": {
    "psr-4": {
        "App\\": "src/"
    }
}
```

Posle:

```json
"autoload": {
    "psr-4": {
        "App\\": "src/",
        "Domain\\": "domain/"
    }
}
```

Sada treba:

```bash
composer dump-autoload
```

da Composer registruje:

```text
Domain\
→ domain/
```

---

## 5. Ako samo dodaš novu PSR-4 klasu?

Ovo je jedna od važnijih praktičnih nijansi.
Recimo mapping već postoji:

```json
"App\\": "src/"
```

i sada samo napraviš:

src/Services/PaymentService.php

sa:

```php
<?php

namespace App\Services;

final class PaymentService
{
}
```

U normalnom PSR-4 autoload setup-u obično ne moraš da pokrećeš:

```bash
composer dump-autoload
```

samo zato što si dodao novu klasu.

---

## Zašto?

Jer Composer već zna pravilo:

```text
App\
→ src/
```

Kada PHP zatraži:

App\Services\PaymentService

Composer može iz tog pravila da izračuna:

src/Services/PaymentService.php

Dakle:

```text
nov PSR-4 class file
→ uglavnom ne zahteva dump-autoload
```

Ovo developeri često rade iz navike, ali nije uvek potrebno.

---

## 6. Kada dump-autoload jeste potreban?

Tipično kada menjaš:

```text
autoload.psr-4
autoload.classmap
autoload.files
autoload.exclude-from-classmap
autoload-dev
```

odnosno samu Composer autoload konfiguraciju.
Na primer:

```json
"autoload": {
    "psr-4": {
        "App\\": "app/"
    }
}
```

promeniš u:

```json
"autoload": {
    "psr-4": {
        "App\\": "src/"
    }
}
```

Obavezno želiš regeneraciju.

---

## 7. Šta se generiše u vendor/composer/?

Posle:

```bash
composer dump-autoload
```

Composer generiše ili ažurira fajlove kao:

```text
vendor/composer/
├── autoload_psr4.php
├── autoload_classmap.php
├── autoload_files.php
├── autoload_real.php
├── autoload_static.php
└── ClassLoader.php
```

Ne moraš da pamtiš tačna imena svih fajlova.
Važniji mentalni model:

```text
composer.json
↓
dump-autoload
↓
vendor/composer/* metadata
↓
vendor/autoload.php
↓
Composer ClassLoader
```

## 8. Primer sa više namespace-a

Recimo:

```json
{
    "autoload": {
        "psr-4": {
            "App\\": "src/",
            "Domain\\": "domain/",
            "Infrastructure\\": "infrastructure/"
        }
    }
}
```

Posle:

```bash
composer dump-autoload
```

Composer zna:

```text
App\Http\Request
→ src/Http/Request.php
```

```text
Domain\Booking\Booking
→ domain/Booking/Booking.php
```

```text
Infrastructure\Database\PdoBookingRepository
→ infrastructure/Database/PdoBookingRepository.php
```

Dakle autoload nije ograničen na jedan src/.

---

## 9. Šta ako mapping promeniš, ali ne pokreneš dump?

Recimo autoloader je generisan kada je bilo:

```json
"App\\": "src/"
```

A ti ručno promeniš na:

```json
"App\\": "app/"
```

i premestiš klase u:

app/

ali ne pokreneš regeneraciju.
Composer autoload metadata može i dalje imati staro pravilo:

```text
App\
→ src/
```

pa dobiješ:

Class "App\Services\BookingService" not found

iako fajl postoji u:

app/Services/BookingService.php

Tada je:

```bash
composer dump-autoload
```

upravo ono što želiš.
10. dump-autoload -o
Vrlo često ćeš videti:

```bash
composer dump-autoload -o
```

ili:

```bash
composer dump-autoload --optimize
```

-o znači:

Generiši optimized autoloader.

Composer tada pokušava da napravi efikasniji class map za PSR-4/PSR-0 klase koje može pronaći.
Mentalno:

```text
standard PSR-4
→ izračunaj filepath kada klasa zatreba
```

```text
optimized autoload
→ unapred napravi više class → filepath mapiranja
```

Na primer konceptualno:

```text
App\Services\BookingService
→ /project/src/Services/BookingService.php
```

```text
App\Http\Request
→ /project/src/Http/Request.php
```

To može smanjiti filesystem lookup tokom runtime-a.

---

## 11. Development vs production

U development-u je običan:

```bash
composer dump-autoload
```

često sasvim dovoljan.
Na production-u se često koristi optimized autoload:

```bash
composer install --no-dev --optimize-autoloader
```

ili nakon install-a:

```bash
composer dump-autoload -o
```

Cilj je runtime efikasnost.
Ali nemoj iz toga napraviti pravilo:

-o moram uvek lokalno.

Ne moraš.

---

## 12. Zašto optimized autoload može otkriti PSR-4 problem?

Recimo imaš:

src/services/BookingService.php

ali klasa je:

```php
namespace App\Services;
```

class BookingService {}

Pri optimizaciji Composer može skenirati klase i primetiti da se ne uklapaju u očekivanu PSR-4 strukturu.
Može prijaviti upozorenje nalik:

Class ... does not comply with psr-4 autoloading standard

To je veoma korisno.
Ne znači:

Composer se pokvario.

Nego:

Tvoj class name / namespace / filepath nisu konzistentni.

## 13. Tipičan problem iz realnog projekta

Recimo napraviš:

src/Services/Bookingservice.php

a unutra:

```php
namespace App\Services;
```

class BookingService {}

Na Windows-u ti možda nešto prolazi.
Pokreneš:

```bash
composer dump-autoload -o
```

i Composer upozori da klasa ne prati PSR-4 standard.
Problem je:

Bookingservice.php

vs:

BookingService.php

Jedno veliko S.
To je odličan način da rano uhvatiš problem pre Linux deployment-a.
14. dump-autoload ne popravlja pogrešan namespace
Ovo je važno.
Ako imaš:

src/Services/BookingService.php

ali unutra:

```php
namespace App\Service;
```

neće:

```bash
composer dump-autoload
```

magično ispraviti:

Service

u:

Services

Composer može regenerisati autoload metadata, ali ne može da popravi tvoj source design.
Dakle:

```text
Class not found
↓
dump-autoload
```

nije univerzalni lek.
Prvo proveravaš:

```text
namespace
filename
folder
class name
use
mapping
```

15. composer dump-autoload i dependencies
Recimo imaš:

```json
"require": {
    "monolog/monolog": "^3.0"
}
```

ali Monolog nije instaliran.
Ako uradiš samo:

```bash
composer dump-autoload
```

to nije zamena za:

```bash
composer install
```

dump-autoload neće rešiti činjenicu da dependency source nije tu.
Dakle:

```text
package missing
→ composer install
```

```text
autoload metadata outdated
→ composer dump-autoload
```

## 16. Kada install već radi dump?

Važno praktično pitanje.
Kada pokreneš:

```bash
composer install
```

Composer na kraju već generiše autoload fajlove.
Zato posle svežeg:

```bash
composer install
```

obično nema smisla odmah zatim raditi:

```bash
composer dump-autoload
```

bez ikakve dodatne promene.
Isto važi nakon mnogih Composer dependency operacija — Composer sam regeneriše autoloader.
Dakle:

```text
composer install
↓
autoload generation već urađena
```

Nemoj komande pokretati ritualno bez razumevanja.

## 17. Laravel composer dump-autoload navika

Sigurno si video savet:

```bash
composer dump-autoload
```

kada Laravel kaže:

Class not found

Ponekad zaista pomaže — naročito ako je autoload konfiguracija menjana.
Ali ako si samo napravio:

App\Services\BookingService

u:

app/Services/BookingService.php

a Laravel već ima:

```text
App\ → app/
```

problem verovatno nije to što nisi pokrenuo dump.
Možda si napisao:

```php
namespace App\Service;
```

umesto:

```php
namespace App\Services;
```

ili pogrešan use.
Zato želim da izađeš iz faze:

"Class not found?"

```text
→ composer dump-autoload 😄
```

u fazu:

"Class not found?"

```text
→ koji FQCN PHP traži?
→ koji PSR-4 prefix važi?
→ koji filepath Composer očekuje?
```

To je mnogo jači debugging mentalitet.

## 18. Autoload optimizacija nije isto što i application cache

Nemoj mešati:

```bash
composer dump-autoload -o
```

sa Laravel stvarima poput:

```text
config cache
route cache
view cache
```

Composer optimizuje:

class loading

Laravel cache komande optimizuju druge framework koncepte.
Dakle:

```text
Composer autoload optimization
≠ Laravel config/route caching
```
