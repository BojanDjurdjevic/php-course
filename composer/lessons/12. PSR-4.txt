Lekcija 12/15 — PSR-4 mental model: kako namespace postaje filepath

Najkraće:
PSR-4 definiše pravilo kako se fully qualified class name mapira na fajl u filesystem-u.

To je veza koju smo do sada stalno pominjali:
App\Services\BookingService
↓
src/Services/BookingService.php

Ali hajde sada precizno da vidimo zašto.
1. Namespace sam po sebi ne zna ništa o folderima
Ovo smo već rekli:
namespace App\Services;

class BookingService {}

PHP iz ovoga sam ne zna da fajl treba da bude u:
src/Services/BookingService.php

To može biti i:
banana/x.php

i PHP jezik sam po sebi nema problem sa tim.
Vezu pravi autoload konfiguracija.
Na primer:
"autoload": {
    "psr-4": {
        "App\\": "src/"
    }
}

Ovo znači:
namespace prefix:
App\

base directory:
src/

2. Kako Composer mapira klasu
Recimo PHP traži:
App\Services\BookingService

Composer ima:
App\ → src/

Prvi deo:
App\

odseče.
Ostaje:
Services\BookingService

Namespace separatori:
\

pretvaraju se u directory separatore:
/

dobijamo:
Services/BookingService

i dodaje se:
.php

pa konačno:
src/Services/BookingService.php

To je cela ideja.
3. Formula
Ako imamo:
Prefix:
App\

Base directory:
src/

onda:
App\X\Y\Z

postaje:
src/X/Y/Z.php

Na primer:
App\Http\Request
→ src/Http/Request.php

App\Repositories\PdoBookingRepository
→ src/Repositories/PdoBookingRepository.php

App\DTO\CreateBookingData
→ src/DTO/CreateBookingData.php

App\Enums\BookingStatus
→ src/Enums/BookingStatus.php

4. Prefix se ne preslikava kao folder
Ovo je važna stvar.
Ako imamo:
"App\\": "src/"

onda:
App\Services\BookingService

nije:
src/App/Services/BookingService.php

nego:
src/Services/BookingService.php

Zašto?
Jer:
App\

je već mapiran na:
src/

Dakle prefix se zameni base folderom.
Mentalno:
App\
↓
src/

pa ostatak namespace-a nastavlja ispod njega.
5. Realan primer
composer.json:
{
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    }
}

Fajl:
src/Services/BookingService.php

unutra:
<?php

namespace App\Services;

final class BookingService
{
}

To se savršeno poklapa:
App\          → src/
Services\     → Services/
BookingService → BookingService.php

6. Ako se namespace ne poklapa
Recimo fajl je:
src/Services/BookingService.php

ali unutra piše:
namespace App\Controllers;

class BookingService {}

Composer traži:
App\Controllers\BookingService

i po PSR-4 pravilu očekuje:
src/Controllers/BookingService.php

Ali fajl ti je:
src/Services/BookingService.php

Dakle mapping je razbijen.
Možeš dobiti:
Class not found

ili Composer warning kada generiše optimized autoload.
7. Ako je filename pogrešan
Recimo:
namespace App\Services;

class BookingService {}

ali fajl se zove:
src/Services/Booking.php

PSR-4 očekuje:
BookingService.php

jer ime klase mora odgovarati očekivanom filepath-u.
Dakle:
class BookingService
→ BookingService.php

8. Case sensitivity
Ovo je jako praktično.
Ako klasa kaže:
class BookingService

PSR-4 očekuje:
BookingService.php

ne:
bookingservice.php

ili:
bookingService.php

Na Windows-u nešto može slučajno proći zbog case-insensitive filesystem-a.
Na Linux produkciji:
BookingService.php
≠ bookingservice.php

i aplikacija pukne.
Zato u PHP projektima navika:
namespace case
folder case
class case
filename case

treba da bude konzistentna.
9. Jedna klasa po fajlu
PSR-4 prirodno vodi ka:
jedna glavna klasa
→ jedan fajl

Na primer:
src/Services/BookingService.php

sadrži:
class BookingService

Tehnički PHP može imati više klasa u istom fajlu, 
ali za PSR-4 autoloadable code to uglavnom nije dobar obrazac.

Jer autoloader traži fajl prema imenu konkretne klase.
10. Interface, enum i trait takođe mogu pratiti PSR-4
Nije samo za class.
Na primer:
namespace App\Contracts;

interface PaymentGateway {}

ide prirodno u:
src/Contracts/PaymentGateway.php

Enum:
namespace App\Enums;

enum BookingStatus: string {}

ide u:
src/Enums/BookingStatus.php

Trait:
namespace App\Traits;

trait LogsActivity {}

ide u:
src/Traits/LogsActivity.php

Dakle PSR-4 mapira class-like symbols kroz namespace/name strukturu.
11. Možemo imati više namespace prefix-a
Na primer:
"autoload": {
    "psr-4": {
        "App\\": "src/",
        "Domain\\": "domain/",
        "Infrastructure\\": "infrastructure/"
    }
}

Onda:
App\Http\Request
→ src/Http/Request.php

Domain\Booking\Booking
→ domain/Booking/Booking.php

Infrastructure\Database\PdoBookingRepository
→ infrastructure/Database/PdoBookingRepository.php

Dakle jedan projekat može imati više mapping-a.
12. Jedan prefix može mapirati i na više foldera
Composer podržava i ovakav stil:
"autoload": {
    "psr-4": {
        "App\\": [
            "src/",
            "legacy-src/"
        ]
    }
}

Composer onda može tražiti kroz više base directories za isti prefix.
To postoji, ali za čist novi projekat mnogo je jednostavnije:
App\ → src/

13. Najduži odgovarajući prefix ima prednost
Recimo:
"autoload": {
    "psr-4": {
        "App\\": "src/",
        "App\\Admin\\": "admin/"
    }
}

Za:
App\Admin\UserController

specifičniji prefix:
App\Admin\

ima više smisla nego opšti:
App\

pa mapping vodi ka:
admin/UserController.php

Ovo je korisno kada namespace tree ima različite physical roots.
14. PSR-4 nije Composer-only standard
PSR-4 je PHP-FIG standard.
Composer ga vrlo često implementira i generiše autoloader prema njemu.
Dakle:
PSR-4
→ standard/convention

Composer
→ alat koji ga praktično koristi

Nemoj mešati:
PSR-4 = Composer

Composer podržava PSR-4, ali PSR-4 nije Composer feature 
u smislu da je Composer izmislio standard samo za sebe.
15. Šta znači PSR?
PSR = PHP Standards Recommendation.
Dolazi iz PHP-FIG zajednice.
Postoje različiti PSR standardi, na primer:
PSR-3
→ logging interface

PSR-4
→ autoloading

PSR-7
→ HTTP message interfaces

PSR-11
→ container interface

Nama je sada fokus:
PSR-4

jer direktno povezuje namespace i autoload.
16. Kako se Composer autoload aktivira
Imamo:
"autoload": {
    "psr-4": {
        "App\\": "src/"
    }
}

Composer generiše svoj autoload metadata.
A aplikacija radi:
require __DIR__ . '/../vendor/autoload.php';

Sada kada napišeš:
use App\Services\BookingService;

$service = new BookingService();

tok je:
PHP traži:
App\Services\BookingService

↓ autoloader

Composer vidi:
App\ → src/

↓ ukloni prefix

Services\BookingService

↓ namespace separator → path

Services/BookingService.php

↓ dodaj base path

src/Services/BookingService.php

↓ require file

To je PSR-4 u praksi.
17. Class not found iako fajl postoji
Ovo je veoma čest problem.
Recimo fajl fizički postoji:
src/services/BookingService.php

a namespace je:
namespace App\Services;

Composer očekuje:
src/Services/BookingService.php

Na Linux-u:
services
≠
Services

Dakle fajl postoji, ali ne na mestu koje mapping očekuje.
Zato poruka:
Class not found

ne znači uvek:
Fajl ne postoji.

Može značiti:
Autoloader ne može da ga pronađe prema pravilima koja si mu dao.

18. Drugi tipičan problem — pogrešan namespace
Struktura:
src/Services/BookingService.php

ali unutra:
namespace App\Service;

singular:
Service

umesto:
Services

Autoloader je možda otvorio fajl očekujući:
App\Services\BookingService

ali fajl definiše:
App\Service\BookingService

To nije ista klasa.
Jedno slovo je dovoljno da pukne.
19. Treći tipičan problem — pogrešan use
Fajl je savršen:
src/Services/BookingService.php

namespace:
namespace App\Services;

ali u controller-u napišeš:
use App\Service\BookingService;

opet tražiš nepostojeći FQCN.
Dakle pri debug-u autoload problema proveravaš:
1. composer.json prefix
2. base folder
3. namespace u fajlu
4. folder strukturu
5. class name
6. filename
7. use/FQCN
8. case sensitivity

To je praktična checklist-a.
20. Kako bi izgledao naš OOP kod iz prethodnog modula
Pre smo sve mogli imati u jednom fajlu:
oop.php

Sada:
src/
├── Contracts/
│   └── BookingRepository.php
├── Controllers/
│   └── BookingController.php
├── DTO/
│   └── CreateBookingData.php
├── Enums/
│   └── BookingStatus.php
├── Http/
│   ├── Request.php
│   └── CreateBookingRequest.php
├── Models/
│   └── Booking.php
├── Repositories/
│   └── InMemoryBookingRepository.php
└── Services/
    └── BookingService.php

composer.json:
{
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    }
}

I svaka klasa dobije odgovarajući namespace.
Na primer:
namespace App\Services;

ili:
namespace App\Http;

ili:
namespace App\DTO;

Ovo već izgleda kao pravi profesionalni PHP projekat.
21. Zašto je ovo mnogo bolje od ručnog require
Bez PSR-4:
require 'src/Models/Booking.php';
require 'src/DTO/CreateBookingData.php';
require 'src/Repositories/BookingRepository.php';
require 'src/Services/BookingService.php';
require 'src/Controllers/BookingController.php';

Sa PSR-4:
require 'vendor/autoload.php';

i gotovo.
Autoload sistem rešava ostalo po potrebi.
To znači:
manje boilerplate-a
manje problema sa redosledom include-a
jasniju strukturu
skalabilniji projekat
standardan PHP ecosystem način rada

22. Laravel paralela
Laravel defaultno koristi veoma sličan mentalni model:
App\
→ app/

Zato:
App\Models\User

ide prirodno u:
app/Models/User.php

A:
App\Http\Controllers\BookingController

u:
app/Http/Controllers/BookingController.php

Ti si dakle PSR-4 koristio sve vreme u Laravelu.
Samo framework scaffolding i Composer su ti sakrili mentalni mehanizam.
23. PSR-4 ne kaže kako treba da organizuješ arhitekturu
PSR-4 ti ne kaže:
moraš imati:
Services/
Repositories/
DTO/
Controllers/

To je tvoja architectural organization.

PSR-4 samo kaže, uprošćeno:
Ako si definisao namespace prefix i base directory, 
ostatak class name-a treba predvidljivo da prati directory/file strukturu.

Dakle:
PSR-4
→ mapping pravilo

arhitektura
→ tvoja odluka

24. Mentalna formula za debugging
Ako vidiš:
Class "App\Services\BookingService" not found

nemoj paničiti.
Rastavi:
Tražena klasa:
App\Services\BookingService

Mapping:
App\ → src/

Oduzmi prefix:
Services\BookingService

Pretvori u path:
Services/BookingService.php

Dodaj base dir:
src/Services/BookingService.php

I onda proveri:
Da li taj fajl postoji?
Da li case odgovara?
Da li unutra definiše baš:
App\Services\BookingService?

To je gotovo cela dijagnostika.
Najvažnija mentalna mapa Lekcije 12
composer.json:

App\ → src/

PHP traži:

App\Services\BookingService

↓ ukloni App\

Services\BookingService

↓ \ → /

Services/BookingService

↓ + .php

Services/BookingService.php

↓ + src/

src/Services/BookingService.php

I zapamti četiri različita sloja:
namespace
→ identitet klase

PSR-4
→ pravilo mapiranja

Composer autoloader
→ koristi to pravilo

filesystem
→ mesto gde fajl stvarno mora da bude

Ako se bilo koji od ta četiri sloja ne poklopi, dobijaš autoload problem.
