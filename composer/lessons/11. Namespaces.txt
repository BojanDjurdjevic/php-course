Lekcija 11/15 — Namespaces: FQCN, use, aliasing i name resolution

Ovo je bitno jer namespace nije samo organizacija foldera — on je deo identiteta klase.

Najkraće:
namespace
→ gde klasa pripada

use
→ koje puno ime želim da koristim kraće

FQCN
→ puno, jednoznačno ime klase

1. Dve klase mogu imati isto kratko ime
Recimo:
namespace App\Models;

class User {}

i:
namespace Vendor\Package;

class User {}

Obe se zovu:
User

ali njihova puna imena su:
App\Models\User

Vendor\Package\User

To su dve potpuno različite klase.
Dakle kratko ime:
User

nije uvek dovoljno da jednoznačno odredi klasu.
2. FQCN — Fully Qualified Class Name
Puno ime klase:
App\Models\User

nazivamo Fully Qualified Class Name.
U PHP kodu apsolutno ime možeš napisati sa početnim backslash-om:
$user = new \App\Models\User();

Početni:
\

znači:
Kreni od globalnog/root namespace-a.

Mentalno:
\App\Models\User
→ apsolutno puno ime

U stringovima/reflection kontekstu često ćeš videti i zapis bez početnog \, 
ali u source-code name resolution-u ovaj vodeći backslash eksplicitno znači fully qualified ime.

3. Trenutni namespace
Ako fajl ima:
namespace App\Services;

i napišeš:
class BookingService {}

puno ime te klase je:
App\Services\BookingService

Dakle:
namespace App\Services;

class BookingService {}

je praktično definicija klase:
App\Services\BookingService

Namespace je deo identiteta.
4. Šta ako unutar namespace-a napišem samo ime klase?
Recimo:
namespace App\Services;

class BookingService
{
    public function create(): Booking
    {
    }
}

PHP mora da odluči šta znači:
Booking

Ako nema odgovarajući use, PHP će to ime posmatrati u kontekstu trenutnog namespace-a.
Dakle može pokušati:
App\Services\Booking

a možda si zapravo mislio:
App\Models\Booking

Zato pišemo:
use App\Models\Booking;

pa:
public function create(): Booking

sada znači:
App\Models\Booking

5. use
Primer:
namespace App\Controllers;

use App\Services\BookingService;

class BookingController
{
    public function __construct(
        private BookingService $service
    ) {}
}

use kaže:
U ovom fajlu, kada kažem BookingService, mislim na App\Services\BookingService.

To nije dependency injection.
To nije autoload.
To nije instanciranje.
To je name import / aliasing.
6. use ne učitava klasu
Ovo je baš važna nijansa.
Ovo:
use App\Services\BookingService;

ne znači:
require 'src/Services/BookingService.php';

use samo uređuje kako PHP tumači ime:
BookingService

Kasnije, kada PHP zaista mora da koristi tu klasu:
new BookingService();

autoload može da pronađe fajl.
Dakle:
use
→ name resolution

autoload
→ file loading

7. Bez use
Možemo da napišemo:
$service = new \App\Services\BookingService();

i to je sasvim validno.
Ali zamisli kod:
public function __construct(
    private \App\Services\BookingService $service,
    private \App\Repositories\BookingRepository $repository,
    private \App\Contracts\PaymentGateway $gateway
) {}

radi, ali je bučno.
Zato:
use App\Services\BookingService;
use App\Repositories\BookingRepository;
use App\Contracts\PaymentGateway;

pa:
public function __construct(
    private BookingService $service,
    private BookingRepository $repository,
    private PaymentGateway $gateway
) {}

mnogo je čitljivije.
8. Aliasing sa as
Ako imamo dve klase istog kratkog imena:
use App\Models\User;
use Vendor\Package\User;

PHP ne može obe da uveze kao:
User

u istom fajlu.
Zato:
use App\Models\User;
use Vendor\Package\User as VendorUser;

pa:
$appUser = new User();
$vendorUser = new VendorUser();

Mentalno:
App\Models\User
→ User

Vendor\Package\User
→ VendorUser

Alias postoji samo u tom fajlu.
Ne preimenuje stvarnu klasu.
9. Alias možeš koristiti i kada nema konflikta
Na primer:
use Very\Long\Infrastructure\Persistence\PdoBookingRepository as BookingRepo;

pa:
$repo = new BookingRepo();

Tehnički može.
Ali nemoj preterivati sa aliasima samo radi skraćivanja.
Dobar alias treba da poveća jasnoću, ne da sakrije pravo značenje klase.
10. Tri tipa class name-a
PHP praktično razlikuje tri korisna oblika.
Fully qualified
new \App\Services\BookingService();

Počinje sa \.
To je apsolutno ime.
Qualified
new Services\BookingService();

Ima namespace separator, ali nema početni \.
Tumači se relativno prema trenutnom namespace-u, osim ako import/rezolucija ne nalaže drugačije.
Unqualified
new BookingService();

Samo kratko ime.
PHP gleda use import, a zatim trenutni namespace u skladu sa pravilima rezolucije.
Za svakodnevni application code najčešće koristiš:
use FQCN
+
kratko ime u ostatku fajla

11. Primer relativnog qualified name-a
Recimo:
namespace App;

new Services\BookingService();

Bez importa, ovo se konceptualno rezolvuje kao:
App\Services\BookingService

jer je ime relativno trenutnom:
App

Ali ovo:
new \Services\BookingService();

je potpuno druga stvar:
Services\BookingService

iz root namespace-a.
Početni \ menja značenje.
12. Namespace nije folder
Ovo ponavljamo jer je mnogo važno.
Možeš fizički imati:
banana/Test.php

a unutra:
namespace App\Services;

class BookingService {}

PHP jezički ne kaže da je to zabranjeno.
Namespace:
App\Services

nije filesystem path.
Vezu:
App\Services\BookingService
→ src/Services/BookingService.php

kasnije pravi PSR-4 autoload konfiguracija.
Dakle:
namespace
→ logical class identity

PSR-4
→ convention/mapping ka filesystem-u

Sledeća lekcija je upravo tome posvećena.
13. namespace deklaracija
Tipično je vrlo rano u fajlu:
<?php

namespace App\Services;

use App\Repositories\BookingRepository;

final class BookingService
{
}

Praktičan standardni raspored:
<?php

namespace ...

use ...
use ...

class ...

To ćeš viđati svuda u Laravel/PHP kodu.
14. Global namespace
Ako fajl nema:
namespace ...

onda je u globalnom namespace-u.
Recimo built-in klase:
PDO
DateTimeImmutable
RuntimeException

žive u globalnom namespace-u.
Ako si unutar:
namespace App\Services;

i napišeš:
new DateTimeImmutable();

PHP ima posebna name-resolution pravila za klase/import-e; u praksi često ćeš videti eksplicitno:
use DateTimeImmutable;

pa koristiti:
new DateTimeImmutable();

ili direktno:
new \DateTimeImmutable();

Oba pristupa mogu jasno pokazati da misliš na globalnu klasu.
15. Built-in exceptions i use
U Laravel kodu često vidiš:
use RuntimeException;
use Throwable;

pa:
catch (Throwable $e)

Zašto import?
Jer trenutni fajl je možda:
namespace App\Services;

a želimo globalni:
Throwable

Import čini nameru eksplicitnom i kod konzistentnim.
16. ::class
Ovo je veoma korisno.
Ako imaš:
use App\Services\BookingService;

onda:
BookingService::class

daje string punog class name-a:
App\Services\BookingService

Ne:
BookingService

nego FQCN string.
To se mnogo koristi u Laravel-u:
BookingStatus::class
PaymentGateway::class
BookingService::class

Na primer container binding:
$this->app->bind(
    PaymentGateway::class,
    StripeGateway::class
);

Ovde ::class daje jednoznačan class/interface identifier.
17. Za ::class ne moraš imati objekat
Ne treba:
$service = new BookingService();
$service::class;

Možeš direktno:
BookingService::class;

To nije poziv static metode.
`
::class` je language construct za dobijanje class name string-a.
18. Namespace i interface/enum/trait
Namespaces nisu samo za klase.
Možeš imati:
namespace App\Contracts;

interface PaymentGateway {}

namespace App\Enums;

enum BookingStatus: string {}

namespace App\Traits;

trait LogsActivity {}

Dakle namespace može organizovati:
classes
interfaces
traits
enums
functions
constants

Nama su trenutno najvažniji OOP tipovi.
19. Jedan realan primer
BookingService.php:
<?php

namespace App\Services;

use App\DTO\CreateBookingData;
use App\Models\Booking;
use App\Repositories\BookingRepository;

final class BookingService
{
    public function __construct(
        private BookingRepository $bookings
    ) {}

    public function create(
        CreateBookingData $data
    ): Booking {
        // ...
    }
}

Pogledaj koliko informacija odmah vidiš:
ova klasa JE:
App\Services\BookingService

koristi:
App\DTO\CreateBookingData
App\Models\Booking
App\Repositories\BookingRepository

Veoma jasna arhitektura.
20. Name collision u realnom svetu
Recimo Laravel ima:
Illuminate\Http\Request

a ti napraviš:
App\Http\Request

U istom fajlu možda trebaš oba.
Možeš:
use Illuminate\Http\Request;
use App\Http\Request as AppRequest;

pa:
public function handle(
    Request $httpRequest,
    AppRequest $applicationRequest
) {}

Tehnički rešeno.
Ali ako ti se takvi konflikti često dešavaju, 
možda je i naming signal da arhitektura može biti jasnija.

21. use function i use const
PHP može importovati i funkcije/constants:
use function Some\Namespace\helper;
use const Some\Namespace\SOME_VALUE;

Postoji i grupisani import.
To treba da znaš da postoji, ali nije centralno za naš Composer/OOP kurs.
Nećemo od toga praviti posebnu lekciju.
22. Grouped imports
Možeš videti:
use App\Models\{Booking, Hotel, User};

umesto:
use App\Models\Booking;
use App\Models\Hotel;
use App\Models\User;

Oba su validna.
Meni je za application code često pojedinačni use čitljiviji, ali to je stil.
23. Case sensitivity — oprez
PHP class name lookup ume da bude forgiving u nekim kontekstima, 
ali PSR-4/file systems mogu biti mnogo manje forgiving, naročito Linux server.

Ako fajl kaže:
BookingService.php

a mapping očekuje baš takav case, nemoj lokalno na Windows-u razvijati naviku da pišeš:
bookingservice.php

pa očekivati da Linux produkcija proguta isto.
Za PSR-4 želimo konzistentno:
namespace segment
class name
file name
directory case

To ćemo dodatno naglasiti u sledećoj lekciji.
24. Kako se ovo povezuje sa autoloadom?
Recimo:
use App\Services\BookingService;

$service = new BookingService();

Koraci su konceptualno:
use
↓
PHP zna da BookingService znači
App\Services\BookingService

new BookingService()
↓
PHP treba klasu
App\Services\BookingService

klasa nije učitana
↓
Composer autoloader

PSR-4 mapping:
App\ → src/

↓
src/Services/BookingService.php

↓
require file

↓
new instance

To je kompletan mentalni tok.
Najvažnija mapa Lekcije 11
namespace App\Services;
→ ova klasa pripada App\Services

use App\Models\Booking;
→ Booking u ovom fajlu znači App\Models\Booking

\App\Models\Booking
→ fully qualified / absolute ime

Booking::class
→ "App\Models\Booking"

I posebno:
namespace
≠ folder

use
≠ require

use
≠ dependency injection

autoload
≠ object creation

Već:
namespace
→ identity

use
→ name resolution

PSR-4
→ class-to-file mapping

autoload
→ file loading

new
→ instance creation

Ako ovo razumeš, sledeća lekcija će biti mnogo lakša.
