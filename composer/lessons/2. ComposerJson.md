# 2. ComposerJson

## Lekcija 2/15 — composer.json: šta predstavlja i kako je strukturisan

Najkraće:

composer.json je glavni konfiguracioni fajl Composer projekta.

On opisuje:

```text
ko je projekat
šta mu treba
kako se autoloaduju klase
koji scripts se mogu izvršiti
koji PHP/extensions zahtevi postoje
```

Mentalno:

```text
composer.json
→ deklaracija namere projekta
```

Nije snapshot konkretno instaliranih verzija — za to služi composer.lock.

---

## Minimalan primer

Recimo naš budući Vanilla PHP projekat:

```json
{
    "name": "bojan/ministay",
    "description": "Vanilla PHP booking application",
    "type": "project",
    "require": {
        "php": "^8.3"
    },
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    }
}
```

I sada hajde polje po polje.
name

```json
"name": "bojan/ministay"
```

Composer package ime obično ima format:

vendor/package

Dakle:

```text
bojan
→ vendor / author / organization
```

```text
ministay
→ package/project name
```

Kod javnog paketa to ime je važno jer drugi mogu uraditi:

```bash
composer require bojan/ministay
```

Za običnu aplikaciju koja neće biti objavljena kao library,
name i dalje može biti korisna metadata.

Važno: ovo nema veze sa PHP namespace-om:

```php
namespace App\Services;
```

To su dve potpuno različite stvari.
description

```json
"description": "Vanilla PHP booking application"
```

Samo metadata.
Ne utiče na runtime aplikacije.
Isto važi i za polja poput:

```json
"license": "MIT"
```

ili:

```json
"authors": [
    {
        "name": "Bojan"
    }
]
```

Korisno za package metadata, ali nije srž dependency management-a.
type

```json
"type": "project"
```

Govori Composer ekosistemu kakva je vrsta paketa.
Česte vrednosti su:

```text
library
project
metapackage
composer-plugin
```

Za našu aplikaciju:

```json
"type": "project"
```

ima smisla.
Biblioteka koju drugi instaliraju bi češće bila:

```json
"type": "library"
```

Ali ovo polje ne pretvara automatski kod u aplikaciju ili library.
To je metadata/semantika za Composer ekosistem.

require

Ovo je jedno od najvažnijih polja:

```json
"require": {
    "php": "^8.3",
    "monolog/monolog": "^3.0"
}
```

Kaže:

Ovi dependencies su potrebni da aplikacija radi.

Ovde imamo dve vrste requirement-a:

```text
php
→ platform requirement
```

```text
monolog/monolog
→ package dependency
```

Možeš imati i PHP extensions:

```json
"require": {
    "php": "^8.3",
    "ext-pdo": "*",
    "ext-mbstring": "*"
}
```

To znači:

Projekat očekuje da environment ima PDO i mbstring.

Composer neće magično instalirati PHP extension na OS-u.
On proverava da requirement postoji.

require-dev

Primer:

```json
"require-dev": {
    "phpunit/phpunit": "^12.0"
}
```

Ovo znači:

Dependency mi treba za development/testiranje,
ali nije potreban produkcionom runtime-u aplikacije.

Tipični primeri:

```text
PHPUnit
PHPStan
Psalm
code style alati
debug tooling
```

---

## Kasnije ćemo imati posebnu lekciju za require vs require-dev,

jer tu postoji važna produkciona priča sa:

```bash
composer install --no-dev
```

Za sada samo:

```text
require
→ runtime dependency
```

```text
require-dev
→ development dependency
```

autoload
Ovo je za nas ogromno:

```json
"autoload": {
    "psr-4": {
        "App\\": "src/"
    }
}
```

To kaže Composer-u:

namespace prefix:

App\

fizički folder:

src/

Dakle:

App\Services\BookingService

mapira se konceptualno na:

src/Services/BookingService.php

A:

App\Http\Request

na:

src/Http/Request.php

Ovo ćemo duboko raditi u PSR-4 lekcijama. Za sada je najvažnije:

autoload opisuje kako Composer može pronaći naše klase.

---

## Escape backslash-a u JSON-u

Ovo je mala, ali važna stvar.
U PHP namespace-u napišeš:

App\Services

Ali u JSON string-u backslash mora biti escaped:

```json
"App\\": "src/"
```

Dakle:

PHP:

App\

JSON:

App\\

Nisu dva namespace separatora — to je samo JSON escape syntax.
autoload-dev
Možeš imati i:

```json
"autoload-dev": {
    "psr-4": {
        "Tests\\": "tests/"
    }
}
```

To je vrlo prirodno:

```text
src/
→ production/application code
```

```text
tests/
→ test classes
```

pa:

```php
namespace Tests\Unit;
```

Composer zna da ga traži unutar tests/.
Detaljnije ćemo u Lekciji 14.
scripts
Composer može imati custom commands/events:

```json
"scripts": {
    "test": "phpunit"
}
```

Tada možeš:

composer test

umesto direktno:

vendor/bin/phpunit

Možeš imati i event hooks, recimo posle autoload generation-a ili instalacije dependencies.
Laravel composer.json koristi scripts dosta intenzivnije.
Bitna mentalna razlika:

```text
require
→ dependencies
```

```text
autoload
→ kako nalazim klase
```

```text
scripts
→ koje komande/hook-ove Composer može pokretati
```

config
Može sadržati Composer ponašanje.
Na primer:

```json
"config": {
    "sort-packages": true
}
```

To kaže Composer-u da sortira dependencies u fajlu.

Postoji mnogo drugih opcija, ali nećemo od config praviti enciklopediju.
Fokusiraćemo se samo na praktično važne stvari kada dođu na red.

minimum-stability i prefer-stable
Možda ćeš ovo nekad videti:

```json
"minimum-stability": "stable",
```

```json
"prefer-stable": true
```

To utiče na to koje stability nivoe paketa Composer prihvata:

```text
dev
alpha
beta
RC
stable
```

Ali za većinu normalnih projekata nema potrebe da ovo diraš bez konkretnog razloga.
Default ponašanje je uglavnom sasvim dovoljno.
repositories
Composer po defaultu koristi Packagist, ali možeš definisati i dodatne izvore:

```json
"repositories": [
    {
        "type": "vcs",
        "url": "https://github.com/example/private-package"
    }
]
```

To je korisno za private ili custom pakete.
Za naš kurs nije core tema, ali treba da znaš da Composer nije ograničen samo na Packagist.

---

## Kako Composer koristi composer.json

Kada pokreneš komandu poput:

```bash
composer install
```

Composer otprilike radi:

```text
pročitaj composer.json
↓
pogledaj requirements
↓
pogledaj composer.lock ako postoji
↓
proveri platform requirements
↓
instaliraj potrebne packages
↓
generiši autoload
```

Kod:

```bash
composer update
```

priča je drugačija jer ponovo rešava version constraints i menja lock snapshot. To ćemo posebno.

---

## Ručno menjanje ili composer require?

Možeš ručno napisati:

```json
"require": {
    "monolog/monolog": "^3.0"
}
```

pa pokrenuti odgovarajuću Composer komandu.
Ali češće ćeš uraditi:

```bash
composer require monolog/monolog
```

Composer onda:

```text
izmeni composer.json
↓
resolve dependencies
↓
instalira paket
↓
izmeni composer.lock
```

Dakle Composer nije samo reader composer.json fajla — njegove komande ga često i automatski održavaju.

---

## Važna razlika: JSON syntax

Pošto je ovo JSON, ne možeš pisati kao PHP array.
Validno:

```json
{
    "require": {
        "php": "^8.3"
    }
}
```

Nije validno:

```json
{
    'require': {
        'php': '^8.3',
    }
}
```

JSON koristi:

```text
double quotes
bez trailing comma
```

To je česta banalna greška kad se ručno menja fajl.

## Naš budući Composer fajl

Za naš mali booking projekat početna verzija bi mogla biti:

```json
{
    "name": "bojan/ministay",
    "description": "Vanilla PHP booking application",
    "type": "project",
    "require": {
        "php": "^8.3",
        "ext-pdo": "*"
    },
    "autoload": {
        "psr-4": {
            "App\\": "src/"
        }
    }
}
```

Kasnije možemo dodati:

```json
"require-dev": {
    "phpunit/phpunit": "^12.0"
}
```

i:

```json
"autoload-dev": {
    "psr-4": {
        "Tests\\": "tests/"
    }
}
```

Tada već imamo veoma realan Composer projekat.
Najvažnija mentalna mapa

```text
composer.json
│
├── name
│   → identitet package-a/projekta
│
├── require
│   → production/runtime dependencies
│
├── require-dev
│   → development dependencies
│
├── autoload
│   → production class loading rules
│
├── autoload-dev
│   → dev/test class loading rules
│
├── scripts
│   → Composer commands/hooks
│
└── config
    → Composer behavior
```

I najbitnije:

```text
composer.json
→ šta projekat ZAHTEVA i kako je KONFIGURISAN
```

```text
composer.lock
→ koje KONKRETNE verzije su resolved
```

To ćemo uskoro dodatno produbiti.
