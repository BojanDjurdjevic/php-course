# 6. Response Object, Redirects & HTTP Output

## 1. Problem sa `echo`, `header()` i `exit`

U prostom PHP-u često imamo:

```php
if (!$user) {
    http_response_code(404);

    echo 'User not found';

    exit;
}
```

ili:

```php
header(
    'Location: /login'
);

exit;
```

ili:

```php
header(
    'Content-Type: application/json'
);

echo json_encode($data);

exit;
```

Sve ovo radi.

Ali Controller sada direktno:

```text
menja globalni HTTP state
šalje output
prekida PHP execution
```

To otežava:

```text
testiranje
middleware
centralno error handling ponašanje
response transformacije
jasan request lifecycle
```

---

# 2. Response kao objekat

Umesto da Controller odmah šalje response browser-u:

```text
Controller
↓
header()
↓
echo
↓
exit
```

Controller može da napravi:

```php
$response = new Response(
    body: 'Hello',
    status: 200,
    headers: [
        'Content-Type' =>
            'text/plain; charset=UTF-8',
    ]
);
```

i jednostavno:

```php
return $response;
```

Tek Front Controller na kraju radi:

```php
$response->send();
```

Mentalno:

```text
Controller
↓
RETURN RESPONSE OBJECT
↓
Application / Front Controller
↓
SEND
↓
Browser
```

---

# 3. HTTP response ima tri glavna dela

Response možemo posmatrati kao:

```text
STATUS
+
HEADERS
+
BODY
```

Na primer:

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8

<h1>Hello</h1>
```

Dakle naš `Response` object prirodno treba da predstavlja:

```text
status
headers
body
```

---

# 4. Minimalni Response

Možemo imati:

```php
final class Response
{
    public function __construct(
        private string $body = '',
        private int $status = 200,
        private array $headers = []
    ) {}

    public function body(): string
    {
        return $this->body;
    }

    public function status(): int
    {
        return $this->status;
    }

    public function headers(): array
    {
        return $this->headers;
    }
}
```

Sada imamo običan PHP object.

Još ništa nije poslato client-u.

---

# 5. Zašto je to važno

Ako Controller vrati:

```php
return new Response(
    'Booking created',
    201
);
```

test može da proveri:

```php
$response->status();
$response->body();
```

bez pravog browser-a.

Ne moramo da hvatamo:

```text
echo output
headers sent
exit()
```

To je velika prednost.

---

# 6. `send()`

Na kraju response mora ipak postati pravi HTTP output.

Na primer:

```php
public function send(): void
{
    http_response_code(
        $this->status
    );

    foreach (
        $this->headers
        as $name => $value
    ) {
        header(
            $name . ': ' . $value
        );
    }

    echo $this->body;
}
```

Front Controller:

```php
$response =
    $app->handle($request);

$response->send();
```

Sada samo jedno mesto u aplikaciji stvarno šalje response.

---

# 7. Controller više ne mora da `exit`

Loše:

```php
header(
    'Location: /bookings'
);

exit;
```

Bolje:

```php
return Response::redirect(
    '/bookings'
);
```

Controller završi prirodno:

```text
return
```

Ne prekida ceo PHP execution globalnim:

```text
exit
```

To daje mnogo čistiji control flow.

# 8. HTML response

Možemo imati helper:

```php
public static function html(
    string $html,
    int $status = 200

    return new self(
        body: $html,
        status: $status,
        headers: [
            'Content-Type' =>
                'text/html; charset=UTF-8',

```


Kasnije View Renderer generiše HTML.

# 10. JSON response

Za API:

```php
public static function json(
    array $data,
    int $status = 200
): self {
    return new self(
        body: json_encode(
            $data,
            JSON_THROW_ON_ERROR
        ),
        status: $status,
        headers: [
            'Content-Type' =>
                'application/json',
        ]
    );
}
```

```php
return Response::json([
    'id' => 42,
    'status' => 'confirmed',
]);
```

Opet Controller ne mora da radi:

```php
header(...);
echo json_encode(...);
exit;
```

# 12. Status code je deo response semantike

Primer:

```text
200 OK
```

znači:

```text

```

Ali različite situacije zaslužuju različite status codes.

Na primer:

```text

201 Created
204 No Content
303 See Other
400 Bad Request
401 Unauthorized
403 Forbidden

```



Koristimo za uspešan normalan response.

# 14. `201 Created`

Ako API kreira novi resource:

```text

```

može vratiti:

```text

```

Na primer:

```php

    [

```

# 15. `204 No Content`

Kada operacija uspe, ali nema body-ja:

```php

    body: '',
    status: 204
);
```

Na primer API delete može vratiti:

```text
204 No Content
```

Kod 204 response-a ne treba imati response body.

# 16. Redirect je HTTP response

Redirect nije neka posebna PHP magija.

To je samo response sa:

```text
3xx status
+
Location header
```

Na primer:

```http
HTTP/1.1 303 See Other
Location: /bookings
```

Dakle:

```php
public static function redirect(
    string $url,
    int $status = 302
): self {
    return new self(
        body: '',
        status: $status,
        headers: [
            'Location' => $url,
        ]
    );
}
```

---

# 17. Browser ponašanje kod redirect-a

Server vrati:

```text
303
Location: /bookings
```

Browser zatim napravi:

```text
novi request
```

ka:

```text
GET /bookings
```

Mentalno:

```text
POST /bookings
↓
Server
↓
303 Location: /bookings
↓
Browser
↓
GET /bookings
```

To je veoma važan web pattern.

---

# 18. PRG — Post/Redirect/Get

Pattern:

```text
POST
↓
REDIRECT
↓
GET
```

zove se:

```text
Post / Redirect / Get
```

ili:

```text
PRG
```

Koristimo ga da posle uspešnog form submit-a browser ne ostane na:

```text
POST response-u
```

nego pređe na novu GET stranicu.

---

# 19. Zašto je PRG koristan

Bez PRG:

```text
POST /bookings
↓
HTML response
```

User uradi refresh.

Browser može pitati:

```text
Resubmit form?
```

Ako potvrdi:

```text
POST /bookings
```

može biti poslat opet.

Potencijalno:

```text
duplicate booking
duplicate order
duplicate action
```

PRG smanjuje ovaj UX/problem flow.

---

# 20. PRG nije idempotency protection

Veoma važna nijansa.

PRG pomaže protiv:

```text
normalnog browser refresh/resubmit flow-a
```

Ali attacker/client i dalje može poslati:

```text
POST
POST
POST
```

direktno.

Zato:

```text
PRG
≠ idempotency
≠ concurrency protection
```

Za kritične use case-ove i dalje trebaju:

```text
transactions
constraints
idempotency keys gde imaju smisla
business invariants
```

---

# 21. Zašto `303 See Other`

Posle POST-a često želimo:

```text
303 See Other
```

jer jasno govori client-u:

> Rezultat pogledaj na drugom URI-ju koristeći GET.

Flow:

```text
POST /bookings
↓
303
Location: /bookings/42
↓
GET /bookings/42
```

Ovo je vrlo prirodan PRG response.

---

# 22. `302 Found`

`302` se istorijski često koristi za form redirects.

Browser-i ga u praksi često pretvaraju u GET nakon POST-a.

Ali semantika kroz istoriju nije bila potpuno čista.

Zato za namerni:

```text
POST
→ GET
```

flow:

```text
303
```

jasnije izražava našu nameru.

---

# 23. `307 Temporary Redirect`

`307` ima bitno drugačiju semantiku.

On kaže:

```text
redirect
ALI
zadrži HTTP method
```

Dakle:

```text
POST /old
↓
307
↓
POST /new
```

Ne:

```text
GET /new
```

Zato `307` nije ono što želimo za klasični PRG.

---

# 24. `308 Permanent Redirect`

Slično:

```text
308
```

čuva method i body, ali redirect je permanent.

Dakle:

```text
POST /old
↓
308
↓
POST /new
```

Opet drugačije od 303.

---

# 25. Redirect status mentalni model

Za kurs dovoljno:

```text
303
→ posle POST-a idi GET-om na drugi URL

307
→ redirect, ali sačuvaj method

308
→ permanent redirect + sačuvaj method
```

`301/302` ćeš često viđati, ali `303` nam je posebno važan za HTML form flow.

```text
↓

↓
```

# 30. Response headers

Response može imati:

```php
[
    'Content-Type' =>
        'application/json',

    'Cache-Control' =>
        'no-store',

    'X-Content-Type-Options' =>
        'nosniff',
]
```

Response abstraction nam daje jedno mesto za njih.

Middleware može kasnije dodati:

```text
security headers
CORS headers
cache headers
request ID
```

bez promene Controller-a.

# 31. Zašto je Response važan za middleware

Zamisli middleware:

```text
Request
↓
Controller
↓
Response
```

Middleware zatim želi da doda:

```http
X-App-Time-Ms: 14.82
```

Ako Controller već radi:

```php
echo $html;
exit;
```

middleware više nema priliku da obradi rezultat.

Ako Controller vrati:

```php
Response
```

middleware može:

```php
$response =
    $next($request);

return $response->withHeader(
    'X-App-Time-Ms',
    '14.82'
);
```

To je ogromna arhitektonska prednost.

# 32. Immutable Response

Kao kod Request-a, možemo napraviti Response immutable.

Na primer:

```php
public function withHeader(
    string $name,
    string $value
): self {
    $clone = clone $this;

    $clone->headers[$name] =
        $value;

    return $clone;
}
```

Ili drugačije implementirati immutable state.

Poenta:

```text
middleware
↓
dobije Response
↓
vrati novu verziju
```

bez nasumične globalne mutacije.

# 33. `withStatus()`

Možemo imati:

```php
$response =
    $response->withStatus(
        201
    );
```

ili:

```php
$response =
    $response->withHeader(
        'Cache-Control',
        'no-store'
    );
```

Ovo je veoma sličan mentalni model modernim HTTP libraries/framework-ovima.

# 34. Response body kao string

Za naš Vanilla projekat dovoljno je:

```text

```

Za HTML:

```text
string
```

Za JSON:

```text
encoded JSON string
```

Za male file downloads možda ćemo koristiti poseban response način.

Ne moramo odmah praviti:

# 35. File download response

Za download možemo imati poseban:

```text
FileResponse
```

ili helper.

Konceptualno:

```php
return Response::download(
    path: $trustedPath,
    filename: 'voucher.pdf',
    contentType:
        'application/pdf'
);
```

Ali kod velikih fajlova nije idealno prvo učitati ceo fajl u string.

Tada `send()` može streamovati file.

Bitna architecture granica ostaje ista:

```text
Controller returns response abstraction
```


ili:



# 43. "Headers already sent"

PHP greška:

```text

headers already sent
```

često nastaje kada prvo imamo:

```php

```

pa kasnije:

```php

    'Location: /login'
);
```

```text

```

nego sve šaljemo na kraju.

# 44. Accidental whitespace problem

# 56. Šta ako Controller vrati string?

Mogli bismo napraviti Router/Application koji automatski pretvara:

```php
return 'Hello';
```

u:

```php
Response::html('Hello');
```

Framework-i često imaju takvu convenience logiku.

Ali za naš Vanilla kurs više volim eksplicitno:

```php
return Response::html(
    'Hello'
);
```

jer jasno vidimo architecture.

# 57. Application može garantovati Response

Na primer:

```php
final class Application
{
    public function handle(
        Request $request
    ): Response {
        return $this->router
            ->dispatch($request);
    }
}
```

Time ceo request pipeline ima jasan contract:

```text
Request in
↓
Response out
```

To je jedna od najvažnijih arhitektonskih formula celog MVC sistema.

# 58. Request / Response symmetry

Sada imamo:

```text
HTTP REQUEST
↓
Request object
↓
Application
↓
Response object
↓
HTTP RESPONSE
```

To je čista boundary.

Unutar aplikacije:

```text
ne treba svuda koristiti
$_SERVER
header()
echo
exit
```

HTTP details su koncentrisani na ivicama sistema.

# 59. MiniStay primer: booking creation

Browser:

```text
POST /bookings
```

Controller:

```php
public function store(
    Request $request
): Response {
    $data =
        $this->bookingRequest
            ->validate($request);

    $booking =
        $this->bookingService
            ->create(
                $this->auth->user(),
                $data
            );

    $url =
        '/bookings/'
        . $booking->id();

    return Response::redirect(
        $url,
        303
    );
}
```

Front Controller:

```php
$response =
    $app->handle($request);

$response->send();
```

Browser dobija:

```text
303
↓
GET /bookings/42
```

Čist PRG flow.

```text
↓

↓

↓
SERVICE
↓
```

# Laravel paralela

Laravel Controller može vratiti:

```php
return response(
    'Hello',
    200
);
```

JSON:

```php
return response()->json(
    [
        'status' => 'ok',
    ]
);
```

View:

```php
return view(
    'bookings.index',
    [
        'bookings' =>
            $bookings,
    ]
);
```

Redirect:

```php
return redirect()
    ->route(
        'bookings.show',
        $booking
    );
```

Ispod svega toga Laravel na kraju pravi HTTP response object.

Čak i kada napišeš:

```php
return view(...);
```

framework zna kako da rezultat pretvori u finalni response.

Naš Vanilla PHP samo čini taj mehanizam eksplicitnim.

# Najvažnije za zapamtiti

HTTP response je:

```text
STATUS
+
HEADERS
+
BODY
```

Controller treba da:

```text
RETURN Response
```

umesto da direktno radi:

```php
header(...)
echo ...
exit;
```

Front Controller na kraju radi:

```php
$response->send();
```

Time dobijamo:

```text
testability
middleware support
jasan control flow
centralized HTTP output
```

Response može predstavljati:

```text
HTML
JSON
redirect
file
error
no-content
```

Redirect je samo:

```text
3xx
+
Location header
```

PRG:

```text
POST
↓
303
↓
GET
```

smanjuje browser form resubmission problem.

Ali:

```text
PRG
≠ idempotency
≠ concurrency safety
```

`303`:

```text
pređi na drugi URL kao GET
```

`307`:

```text
redirect uz isti method
```

`308`:

```text
permanent redirect uz isti method
```

Service ne treba da vraća Response.

Repository ne treba da zna HTTP.

Bolje:

```text
SERVICE
→ application result

CONTROLLER
→ Response
```

Najvažnija formula:

```text
REQUEST IN
↓
APPLICATION
↓
RESPONSE OUT
```

Ako samo jednu rečenicu zapamtiš:

> **Response object omogućava da aplikacija prvo odluči šta želi da vrati, a da stvarno slanje HTTP statusa, header-a i body-ja ostane jedan poslednji, centralizovan korak.**
