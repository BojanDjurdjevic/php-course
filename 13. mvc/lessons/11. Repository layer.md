# 11. Repository Layer & Persistence Boundary

## 1. Šta Repository zapravo rešava

Repository stoji između:

```text id="0fp0ae"
application/domain layer-a
```

i:

```text id="w2t4mn"
persistence layer-a
```

Mentalno:

```text id="r6oiaw"
Service
↓
Repository
↓
PDO / SQL
↓
Database
```

Service želi da kaže:

```text id="xq5x8d"
"Nađi Booking #42."
```

Ne:

```text id="3fgz8v"
"Pripremi SELECT,
binduj :id,
execute,
fetch associative array,
castuj kolone."
```

To je Repository odgovornost.


# 4. Sa Repository-jem

Service:

```php id="9url1g"
$booking =
    $this->bookings
        ->findById($id);

if ($booking === null) {
    throw new BookingNotFoundException();
}
```

Repository:

```php id="5o20le"
public function findById(
    int $id
): ?Booking {
    $stmt =
        $this->pdo->prepare(
            'SELECT *
             FROM bookings
             WHERE id = :id'
        );

    $stmt->execute([
        'id' => $id,
    ]);

    $row =
        $stmt->fetch(
            PDO::FETCH_ASSOC
        );

    if ($row === false) {
        return null;
    }

    return $this->hydrate($row);
}
```

Jasnije layering.

# 9. Hydration pripada Repository-ju

Na primer:

```php id="9elno8"
private function hydrate(
    array $row
): Booking {
    return new Booking(
        id:
            (int) $row['id'],

        userId:
            (int) $row['user_id'],

        roomId:
            (int) $row['room_id'],

        status:
            BookingStatus::from(
                $row['status']
            ),

        checkIn:
            new DateTimeImmutable(
                $row['check_in']
            ),

        checkOut:
            new DateTimeImmutable(
                $row['check_out']
            )
    );
}
```

Repository prevodi:

```text id="prca0q"
DB representation
↓
application representation
```

# 62. In-memory Repository

Na primer:

```php id="yb57be"
final class InMemoryBookingRepository
    implements BookingRepository
{
    /** @var array<int, Booking> */
    private array $items = [];

    public function findById(
        int $id
    ): ?Booking {
        return $this->items[$id]
            ?? null;
    }

    public function save(
        Booking $booking
    ): void {
        $this->items[
            $booking->id()
        ] = $booking;
    }
}
```

Odlično za određene unit testove.

# 69. Laravel paralela

Laravel Eloquent može direktno raditi:

```php id="pjbs0w"
$booking =
    Booking::query()
        ->where('user_id', $user->id)
        ->find($id);
```

Tu Eloquent Model + Builder već rade velik deo persistence posla.

Ako uvedemo Repository, Controller/Service može imati:

```php id="gqdlda"
$booking =
    $this->bookings
        ->findForUser(
            $id,
            $user->id
        );
```

Oba su legitimna.

Važno je razumeti tradeoff:

```text id="1bsoya"
Direct Eloquent
→ manje abstraction-a
→ brže i jednostavnije

Repository
→ jasnija persistence granica
→ lakši domain isolation
→ lakše zamene/test doubles
```

Repository je:


Mentalno:

```text id="vqcfxn"

↓
Repository
↓
```

```text id="ydxdgh"

```

Hydration:

```text id="xkrh4x"
DB row
→ Entity
```

Persistence mapping:

```text id="7h1iui"
Entity
→ DB values
```

Repository ne treba da:

```text id="rs69yb"

zna Request

```

Prepared statements:



```text id="nct61s"

```

```text id="0g1ly9"

```

```text id="lnflte"

```

```text id="xf7cg9"
jednu transaction
preko više Repository-ja
```

Ima smisla kada stvarno daje:

```text id="qscu8u"

mapping

```

```text id="n2tkmv"

→ query tool

Eloquent
→ ORM / Active Record

Repository
→ architectural boundary
```

> **Dobar Repository skriva mehanizam persistence-a, ali ne skriva semantiku operacije koju application mora da razume.**
