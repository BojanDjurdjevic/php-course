# 2.QueryString

```text
https://example.com/products
                         │
                         └── ?page=2&sort=price
```

Deo nakon ? je query string

parametri se pišu kao -> key=value A međusobno se odvajaju sa -> &

?page=2&sort=price :

```text
page = 2
sort = price
```

http://php-course.test/products.php?page=2&sort=price -> `print_r($_GET)`;

Dobijemo:

```text
Array
(
    [page] => 2
    [sort] => price
)
```

---

```php
$_GET = [
    'page' => '2',
    'sort' => 'price',
];
```

## Query string ne mora biti vezan za GET metodu

Ovo je zanimljiva nijansa.
Možeš imati:

```http
POST /orders?send_email=1
```

I PHP će i dalje imati:

```php
$_GET['send_email'];
```

jer `$_GET` predstavlja URL query parameters, ne telo GET requesta.

```php
$_GET
```

nije:  "podaci iz GET metode"

nego:  "podaci iz URL query stringa"

---

## Specijalni karakteri

Recimo želimo:

search=PHP & Laravel

Ako samo napišeš:

?search=PHP & Laravel

& ima posebno značenje — odvaja parametre.
Zato mora biti encoded.
Na primer:

?search=PHP+%26+Laravel

PHP će dobiti:

```php
$_GET['search'];
```

kao:

PHP & Laravel

To je razlog zašto URL encoding postoji.

## Nested / array query parametri — PHP je ovde baš zanimljiv

Recimo:

?filters[city]=Novi+Sad&filters[min_price]=50

PHP će napraviti:

```php
$_GET = [
    'filters' => [
        'city' => 'Novi Sad',
        'min_price' => '50',
    ],
];
```

Dakle možeš:

```php
$city = $_GET['filters']['city'] ?? null;
```

Ovo je jedna vrlo PHP-specifična i korisna mogućnost.

---

## Indexed arrays u query stringu

Možeš poslati:

?features[]=wifi&features[]=parking&features[]=spa

PHP:

```php
$_GET = [
    'features' => [
        'wifi',
        'parking',
        'spa',
    ],
];
```

Dakle:

```php
$features = $_GET['features'] ?? [];
```

Možeš zatim:

```php
foreach ($features as $feature) {
    echo $feature;
}
```

Ovo je vrlo zgodno za checkbox filtere.

## Associative nested filters

Recimo auto search:

/cars?filter[make]=BMW&filter[fuel]=diesel&filter[min_price]=5000

PHP:

```php
$_GET = [
    'filter' => [
        'make' => 'BMW',
        'fuel' => 'diesel',
        'min_price' => '5000',
    ],
];
```

Onda:

```php
$filters = $_GET['filter'] ?? [];
```

i:

```php
$make = $filters['make'] ?? null;
$minPrice = $filters['min_price'] ?? null;
```

Veoma čist način organizovanja kompleksnijih filtera.

```text
http_build_query() — array → query string
```

Imamo:

```php
$params = [
    'page' => 2,
    'sort' => 'price',
    'city' => 'Novi Sad',
];
```

Možemo:

```php
$query = http_build_query($params);

echo $query;
```

dobiti nešto poput:

page=2&sort=price&city=Novi+Sad

## PHP-ov `http_build_query()` generiše URL-encoded query string iz niza ili objekta. php.net

To je mnogo bolje nego ručno:

```php
$query = '?page=' . $page
```

```text
    . '&sort=' . $sort
    . '&city=' . $city;
```

jer `http_build_query()` pravilno radi encoding.

---

Nested array + `http_build_query()`

```php
$params = [
    'filters' => [
        'city' => 'Novi Sad',
        'price_min' => 50,
    ],
    'page' => 2,
];

$query = http_build_query($params);
```

dobiješ URL-encoded varijantu nečega što konceptualno predstavlja:

```text
filters[city]=Novi Sad
filters[price_min]=50
page=2
```

Dakle PHP zna oba smera:

```text
array
↓
http_build_query()
↓
query string
```

---

```text
parse_str() — query string → array
```

Obrnuto:

```php
$query = 'page=2&sort=price';

parse_str($query, $params);

print_r($params);
```

dobijaš:

```php
[
    'page' => '2',
    'sort' => 'price',
]
```

`parse_str()` parsira string kao query string i rezultat smešta u prosleđeni niz. U modernom PHP-u drugi argument je obavezan. php.net
Mentalno:

```php
http_build_query()
```

```text
ARRAY → QUERY STRING
```

```php

```

```text
QUERY STRING → ARRAY
```

Slično kao naše:

implode / explode

samo specijalizovano za URL query format.

Ne verovati `$_GET` inputu

Query string je user input.

Korisnik može ručno napisati:

?page=hello

ili:

?price=-999999

ili:

?sort=DROP_TABLE

Zato ovo:

```php
$page = $_GET['page'] ?? 1;
```

nije dovoljno ako ti stvarno treba integer.
Možeš:

```php
$page = filter_input(
    INPUT_GET,
    'page',
    FILTER_VALIDATE_INT
);

if ($page === false || $page === null || $page < 1) {
    $page = 1;
}
```

Ili ručna validacija:

```php
$page = $_GET['page'] ?? '1';

if (!ctype_digit($page)) {
    $page = '1';
}

$page = (int) $page;
```

---

Output encoding je druga stvar

Recimo:

?name=`<script>``alert(1)``</script>`

Ovo je opasno:

```php
echo $_GET['name'];
```

Jer browser može pokušati da interpretira HTML/JS.
Bolje:

```php
echo htmlspecialchars(
    $_GET['name'] ?? '',
    ENT_QUOTES,
    'UTF-8'
);
```

Važno:

```text
VALIDATION
"Da li je input dozvoljen?"
```

nije isto što i

```text
OUTPUT ESCAPING
"Kako ga bezbedno prikazujem?"
```

## Laravel pandan

Core PHP:

```php
$page = $_GET['page'] ?? 1;
```

Laravel:

```php
$page = $request->query('page', 1);
```

Ako želiš sve:

```php
$query = $request->query();
```

Laravel dokumentacija kaže da `query()` čita isključivo query string, dok `input()` može da čita input šire iz request-a. Laravel
Dakle:

```php
$request->query('page');
```

je precizniji pandan:

```php
$_GET['page']
```

nego:

```php
$request->input('page');
```

## MAPA PAMĆENJA

URL:

```text
/cars?page=2&sort=price
      └─────────────────┐
                        ↓
                  QUERY STRING
                        ↓
```

PHP parsira:

```text
                        ↓
$_GET = [
    'page' => '2',
    'sort' => 'price',
];
```

```text
READ PARAMETER
$_GET['page'] ?? 1
```

```text
RAW QUERY
$_SERVER['QUERY_STRING']
```

```text
ARRAY → QUERY STRING
http_build_query()
```

```text
QUERY STRING → ARRAY
parse_str()
```

```text
LARAVEL
$request->query()
```

ZAMKE :

`$_GET` vrednosti su uglavnom stringovi

`$_GET` nije vezan samo za GET HTTP method

query input je user-controlled

URL encoding je obavezan za specijalne karaktere

route parameter ≠ query parameter
