Ako korisnik unese:

```text

```

```http
POST /http/lesson-04/process.php HTTP/1.1
Host: php-course.test
Content-Type: application/x-www-form-urlencoded
Content-Length: ...
```

name=Bojan&email=bojan%40example.com

Primeti:

```http
POST /process.php
```

je request line.
Zatim:

Content-Type: application/x-www-form-urlencoded

opisuje format body-ja.
I na kraju:

name=Bojan&email=bojan%40example.com

je request body. Kod POST forme browser šalje podatke u body-ju, a Content-Type govori serveru kako su ti podaci

POST BODY

```text
        ↓ PHP
```


PHP definiše `$_POST` kao superglobalni asocijativni niz podataka iz POST zahteva kada je body kodiran kao application/x-www-form-urlencoded ili multipart/form-data.

## POST ne znači da su podaci tajni

Ovo je veoma važna stvar.
Ljudi često kažu:

POST je bezbedniji jer password nije u URL-u.

Preciznije:

POST samo ne stavlja podatke u query string.
To nije encryption.
Ako pošalješ:

```http
POST /login
```

email=bojan@example.com&password=secret

preko običnog:

http://

sam POST ne štiti password.
Za transportnu zaštitu koristi se:

HTTPS

Dakle:

```text
GET vs POST
→ gde / kako se request semantički šalje
```

```text
HTTPS
→ šifrovanje komunikacije
```

To su odvojeni problemi.

---

application/x-www-form-urlencoded
Ovo je default za običnu HTML POST formu:

```html
<form method="POST">
```

Browser šalje nešto nalik:

name=Bojan&city=Novi+Sad&age=40

Izgleda skoro kao query string.
I jeste vrlo sličan encoding:

key=value&key=value

Razlika je gde se nalazi.
GET:

URL

?name=Bojan&city=Novi+Sad

POST:

BODY

name=Bojan&city=Novi+Sad

MDN opisuje application/x-www-form-urlencoded upravo kao key/value parove razdvojene sa &, uz URL/percent encoding specijalnih karaktera.

Checkbox ima jednu čuvenu zamku

Recimo:

```html
<input
    type="checkbox"
    name="newsletter"
    value="1"
```

>

Ako je checkbox čekiran:

```php
$_POST['newsletter'];
// '1'
```

Ali ako nije čekiran, browser ga uglavnom uopšte neće poslati.
Dakle možda nećeš dobiti:

```php
[
    'newsletter' => '0',
]
```

nego ključ jednostavno ne postoji.
Zato:

```php
$newsletter = isset($_POST['newsletter']);
```

ili:

```php
$newsletter = ($_POST['newsletter'] ?? '0') === '1';
```

Laravel ti za ovakve slučajeve daje mnogo prijatnije:

```php
$newsletter = $request->boolean('newsletter');
```

Content-Type

Ovo je jako bitno!!!

PHP ne kaže samo:

„Aha, POST je — napuniću `$_POST`.“

Nije tako jednostavno.
Bitno je u kom formatu je request body poslat.
Klasična forma:

Content-Type: application/x-www-form-urlencoded

```text
→ PHP popunjava:
$_POST
```

Forma sa file uploadom:

Content-Type: multipart/form-data

```text
→ PHP popunjava:
$_POST
```

```php
$_FILES
```

Ali ako JavaScript pošalje:

Content-Type: application/json

sa:

```json
{
    "name": "Bojan",
    "email": "bojan@example.com"
}
```

onda:

```php
$_POST
```

neće automatski sadržati taj JSON.
PHP dokumentacija eksplicitno navodi da `$_POST` automatski radi
za application/x-www-form-urlencoded i multipart/form-data;
za druge content type-ove poput application/json koristi se raw body preko php://input.

---

multipart/form-data

Ako imaš:

```html
<form
    method="POST"
    enctype="multipart/form-data"
```

>

browser šalje body u delovima.
Recimo:

```text
text field
file
text field
file
```

svaki postaje poseban part, odvojen tzv. boundary vrednošću. multipart/form-data je encoding koji se koristi kada forma šalje fajlove. MDN Web Docs
PHP tada tekstualne vrednosti stavlja u:

```php
$_POST
```

a uploadovane fajlove u:

```php
$_FILES
```
