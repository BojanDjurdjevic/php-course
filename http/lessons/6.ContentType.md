# 6.ContentType

```text
HTTP METHOD
+
Content-Type
+
BODY FORMAT
        ↓
PHP odlučuje kako da obradi body
```

---

Content-Type header govori serveru u kom formatu je sadržaj request body-ja. Kod web aplikacija ćeš stalno susretati tri formata:

```text
application/x-www-form-urlencoded
multipart/form-data
application/json
```

PHP automatski popunjava `$_POST` za prva dva kada je u pitanju standardni POST request, dok se JSON body čita drugačije.

## Kako onda čitamo JSON u core PHP-u?

Prvo uzmemo sirov body:

```php
$rawBody = file_get_contents('php://input');
```

Recimo da je:

```json
{
    "name": "Bojan",
    "age": 40,
    "active": true
}
```

`$rawBody` je za sada samo string.
Možeš proveriti:

```php
var_dump($rawBody);
```

Mentalno:

```text
HTTP BODY
        ↓
php://input
        ↓
STRING
```

Onda JSON parsiramo:

```php
$data = json_decode(
    $rawBody,
    true
);
```

Drugi argument:

true

znači:

pretvori JSON objects u PHP associative arrays.

Dobijamo:

```php
$data = [
    'name' => 'Bojan',
    'age' => 40,
    'active' => true,
];
```

PRIMER:

```php
<?php

if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    http_response_code(405);

    exit('Method Not Allowed');
}

    $_SERVER['CONTENT_TYPE']
```

?? '';

```php
if (!str_contains(
    $contentType,
    'application/json'

    exit('Unsupported Media Type');
```

## Važna stvar: Content-Type nije Accept

Ljudi ih često pomešaju.
Request:

```text
Content-Type: application/json
Accept: application/json
```

nisu ista stvar.
Content-Type kaže:

Ono što ti šaljem je JSON.

Accept kaže:

Voleo bih da mi response vratiš kao JSON.

Mentalno:

```text
Content-Type
REQUEST BODY format
```

```text
Accept
DESIRED RESPONSE format
```

---

| Content-Type | Tipična upotreba | Core PHP |
| --- | --- | --- |
| `application/x-www-form-urlencoded` | obična HTML forma | `$_POST` |
| `multipart/form-data` | forma + fajlovi | `$_POST` + `$_FILES` |
| `application/json` | API / SPA | `php://input` + `json_decode()` |

## Zašto true?

Jer potpis funkcije dozvoljava da kažeš da želiš JSON objekte kao associative arrays.

Bez true:

```php
$data = json_decode($rawBody);
```

dobio bi objekat:

```php
$data->name;
$data->age;
```

## Problem sa klasičnim `json_decode()`

Pogledaj:

```php
$data = json_decode($rawBody, true);
```

Ako JSON nije validan:

```json
{
    "name": "Bojan",
}
```

trailing comma čini JSON nevalidnim.
Tradicionalno `json_decode()` može vratiti:

null

Ali postoji problem:

validan JSON može biti i:

null

koji takođe daje PHP:

null

Zato samo:

```php
if ($data === null)
```

nije idealna detekcija greške. PHP je upravo zbog toga dobio JSON_THROW_ON_ERROR: ---->>>

```php
try {
    $data = json_decode(
        $rawBody,
        true,
        512,
        JSON_THROW_ON_ERROR
    );
} catch (JsonException $e) {
    //
}
```

--->>>

## I kod `json_encode()` može doći do greške

Moderni pristup:

```php
try {
    $json = json_encode(
        $data,
        JSON_THROW_ON_ERROR
    );
} catch (JsonException $e) {
    //
}
```

Isti flag radi i za encoding i decoding

## JSON_THROW_ON_ERROR + drugi flagovi

Flags su bitmask, pa ih možeš kombinovati:

```php
$json = json_encode(
    $data,
    JSON_UNESCAPED_UNICODE
    | JSON_THROW_ON_ERROR
);
```

ili:

```php
$json = json_encode(
    $data,
    JSON_UNESCAPED_UNICODE
    | JSON_PRETTY_PRINT
    | JSON_THROW_ON_ERROR
);
```

Ovaj operator:

|

ovde je bitwise OR i služi za kombinovanje flagova.

## JSON response mora imati pravi Content-Type

Nemoj samo:

```php
echo json_encode($data);
```

Bolje:

```php
header(
    'Content-Type: application/json; charset=UTF-8'
);

echo json_encode($data);
```

Jer body jeste JSON, pa response treba to jasno da kaže klijentu.
Konceptualno:

```http
HTTP/1.1 200 OK
Content-Type: application/json; charset=UTF-8
```

```json
{"name":"Bojan"}
```

```php
$data = [
```
