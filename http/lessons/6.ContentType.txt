-----------------------------------

Content-Type header govori serveru u kom formatu je sadržaj request body-ja. Kod web aplikacija ćeš stalno susretati tri formata:

application/x-www-form-urlencoded
multipart/form-data
application/json

PHP automatski popunjava $_POST za prva dva kada je u pitanju standardni POST request, dok se JSON body čita drugačije.

Ovo je klasičan format obične HTML forme.

Forma:
<form method="POST" action="process.php">
    <input
        type="text"
        name="name"
        value="Bojan"
    >

    <input
        type="email"
        name="email"
        value="bojan@example.com"
    >

    <button type="submit">
        Send
    </button>
</form>

Browser šalje otprilike:

POST /process.php HTTP/1.1
Content-Type: application/x-www-form-urlencoded

name=Bojan&email=bojan%40example.com

Body izgleda skoro identično query stringu:

name=Bojan&email=bojan%40example.com

PHP ga automatski parsira:

$_POST = [
    'name' => 'Bojan',
    'email' => 'bojan@example.com',
];

To je default encoding standardne HTML forme kada ne navedeš drugi enctype. MDN Web Docs

Kako onda čitamo JSON u core PHP-u?
Prvo uzmemo sirov body:
$rawBody = file_get_contents('php://input');

Recimo da je:
{
    "name": "Bojan",
    "age": 40,
    "active": true
}

$rawBody je za sada samo string.
Možeš proveriti:
var_dump($rawBody);

Mentalno:
HTTP BODY
        ↓
php://input
        ↓
STRING

Onda JSON parsiramo:
$data = json_decode(
    $rawBody,
    true
);

Drugi argument:
true

znači:
pretvori JSON objects u PHP associative arrays.

Dobijamo:
$data = [
    'name' => 'Bojan',
    'age' => 40,
    'active' => true,
];

PRIMER:

<?php

if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    http_response_code(405);

    exit('Method Not Allowed');
}

$contentType =
    $_SERVER['CONTENT_TYPE']
    ?? '';

if (!str_contains(
    $contentType,
    'application/json'
)) {
    http_response_code(415);

    exit('Unsupported Media Type');
}

$rawBody = file_get_contents(
    'php://input'
);

$data = json_decode(
    $rawBody,
    true
);

if (!is_array($data)) {
    http_response_code(400);

    exit('Invalid JSON');
}

$name = $data['name'] ?? null;

echo htmlspecialchars(
    (string) $name,
    ENT_QUOTES,
    'UTF-8'
);

-----------------------------------------------------

Važna stvar: Content-Type nije Accept
Ljudi ih često pomešaju.
Request:
Content-Type: application/json
Accept: application/json

nisu ista stvar.
Content-Type kaže:
Ono što ti šaljem je JSON.

Accept kaže:
Voleo bih da mi response vratiš kao JSON.

Mentalno:
Content-Type
REQUEST BODY format

Accept
DESIRED RESPONSE format

---------------------------------------------------------

| Content-Type                          | Tipična upotreba          | Core PHP |
|----------------------------------------------------------------------------------------------------|
| `application/x-www-form-urlencoded`   | obična HTML forma         | `$_POST` |
| `multipart/form-data`                 | forma + fajlovi           | `$_POST` + `$_FILES` |
| `application/json`                    | API / SPA                 | `php://input` + `json_decode()` |

--------------------------------------

Problem sa klasičnim json_decode()
Pogledaj:
$data = json_decode($rawBody, true);

Ako JSON nije validan:
{
    "name": "Bojan",
}

trailing comma čini JSON nevalidnim.
Tradicionalno json_decode() može vratiti:
null

Ali postoji problem:
validan JSON može biti i:
null

koji takođe daje PHP:
null

Zato samo:
if ($data === null)

nije idealna detekcija greške. PHP je upravo zbog toga dobio JSON_THROW_ON_ERROR: ---->>>

try {
    $data = json_decode(
        $rawBody,
        true,
        512,
        JSON_THROW_ON_ERROR
    );
} catch (JsonException $e) {
    //
}

--->>>

I kod json_encode() može doći do greške
Moderni pristup:
try {
    $json = json_encode(
        $data,
        JSON_THROW_ON_ERROR
    );
} catch (JsonException $e) {
    //
}

Isti flag radi i za encoding i decoding

------>>>>

JSON_THROW_ON_ERROR + drugi flagovi
Flags su bitmask, pa ih možeš kombinovati:
$json = json_encode(
    $data,
    JSON_UNESCAPED_UNICODE
    | JSON_THROW_ON_ERROR
);

ili:
$json = json_encode(
    $data,
    JSON_UNESCAPED_UNICODE
    | JSON_PRETTY_PRINT
    | JSON_THROW_ON_ERROR
);

Ovaj operator:
|

ovde je bitwise OR i služi za kombinovanje flagova.

json_encode() — PHP → JSON
Obrnuta operacija.
Imamo:
$user = [
    'id' => 15,
    'name' => 'Bojan',
    'active' => true,
];

radimo:
$json = json_encode($user);

dobijamo:
{"id":15,"name":"Bojan","active":true}

PHP json_encode() vraća JSON reprezentaciju prosleđene vrednosti; nizove i objekte serijalizuje rekurzivno. PHP
Mentalno:
json_decode()

JSON STRING
→ PHP


json_encode()

PHP
→ JSON STRING

------------------------------------------------

JSON response mora imati pravi Content-Type
Nemoj samo:
echo json_encode($data);

Bolje:
header(
    'Content-Type: application/json; charset=UTF-8'
);

echo json_encode($data);

Jer body jeste JSON, pa response treba to jasno da kaže klijentu.
Konceptualno:
HTTP/1.1 200 OK
Content-Type: application/json; charset=UTF-8

{"name":"Bojan"}

da bi Unicode karakteri ostali čitljivi.

što sprečava gubitak preciznosti tako što velike integer vrednosti čuva kao string. PHP
