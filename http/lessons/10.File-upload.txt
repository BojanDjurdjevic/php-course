File uploads + $_FILES

Kod upload-a fajla dešava se nešto malo drugačije od običnog text inputa. Browser pravi multipart/form-data request, 

PHP fajl privremeno smešta na server i zatim ti kroz $_FILES daje podatke o tom privremenom fajlu. 

Mi odlučujemo da li je fajl validan i gde će trajno biti sačuvan.

---

<input type="file">
        ↓
multipart/form-data
        ↓
HTTP request
        ↓
PHP primi upload
        ↓
temporary directory
        ↓
$_FILES
        ↓
validation
        ↓
move_uploaded_file()
        ↓
permanent storage

HTML forma mora imati multipart/form-data !!!

<form
    action="upload.php"
    method="POST"
    enctype="multipart/form-data" // ---> OVO
>
    <input
        type="text"
        name="title"
    >

    <input
        type="file"
        name="photo"
    >

    <button type="submit">
        Upload
    </button>
</form>

Bez multipart/form-data klasičan HTML file upload neće raditi kako treba. 
PHP dokumentacija to eksplicitno zahteva za POST upload forme.

https://www.php.net/file-upload.post-method

-----------------------------------------

Šta PHP dobija?

Ako korisnik unese:

title = Hotel Dunav

i izabere:
hotel.jpg

PHP razdvaja request na:
$_POST = [
    'title' => 'Hotel Dunav',
];

i:
$_FILES = [
    'photo' => [
        // informacije o fajlu
    ],
];

Dakle:
normal fields
→ $_POST

files
→ $_FILES

Ime:
$_FILES['photo']

dolazi iz:
name="photo"

isto kao što name="title" određuje ključ u $_POST.

echo '<pre>';

Dobićeš otprilike:

[
    'photo' => [

        'full_path' => 'hotel.jpg',

----------------------------------- TABELA KLJUČEVA $_FILES ---------------------------------------------

| Key           | Značenje |
|------------------------------------------------
| `name`        | originalno ime sa korisnikovog računara |
| `type`        | MIME type koji je prijavio client |
| `tmp_name`    | privremena lokacija fajla na serveru |
| `error`       | upload status |
| `size`        | veličina u bajtovima |

PHP dokumentacija posebno upozorava da type dolazi od browsera/clienta i nije proverena vrednost, 
pa mu ne treba verovati za validaciju.

https://www.php.net/file-upload.post-method

---------------------------------------

Najvažnija vrednost: tmp_name !!!

Recimo:
$tmpName = $_FILES['photo']['tmp_name'];

To nije originalni fajl sa korisnikovog računara.

To je fajl koji je PHP privremeno napravio na tvom serveru.

USER PC

hotel.jpg
   ↓ upload

SERVER TEMP FOLDER

php8A32.tmp
   ↓

$_FILES['photo']['tmp_name']

Ako ga želiš trajno sačuvati, moraš ga premestiti.

------------------------------------------

Prvo proveravamo error

Najpre:
$file = $_FILES['photo'] ?? null;

if ($file === null) {
    exit('No file field.');
}

if ($file['error'] !== UPLOAD_ERR_OK) {
    exit('Upload failed.');
}

Uspešan upload ima:

UPLOAD_ERR_OK

što je vrednost:
0

PHP ima imenovane konstante, pa je mnogo bolje:
if ($file['error'] !== UPLOAD_ERR_OK)

nego:
if ($file['error'] !== 0)

jer kod govori sam za sebe.

--------------------------------------------   NAJVAŽNIJI UPLOAD_ERR_* -----------------------------------

| Constant                  | Value             | Značenje |
|-------------------------------------------------------
| `UPLOAD_ERR_OK`           | `0`               | upload uspešan |
| `UPLOAD_ERR_INI_SIZE`     | `1`               | veći od `upload_max_filesize` |
| `UPLOAD_ERR_FORM_SIZE`    | `2`               | veći od HTML `MAX_FILE_SIZE` |
| `UPLOAD_ERR_PARTIAL`      | `3`               | uploadovan samo deo fajla |
| `UPLOAD_ERR_NO_FILE`      | `4`               | fajl nije izabran |
| `UPLOAD_ERR_NO_TMP_DIR`   | `6`               | nema temp foldera |
| `UPLOAD_ERR_CANT_WRITE`   | `7`               | PHP nije mogao da upiše fajl |
| `UPLOAD_ERR_EXTENSION`    | `8`               | PHP extension zaustavio upload |

------------------------------------------------------------------------------------------------------------

if ($file['error'] === UPLOAD_ERR_NO_FILE) {
    exit('Please select a file.');
}

------------------

is_uploaded_file()


Možeš dodatno proveriti:

if (!is_uploaded_file($file['tmp_name'])) {
    exit('Invalid uploaded file.');
}

Ova funkcija proverava da li je dati fajl zaista nastao PHP HTTP upload mehanizmom. 
Namenjena je upravo zaštiti od situacija gde bi neko pokušao da te navede 
da obrađuješ neki drugi lokalni fajl na serveru. 

Ali kasnije kada koristiš:
move_uploaded_file()

ona već radi odgovarajuću upload proveru.

------------------

Nemoj verovati originalnom imenu

Korisnik pošalje:
$file['name'];

i dobiješ:
hotel.jpg

Ali to ime dolazi od klijenta.

Ne bih radio:

$destination = __DIR__ . '/uploads/' . $file['name'];

bez daljih mera.

Zašto?

Zbog:
kolizija imena
čudnih karaktera
manipulisanih ekstenzija
potencijalnih path problema

Originalno ime je korisno kao metadata, ali nije dobro da automatski postane server filename.

-------------------------------------

Generiši sopstveno ime

Jedan jednostavan pristup:

$fileName = bin2hex(random_bytes(16)) . '.jpg';

Dobićeš nešto poput:
2f83e5a8a3d92b384cc67d46e69bb814.jpg

Ali primeti: još ne znamo da je stvarno JPG.

Zato prvo moramo utvrditi MIME type.

-------------------------------------

Ne veruj $_FILES['photo']['type']


$file['type']

može reći:

image/jpeg

ali browser je taj podatak poslao.

PHP dokumentacija izričito kaže da ova MIME vrednost nije proverena na PHP strani.

Zato NIKAKO:

if ($file['type'] === 'image/jpeg') {
    // sigurno JPG
}

Za stvarnu proveru sadržaja koristimo Fileinfo.

--------------------------------------

finfo_file() — MIME iz sadržaja

$finfo = finfo_open(FILEINFO_MIME_TYPE);

$mime = finfo_file(
    $finfo,
    $file['tmp_name']
);

finfo_close($finfo);

finfo_file() analizira fajl i vraća informacije o njegovom sadržaju; sa FILEINFO_MIME_TYPE tražimo MIME type.

------------ MODERAN OOP STIL ZA finfo_file() ---------------------------

$finfo = new finfo(FILEINFO_MIME_TYPE);

$mime = $finfo->file($file['tmp_name']);

--------------------------------------

Dozvoljena MIME lista


Recimo prihvatamo:
JPEG
PNG
WebP

Možemo:
$allowedTypes = [
    'image/jpeg' => 'jpg',
    'image/png' => 'png',
    'image/webp' => 'webp',
];

onda:
if (!isset($allowedTypes[$mime])) {
    exit('Unsupported file type.');
}

A ekstenziju uzmemo iz naše trusted mape:

$extension = $allowedTypes[$mime];

Ne:

pathinfo(
    $file['name'],
    PATHINFO_EXTENSION
);

kao jedini dokaz tipa.
Jer korisnik može fajl nazvati:
malware.jpg

bez obzira na stvarni sadržaj.

--------------------------------------

Provera veličine

$_FILES ti daje:
$file['size']

u bajtovima. 

Recimo maksimum 5 MB:

$maxSize = 5 * 1024 * 1024;

if ($file['size'] > $maxSize) {
    exit('File is too large.');
}

1 KB = 1024 bytes
1 MB = 1024 * 1024 bytes

Ali ova application-level provera nije jedini limit.
PHP ima i server konfiguraciju.

-------------------------------------

php.ini upload limiti

Najvažniji su:

---
file_uploads = On

upload_max_filesize = 10M

post_max_size = 12M

max_file_uploads = 20
---

Posebno:
upload_max_filesize

maksimalna veličina jednog uploadovanog fajla.
post_max_size

maksimalna veličina celog POST body-ja.
Zato treba:
post_max_size
>
upload_max_filesize

Ako ceo POST pređe post_max_size, PHP može ostaviti i $_POST i $_FILES prazne, što ume da bude vrlo zbunjujuće pri debuggingu.
Ovo je dobra praktična stvar da zapamtiš za production.

move_uploaded_file()

Kad je fajl prošao validaciju:

$destination = __DIR__ . '/uploads/' . $fileName;

$success = move_uploaded_file(
    $file['tmp_name'],
    $destination
);

Ako uspe:
true

inače:
false

move_uploaded_file() dodatno proverava da source zaista jeste fajl uploadovan PHP HTTP upload mehanizmom. 
Ako destination već postoji, može ga prepisati, pa je još jedan razlog da generišeš jedinstvena imena.

---------------------------------------------

PRIMER:

<?php

if ($_SERVER['REQUEST_METHOD'] !== 'POST') {
    header('Allow: POST');

    http_response_code(405);

    exit('Method Not Allowed');
}

$file = $_FILES['photo'] ?? null;

if ($file === null) {
    http_response_code(422);

    exit('Photo is required.');
}

if ($file['error'] !== UPLOAD_ERR_OK) {
    http_response_code(400);

    exit('Upload failed.');
}

$maxSize = 5 * 1024 * 1024;

if ($file['size'] > $maxSize) {
    http_response_code(422);

    exit('File is too large.');
}

$finfo = new finfo(
    FILEINFO_MIME_TYPE
);

$mime = $finfo->file(
    $file['tmp_name']
);

$allowedTypes = [
    'image/jpeg' => 'jpg',
    'image/png' => 'png',
    'image/webp' => 'webp',
];

if (!isset($allowedTypes[$mime])) {
    http_response_code(415);

    exit('Unsupported file type.');
}

$extension = $allowedTypes[$mime];

$fileName = bin2hex(random_bytes(16))  . '.'  . $extension;

$uploadDirectory = __DIR__ . '/uploads';

if (!is_dir($uploadDirectory)) {
    mkdir(
        $uploadDirectory,
        0755,
        true
    );
}

$destination = $uploadDirectory . DIRECTORY_SEPARATOR . $fileName;

if (
    !move_uploaded_file(
        $file['tmp_name'],
        $destination
    )
) {
    http_response_code(500);

    exit('Could not store file.');
}

http_response_code(201);

echo 'Uploaded: '
    . htmlspecialchars(
        $fileName,
        ENT_QUOTES,
        'UTF-8'
    );

---------------------------------------- SECURITY ---------------------------------

Upload sigurnost — tri stvari nikad ne veruj

Ako imamo:
$_FILES['photo']

posebno tretiraj kao user-controlled:
original name
client MIME type
extension

Originalno ime može biti lažno.
type može biti lažan.
Ekstenzija može biti lažna.
Zato pravi pipeline:
---
temporary uploaded file
↓
server-side MIME/content validation
↓
size validation
↓
generated filename
↓
safe storage location
---

Zašto upload PHP fajla može biti veoma opasan?

Zamisli da neko uploaduje:
shell.php

a ti ga sačuvaš direktno u javni executable direktorijum:
/public/uploads/shell.php

i server dozvoljava PHP execution u tom folderu.
Napadač zatim otvori:
/uploads/shell.php

i server izvrši kod.

Zato kod user uploads generalno želiš:
strogu type validation
generated names
kontrolisane ekstenzije
storage gde upload nije executable

Za framework storage je često mnogo bolje da fajlovima pristupaš kroz jasno konfigurisani filesystem/disk nego da ih nasumično pišeš u web root.

Laravel — koliko toga UploadedFile apstrahuje?
Core:
$file =
    $_FILES['photo'];

Laravel:
$file =
    $request->file('photo');

Laravel vraća:
Illuminate\Http\UploadedFile

objekat. Laravel
Možeš proveriti postojanje:
if ($request->hasFile('photo')) {
    //
}

i uspešan upload:
if (
    $request->file('photo')->isValid()
) {
    //
}

Aktuelni Laravel Request API upravo ima file(), hasFile() i isValid().

$request->validate([
    'photo' => [
        'required',
        'image',
        'max:5120',
    ],
]);

------------------------------------ Direktno core ↔ Laravel mapiranje -----------------------------

| Core PHP                  | Laravel |
|-----------------------------------------------------------------------------
| `$_FILES['photo']`        | `$request->file('photo')` |
| `UPLOAD_ERR_OK`           | `$file->isValid()` |
| ručna MIME provera        | validation `image` / `mimes` / `File::types()` |
| `finfo`                   | framework MIME detection |
| `random_bytes()` filename | `$file->hashName()` / `store()` |
| `move_uploaded_file()`    | `$file->store()` |
| filesystem folder         | Storage disk |
| ručni path                | returned storage path |
